# Terminal Agent Bridge 0.2.2

0.2.2 fixes two self-test reports that hid what had happened and corrects the documentation.
Commands, output, session records and provider transports are those of 0.2.1, and there is
nothing to migrate. A session launched by 0.2.1 is read as it is.

## Fixes

- A Ghostty launch that timed out after its tab existed left the tab open, while the session was
  recorded closed without a handle and the self-test reported its cleanup as passed (#86). The
  adapter now returns the proven handle as data, the launcher keeps it in the session's records
  and marks the session failed with the surface named, and `close-session --explicit` closes
  that surface later through Ghostty's own close script. Two orderings around that handoff are
  fenced: a close that arrives while the surface is still being created is refused until the
  launch deadline (at most 30 seconds), and a handoff that finds the session already closed
  binds nothing and leaves the exact surface in the session's error, where a later close keeps
  it. The self-test reports an unconfirmed cleanup as `not_verified` and names the session, the
  stored state and the recorded error.
- `self-test agy` in Agy's default permission mode timed out when Agy asked to run a command
  for a prompt that needs none, and the report said only that the wait timed out (#82). The
  prompt now says that no tool, command or file is needed, and the Agy adapter reads the tool
  confirmation from the session's own log: `doctor` reports it as
  `agy_tool_confirmation_observed`, and a timed-out self-test result step includes it in its
  reason. The observation changes nothing else: the request is not failed, the claim is kept,
  nothing is resent and no approval is answered.

## Documentation

- [macOS permissions](../macos-permissions.md) says that a launch may need the screen unlocked,
  gives the lock-state check and asks for an unlocked repeat before a timeout is read as a
  regression (#80). The cause of the first-attempt timeouts recorded there stays open.
- The command reference, the terminals page, the providers page and the testing guide describe
  the retained handle, the two fenced orderings, the Agy observation and the self-test reasons.

## Verification and remaining limits

- macOS tests passed: 726 tests, no failures, 6 ignored (five live tests and one subprocess
  fixture). Clippy passed for the host, `x86_64-unknown-linux-gnu` and `x86_64-pc-windows-msvc`;
  formatting and diff checks passed. Ignored tests are not runtime evidence.
- Linux and native Windows were checked locally, not run. Their tests run in CI and in the
  Release workflow for the tagged commit.
- The Ghostty fix is covered by fake-runner tests of the three orderings, each of which fails
  against the old code. No Ghostty automation timeout was produced live, so the recovery close
  after a real failed launch is not verified; the ordinary Ghostty round trip passed.
- Authenticated macOS round trips through `self-test` with provider defaults (ask, result,
  `tell`, result, owned-session cleanup), with the screen unlocked: Codex 0.160.1 passed in
  iTerm2, Ghostty, WezTerm and Terminal.app; Claude Code 2.1.292 in WezTerm; Agy in WezTerm in
  its default permission mode (once with 1.2.16 and once with 1.3.0, which Agy installed
  between the two runs) and with `--yolo`; Pi 1.0.0 in WezTerm with
  `--model openai-codex/gpt-5.6-sol` and a logged-in provider. These are the first recorded Pi
  round trip and the first recorded Agy default-mode pass; neither row shows that the new
  prompt wording is what made Agy answer without a tool, because the default-mode timeout of
  0.2.1 was not reproduced first.
- Not exercised with this release: native Windows and Linux at runtime, Warp, a close after
  the owner died, provider approval prompts, and a Pi prompt that the provider refuses (#83).
- The limits recorded for 0.1.1, 0.1.2, 0.2.0 and 0.2.1 are unchanged.
