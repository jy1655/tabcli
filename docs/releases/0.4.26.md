# Terminal Agent Bridge 0.4.26

0.4.26 lets a parent notice a managed Codex or Claude session's structured questions before
completion and see retained question presence in ordinary completion output. Once the provider
ends the Request, an ordinary `tell` can supply the missing information in a new Request.
This completes the notification and follow-up shape of #189. Windows private-permission setup
also stops launching a SID-query subprocess for every lock and record write (#305, #306).

## Question handoffs

- `wait SESSION/REQUEST --questions` wakes on retained emissions while the Request is pending
  (#303). The address remains in `remaining`; `ended: null` is not completion. Pass the returned
  `after_question` cursor through `--after-question` to skip an already observed prefix. Default
  waits keep their completion timing; an ended Request takes precedence over its questions.
- Managed Claude sessions now observe structured `AskUserQuestion` emissions through a separate
  optional native plugin (#304). It retains only main-loop engine/core question returns bound
  to the original current Request. The completion plugin remains independent. Observation does
  not answer a tool, grant permission or prove a dialog was shown.
- Successful waited `ask`, `tell` and `reopen`, and any ended `result --wait` or default `wait`, add
  `question_emitted: true` and `question_emission_count` when their Request retains emissions.
  Plain output gives the command to retrieve their text. Ordinary result and inspect, and the
  active or latest-result Request in status, expose the same count. A count measures emission
  items, each of which may contain multiple questions. Closed history retains the count without
  an active attention flag. Lists, timeline, attachments and completion records keep their
  contracts.
- The host integration guidance describes reading the questions before accepting the result,
  observing with bounded question-aware waits, and sending missing facts only after the session
  is Ready. A `tell` creates another Request; it does not mark an earlier emission answered.

Absent question fields mean unknown. An emission never means pending, displayed, executed,
unanswered or answered. Tool availability and retained evidence depend on the provider's model,
configuration and history. Incomplete/unreadable observations remain diagnostic and do not
change completion. This release adds no external same-turn answer endpoint for a managed Codex
TUI, no automatic answer to Claude's person-facing dialog, and no structured question observer
for Agy or Pi. If an actual Claude question dialog is open, a person answers it on the surface;
Bridge does not change Claude's timeout or permission settings.

## Windows performance

Each private-permission operation reads `TokenUser` from the current process token in-process,
instead of starting `whoami.exe`. Identity is read on every call; no cache is introduced.
DACL application and reapplication, ownership, file/directory syncs, lifecycle behavior,
fixtures and serial test execution are unchanged.

Local profiling measured 33,909 SID-query calls taking 233.15s before the change. Main unit
execution fell from 406.75s to 136.60s; the final uninstrumented full suite took 177.99s versus
455.59s. The first hosted Windows comparison reduced the test step from 21m57s to 12m11s,
including compilation, and main unit execution from 1,209.89s to 631.57s. Hosted run times vary;
the [measurement record](../verification/2026-10-24-windows-test-runtime.md) separates directly
measured SID cost from remaining filesystem work and host variation. No production provider
latency improvement is asserted.

## Verification and upgrade

- The [question-handoff record](../verification/2026-10-24-question-handoff.md) identifies the
  exact tested candidate and SHA-256. Native Windows Codex 0.164.0 with provider defaults and
  `--yolo` emitted a question while pending, completed with a missing-fact report, accepted an
  ordinary follow-up carrying the fact, returned the expected result and preserved history
  after confirmed close. The control deliberately requested tool use and a bounded ending;
  it does not prove unsolicited questions or automatic ending of every blocked task.
- [Claude question observation](../verification/2026-10-23-claude-question-emissions.md) was
  verified separately on native Windows with Claude Code 2.1.309. That record includes the
  separate-plugin layout and ordinary completion check. It does not verify an automated answer
  to a pending dialog. Authenticated macOS questions and Agy/Pi questions remain unverified.
- The combined code passed the full native Windows serial suite (1,308 passed, 5 ignored),
  host and Linux/Windows cross-target Clippy, formatting, language and diff checks. Integration
  generation/check and Python package tests passed. The SID change also passed all seven
  [PR CI jobs](https://github.com/jy1655/tabcli/actions/runs/39980993825), including native Windows,
  macOS, Linux, MSRV and both release builds. Ignored live tests are not runtime passes.
- [0.4.25's upgrade notes](0.4.25.md#upgrade-notes) still apply: new Claude sessions require
  stable Claude Code 2.1.302 or later and verified native module readiness. Older legacy Claude
  sessions can finish a pending Request but cannot take a new `tell` after upgrade. Inspect and
  close/reopen or start a fresh session as documented. Do not downgrade binaries used by open
  sessions.

The release includes verified macOS and Windows CLI archives and the Claude, Codex, Agy and Pi
integration packages, with checksums. Integrations contain instructions and no engine binary.
