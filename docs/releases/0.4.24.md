# Terminal Agent Bridge 0.4.24

0.4.24 is the first release that ships the host integrations: one shared `agent-bridge` skill
packaged for Claude Code, Codex, Agy and Pi, published as eight release assets beside the four
CLI assets (#288, closes #285). It also checks the macOS guarded dialog response against the
request's claim and expiry before any automation runs (#279), and carries the remaining module
moves of the 2026-10-22 architecture review, none of which changes behaviour (#276, #278, #280,
#281, #284, #287, #289 to #294), with one build fix for their combination (#286).

## Observable changes

- Host integrations (#288). An integration lets a coding assistant use `tabcli` without global
  instructions that you write yourself: it installs one skill that tells the assistant how to
  delegate with `ask`, continue with `tell`, read the exact result, diagnose with `inspect`,
  `doctor` and `status`, and close only the sessions it created. The integration adds no
  transport of its own, changes no permission, trust or engine setting, never adds `--yolo`
  unless you ask, never approves a trust or permission prompt, and never resends after a timeout
  or an uncertain delivery. Each host installs its package through its own mechanism (Claude
  Code and Codex plugin marketplaces, the Agy plugin directory, a Pi package); any host can
  target any provider. The packages are instructions only and contain no `tabcli` binary. Their
  version equals the Cargo version (0.4.24); the minimum compatible CLI, 0.4.22, is independent
  and recorded in each `integration.json`. `scripts/integrations.py` generates, checks, builds
  and verifies the packages; CI checks source consistency and packaging on Linux, macOS and
  Windows, and the Release workflow builds the packages from the validated tag commit and
  verifies the twelve assets together. Installation, update, removal, host permissions and
  Agy's native persistent-shell procedure are in [docs/integrations.md](../integrations.md).
- Release asset set (#288). A release now has twelve assets: `tabcli-<version>-aarch64-apple-darwin.tar.gz`,
  `tabcli-<version>-x86_64-pc-windows-msvc.zip`, `agent-bridge-claude-<version>.zip`,
  `agent-bridge-codex-<version>.zip`, `agent-bridge-agy-<version>.zip`,
  `agent-bridge-pi-<version>.zip`, each with its `.sha256`. `docs/releasing.md` describes the
  integration verification step; releases up to 0.4.23 keep their four assets.
- macOS guarded dialog precheck (#279). Dispatching the guarded workspace-dialog response on
  macOS previously discarded the request's claim and expiry. It now checks claim currency, the
  session's ended state and the request's original expiry under the lifecycle lock, releases the
  lock, and only then calls the terminal automation; busy or unreadable lifecycle evidence
  refuses before automation. The iTerm2 and Terminal.app scripts compare the screen with
  `considering case`. Both platforms report a pre-write refusal as the terminal's
  `StaleDialogClaim`; Windows keeps its wire replies and the helper-side checks at each write,
  macOS keeps the specific refusal cause in the error chain. Consent still sets `attempted`
  immediately before `surface.answer`, and an ordinary automation error remains a
  possible-response failure that never retries input. The precheck is not atomic with the key
  write or with the provider consuming it.

## Module moves (no behaviour change)

- Reopen reservation (#276, card 3). `reopen/reservation.rs` owns the source marker's claim,
  finalisation and release, the refused-launch observation and its settlement; `reopen/gate.rs`
  types the refusal gates with every JSON spelling unchanged; Session owns the three auxiliary
  decoders and the marker schema with their legacy, missing-record and error-context policies.
- Console client (#278, card 2). `console_control/client.rs` owns the Windows helper behind
  `Client<H: HelperProcess>` for send, text-only send, screen, guarded dialog and submit, and
  close; the Codex Windows paste holds one client across its operations. Payload lifetime, wire
  arguments and replies, deadlines and failure classification are unchanged.
- Codex bound turn (#281, card 5; #286). `codex/turn.rs` owns the seven adapter-private records of
  a bound turn with one typed decoder each, the marker, and the `bind`, `stop` and `notify`
  operations under the lifecycle lock; `handle_hook` routes to them. Record names and JSON
  objects are byte-identical, so older binaries read them as before. #286 gates the
  `read_binding` compatibility path to Windows and test builds, which #278 and #281 merged
  together had left unused on Linux and MSRV.
- Claude turn and trust (#284, row 11). `claude/turn.rs` owns the Turn identity, marker, pending
  record, target message, correlated response and Stop handlers; `claude/trust.rs` owns the trust
  store reads and the exact-scope check behind a `GitScope` seam whose production adapter runs
  the same Git command under the same 2 s bound.
- Codex screen lexicon (#280). `codex/launch/lexical.rs` owns the empty-composer and hook-review
  labels, numbered-label decoding and the confirmation-hint lexemes; the readiness, submission
  and addressed-draft predicates keep their separate matching modes and order.
- Ghostty frame host (#287, row 9). `terminal/macos/ghostty/host.rs` owns the frame protocol,
  Bridge's replaceable fallback for Ghostty's missing surface identity: frame encoding and
  parsing, `run_host`, raw-mode restoration, launch verification and the bound start. No wire
  change; `launch::wait_for_binding` stays in Session.
- Portable terminal dispatch (#294, row 13). The terminal facade keeps its Windows caller names
  through direct re-exports, and `terminal/refusing.rs` owns the Linux and other-OS refusals with
  their original messages.
- Agy log lexing and delivery runtime (#293, row 10). `agy/log.rs` owns the complete-line lexer
  and noise stripping; the Agy transports take an adapter-owned `Runtime`, so the real send path
  is tested with scripted effects and time. Trust before readiness, the quiet period, one paste
  and the receipt rule are unchanged.
- Residual surface vocabulary (#292). `ResidualSurface` and `SessionStatus::residual_surface`
  live in `session/state.rs` beside the serialised status; the launch path keeps an alias.
- Lifecycle test fixtures (#290, row 14). The fifteen mechanical setup helpers that the close
  tests and the native command tests duplicated live once under `session::test_support`
  (test-only); crash-state and malformed fixtures stay literal.
- Record primitives (#291, row 15). `session/primitives.rs` re-exports its existing names over
  `state_root.rs`, `durable.rs` and `locks.rs`; fsync order, Windows replacement retry,
  permission-before-publication and the fault hooks are unchanged.
- Typed completion events (#289). A private `EventOutcome` constructs the success, failure and
  confirmed-cancellation events that four writers in `session/turn.rs` repeated; each writer keeps
  its authority and publication policy, and the serialised bytes are pinned by tests.

## Verification and limits

Every change passed the serial suite (`cargo test --all-targets --all-features --
--test-threads=1`), Clippy with `-D warnings` on the host and for `x86_64-pc-windows-msvc`, fmt
and `git diff --check`, and every main-push CI job including the Windows runner (seven jobs from
#288 on: the integration packages are checked on Linux, macOS and Windows). At main `31a2b44`
the macOS job ran 1,425 tests and the Windows job 1,228, none failed. Every change except the
two-line build fix (#286) was reviewed read-only before merge (Codex gpt-6-astra xhigh); #279,
#288, #289 and #291 were corrected after their review and re-run. `scripts/integrations.py
check` and the Python test suite (21 tests, 2 platform-specific skips on macOS) pass at the
release commit.

Live, on native Windows: the Reopen reservation (#276) with Claude Code 2.1.308 (reopen and
follow-up, a proven pre-spawn launch failure, marker release and retry, duplicate source); the
console client (#278) with Codex 0.163.0, Claude Code 2.1.308 and Pi 1.3.0 round trips; the
integrations (#288) as Claude → Codex, Codex → Claude, Pi → Agy and Agy → Pi round trips with
every package installed from its archive, recorded in
[docs/verification/2026-10-22-host-integrations.md](../verification/2026-10-22-host-integrations.md).
A non-publishing Release rehearsal with tag v0.4.23 passed on the integration branch and again
on the release branch. The installing machine's self-test is recorded separately.

Not verified: the macOS guarded dialog precheck (#279) against a real provider dialog (the macOS
CI job replayed the AppleScript case checks; no authenticated dialog was answered); an
authenticated macOS host using an installed integration, and the Windows host and target
combinations not listed above; an Agy follow-up through the console client (#278; Agy 1.4.5
asked for `RunCommand` approval and timed out) and Agy's live behaviour with the moved lexer
(#293); a Ghostty self-test on the moved host (#287; the screen was locked when it was tried).
Each module move is proven by byte comparison of the moved bodies, unchanged runtime-contract
pins and the suites above, not by a live run of the changed binary.
