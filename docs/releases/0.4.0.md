# Terminal Agent Bridge 0.4.0

0.4.0 adds `cancel`, the user's recorded request that a session's current turn be interrupted
instead of waited for, with Pi as the first provider whose interruption Bridge can confirm. It
fixes the iTerm2 launch when iTerm2 is not running, says what a terminal creation failure left
behind, and records, per terminal, why a guarded trust-dialog response is or is not possible.
Every existing record, transport, trust rule and close authority stays as it was.

## Changes

- `cancel SESSION` records a cancel for the active request of a `running` or `working` session
  and refuses, with the reason, when there is nothing to cancel, when the request already has a
  result, when a cancel is already recorded for it, or when the session's provider cannot be
  interrupted by this release's integration. The request ends `cancelled` only when the
  provider's own interruption signal, correlated to that turn, reaches Bridge; a turn the user
  interrupted at the keyboard stays a plain failure. `result`, `wait`, `status`, `inspect`,
  the timeline and doctor show the cancel and its outcome from one observation; `search`
  leaves cancelled turns out as it does failed ones. Pi sessions started by this release
  support it through the extension Bridge installs; Codex, Claude and Agy refuse it, and the
  providers page says which upstream change would lift each refusal.
- iTerm2 is addressed by its bundle identifier, so a launch starts iTerm2 when it is not
  running; by name the launch failed before any surface existed (#99). Only the launch may start
  it: the send, verify, close and screen scripts stop when iTerm2 is not running.
- A terminal creation failure that leaves no proven surface records that no surface handle was
  recorded and no prompt was sent. A macOS automation call that runs until the deadline says
  that the application did not answer, adds that the screen is locked when it is, and points to
  the permissions page, which now has an "Automation timeouts" section (#80).
- The guarded trust-dialog scripts for iTerm2 and Terminal.app compile in the test suite, the
  Windows console's send-or-not decision is tested on its own, and the terminals and security
  pages say per terminal why Ghostty, WezTerm and Warp cannot answer the dialog (#77). The README
  documents `consent inspect`, `revoke` and `reset` and what is never shared (#28).

## Verification

See the [macOS verification record](../verification/2026-10-11-macos-0.4.0.md). Automated
fixtures and authenticated CLI checks are reported separately there; the live checks of this
release were run with the screen locked unless the record says otherwise.

Cancel for Codex, Claude and Agy, recovery close of a Warp tab whose control binding never
persisted (#87), Warp live verification (#63), and a close of a session whose surface vanished
while its provider process lives (#101) remain outside this release.
