# Terminal Agent Bridge 0.4.34

0.4.34 lets an agent discover the binary's public command contract with
`tabcli describe [COMMAND] --json`, teaches the integration skill to adopt that contract with
a fallback for older binaries, and adds `capabilities.cancel` to ordinary `inspect --json`
output. There are no changes to provider transports, completion protocols, permission
policies or record schemas. This release adds no way to answer a question and no cancel
support for another provider.

## Static command contract

`tabcli describe --json` returns a versioned envelope with `contract_version: 1`,
`binary_version`, `scope: "build"` and one entry per public command: `name`, `summary`,
`synopsis`, `possible_effects`, argv `examples`, command-scoped `features` and `notes`.
`tabcli describe COMMAND --json` returns a single command. Without `--json` it prints a
short human-readable summary; with `--json`, errors are structured too. Unknown commands and
hidden helpers produce the same public-command error.

`describe` reads no providers, settings or sessions, creates no state root, repairs nothing
and runs no probe. The contract describes what this build supports. It is not runtime
capability, provider availability, readiness or authorization: every action still checks
its own current gates, and runtime evidence comes from `status`, `inspect` and `doctor`.
`possible_effects` covers every form of a command; `notes` names the conditional ones.
Examples are argv illustrations, not commands to run automatically, and synopsis strings are
usage notation, not an input schema. Neither an exit code nor `failure_kind` grants retry
authority.

The question features that `result` (`question_emissions`) and `wait` (`questions`,
`after_question`) advertise describe the existing question observation interface. Observing
a question emission is not answering it: the features do not show that a given session can
observe a question, that a dialog is pending, or that Bridge can answer it.

`--help` is unchanged apart from listing `describe` and the already supported
`settings codex-lifecycle-hooks` form. See [CLI](../cli.md#discover-the-command-contract).

## Integration skill discovery

The `agent-bridge` skill for Claude Code, Codex, Agy and Pi now runs `tabcli describe --json`
once per resolved executable and task. It adopts the contract only when the command succeeds
with `ok: true`, `contract_version: 1`, `scope: "build"` and public entries for `ask`, `tell`,
`result`, `wait`, `inspect`, `doctor` and `close-session`, and reads a feature only from its
own command entry. Otherwise, including on binaries older than 0.4.34, it falls back to
`tabcli --help` and reports that the contract was unavailable or unrecognized. The skill's
minimum supported tabcli version stays 0.4.22. The bounded `wait --questions` path uses the
`wait` entry's features, or the help listing on the fallback.

## Cancel admission observation

Ordinary `inspect --json` output adds `capabilities` with `schema_version: 1`,
`observed_unix_ms` and `cancel`. `capabilities.cancel` reports what `cancel`'s own admission
would decide for the snapshot inspect read. Inspect runs the same admission code that
`cancel` uses, under the shared lifecycle lock it already holds for that snapshot, without
the write. `state` is `admissible`, `refused`, `unsupported` or `unknown`, with a stable
`reason`; `request_id` appears only when the admission read the active receipt, and `detail`
carries the refusal or read error.

This is an observation, not a reservation or an interruption. A writer can change the
session as soon as inspect releases its lock, and `cancel` rechecks every gate under its
exclusive lock. An admissible cancel records intent only and proves neither interruption nor
completion. `unsupported` (`provider_unsupported`) reports the adapter's refusal for this
admission, which for Pi includes missing or stale startup readiness. Cancel remains limited
to Pi sessions with verified extension readiness. Human and timeline output do not include
capabilities. The reason table is in [CLI](../cli.md).

## Verification and upgrade

Before the version bump, the complete local Rust suite passed (1,388 passed, 5 ignored) and
the Python script suite passed (95 passed, 14 skipped). Runtime behavior of the packaged
release, and authenticated provider round trips with it, are not yet verified. CI and
cross-target checks are separate evidence.

The [open-session upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not downgrade a
binary used by an open session. The release includes macOS and Windows CLI archives and
Claude, Codex, Agy and Pi integration packages with checksums. Integration packages contain
instructions, not the engine binary; updating an integration takes effect in new host
conversations.
