# Terminal Agent Bridge 0.4.38

0.4.38 closes the remaining cards of the 2026-11-06 architecture review in one change (#363).
Five areas get a single owning module:

- Claude's completion records;
- the settings' values and usage text;
- each command's failure output;
- the decoding of core session records;
- Agy's and Pi's pending turns.

No command, setting, record or transport was added. These moves were made to keep each
caller's public JSON, text output, error messages, record schemas, read limits and lifecycle
ordering as they were. The comparisons that support this, and what they leave out, are listed
under [Verification and upgrade](#verification-and-upgrade).

## What changes for a caller

Nothing is meant to change. Treat any difference a caller can observe in output, errors,
records or timing as a defect of this release.

## Claude completion records

Claude's four completion records now have one owner, `claude/completion/records.rs`:

- the completion mode recorded at launch;
- the question mode recorded at launch;
- the module's readiness;
- the module's latest rejected signal.

That module holds the records' names, schemas, validity rules and writers, and the answers
other code reads from them. Tests outside the module write the records through its fixtures
instead of spelling their names and JSON.

The module keeps two read policies, which differ on purpose:

- **Delivery, hooks and capability observations** read the whole file and decode it after a
  lossy UTF-8 conversion. They need the whole file because the completion-mode record carries
  the whole output of `claude --version`, which has no limit of its own.
- **`doctor`** reads at most 16 KiB, as strict UTF-8.

A completion-mode record over 16 KiB is therefore still read as native completion by delivery,
while `doctor` reports it unreadable. That was already the case in 0.4.37; new tests now pin
it, together with the exact refusal texts and the bytes each writer records.

## Settings

Each setting accepted by `tabcli settings` is now declared once, and its type, wire values,
default, parser, synopsis line and usage text come from that declaration. `describe` and
`settings --help` take their synopsis lines from it. The settings record keeps its storage,
read timing and error messages.

The two existing orders are kept:

- The synopsis lists `windows-tab-window` first.
- The usage text printed for an invalid argument keeps its older order, with
  `macos-open-mode` first.

## Failure output

Every public command's registry entry now declares where its failures go:

- whether an argument-parsing failure with `--json` prints a JSON error object;
- whether a runtime failure is a JSON error object, a turn report or stderr text;
- which default fields a JSON error carries.

The common note in `describe` is built from those declarations rather than written by hand,
and it renders the same text as before. A test pins the exact JSON that `search` prints for a
parsing failure at its `--json` boundaries, where the query itself can be the text `--json`.

## Core session records

The decoders for the core session records live beside the existing ones in
`session/record.rs`:

- events;
- the cancel request;
- the terminal handle;
- the consumed-terminal tombstone;
- the timeline's strict decode.

The readers in the queries, `reopen`, close, `cancel`, `hold` and the terminal helpers call
these decoders. Each reader keeps its own read limits, lossy or strict decoding,
missing-record policy and error context.

## Agy and Pi pending turns

Each adapter's pending turn moves out of the adapter root into its own module, `agy/turn.rs`
and `pi/turn.rs`. That covers:

- its record and schema;
- install, read and cancel;
- the prompt framing and response correlation;
- for Pi, its hook handling and failure-signal decode.

The asymmetries between the two adapters stay:

| | Agy | Pi |
|---|---|---|
| Lock and Claim-currency check | none | lifecycle lock and Claim-currency check |
| Suffix marker | mandatory | optional |
| Record read | lossy | 4,096-byte strict |

The installed Pi extension is byte-identical. The runtime literal pins moved with their code
and keep every owner's count.

## Unchanged

- The runtime literal pin gate stays as it is.
- `tell` and `inspect`'s `capabilities.tell` keep their separate check lists.

A redesign of either would change what the gate protects or which error comes first.

## Verification and upgrade

### Before the version bump

The integrated change passed the following checks:

- the complete local Rust suite on macOS: 1,687 passed, 6 ignored;
- Clippy with warnings denied, for the host and for the Windows MSVC and Linux targets;
- the Python script suite: 109 run, 2 skipped;
- the language lint;
- the CI jobs of its pull request on Linux, macOS and Windows;
- the main commit's CI.

The pull request's first Windows CI run failed one new characterization test. Its expected
error kept the path `events/orphan.json`, while the reader on Windows displays
`events\orphan.json`. Only the test fixture was corrected, and the same test then passed on the
Windows CI runner. That is a result of the Windows CI runner, not of a Windows PC.

### With the version bump

The complete local Rust suite passed on macOS (1,687 passed, 6 ignored), and the Python script
suite passed (109 run, 2 skipped).

### How behavior preservation was checked

- **Characterization tests.** New tests for Claude's live and `doctor` record policies, the
  core record decoders and the typed setting values passed both on the code before these
  changes and after them. The existing Agy and Pi adapter tests passed after the move; only
  their import paths changed.
- **CLI matrix.** 123 isolated cases matched a binary built before these changes in exit code,
  stdout and stderr. The cases cover argument parsing and help for the 19 public commands,
  `describe` in JSON and text, and failure output when the state root cannot be read; they do
  not cover working sessions.
- **Help fixture.** It is unchanged.
- **Settings outputs.** They matched outputs saved earlier. The identity of the binary that
  produced those saved outputs was not verified.

### Not exercised

- No authenticated provider session and no terminal surface was exercised for this release on
  macOS or on native Windows.
- Ignored live tests were not run.

The packaged 0.4.38 release's runtime is not verified by these notes; those checks are separate
and recorded outside this repository.

### Upgrade

No record name or schema changed, so records written by 0.4.37 are read as before. The
[open-session upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not downgrade a binary
used by an open session.

The release includes macOS and Windows CLI archives and Claude, Codex, Agy and Pi integration
packages with checksums. Integration packages contain instructions, not the engine binary;
updating an integration takes effect in new host conversations.
