# Terminal Agent Bridge 0.2.0

0.2.0 renames the command and the package from `agent-bridge` to `tabcli`. The product is now
called Terminal Agent Bridge (TAB). Sessions behave as they did in 0.1.2.

## The rename

The crates.io package `agent-bridge` and several repositories of that name are other tools that
also work with coding-agent CLIs, so the old executable name collided with them.

- The executable and the Cargo package are `tabcli`. `--version`, the help text and every hint
  that tells you which command to run next use the new name.
- The repository is `github.com/jy1655/tabcli`. The old URL redirects.
- Release archives are `tabcli-<version>-aarch64-apple-darwin.tar.gz` and
  `tabcli-<version>-x86_64-pc-windows-msvc.zip`. Each contains the executable, `LICENSE` and
  `THIRD_PARTY_NOTICES.md`.

## Upgrading from agent-bridge 0.1.x

- Nothing in your state changes. Sessions, settings and consent records stay under
  `~/.agent-bridge/native-sessions` and are read as they are. The `AGENT_BRIDGE_*` environment
  variables keep their names.
- No `agent-bridge` alias is installed. Change scripts and instructions that call
  `agent-bridge` to call `tabcli`.
- Keep the old executable where it is until the sessions it launched are closed. Their hooks
  call it by its path. A session launched by 0.1.x can be inspected, continued and closed with
  `tabcli` meanwhile.

The identifiers that running sessions and the provider CLIs depend on did not change: record
names, the delegation header, turn markers, the Pi extension's fields, the hidden host commands
and the terminal identifiers. A test now pins them so that a later rename cannot change them
unnoticed.

## Documentation

- `README.md` is rewritten in English for first-time readers; `README.ko.md` is the Korean
  version.
- New reference documents: [commands](../cli.md), [terminals](../terminals.md),
  [providers](../providers.md), [security and data](../security-and-data.md),
  [architecture](../architecture.md) and [testing](../testing.md).
- New `CONTRIBUTING.md` and `SECURITY.md`, issue forms and a pull-request template.
- `THIRD_PARTY_NOTICES.md` records the licences of every package in `Cargo.lock`. Earlier
  archives shipped without these notices.

The reference documents were written from the code and correct several statements in the earlier
README: `self-test` reuses verified workspace consent, and `--isolated` separates Bridge's
records, not the provider's trust store; `search` skips failed results; the guarded response to
a workspace-trust dialog works only in iTerm2, Terminal.app and the Windows console; a failed
Claude follow-up turn keeps its claim, because the failure cannot be tied to a request.

## Other changes

- Six errors that named the old executable now say "failed to locate the current executable".
- The Release workflow reads the package name from the tagged commit, so a rehearsal of a tag
  before 0.2.0 still packages `agent-bridge` the way that release did.

## Verification and remaining limits

- macOS tests passed: 713 tests, no failures, 6 ignored (five live tests and one subprocess
  fixture). Clippy passed for the host, `x86_64-unknown-linux-gnu` and `x86_64-pc-windows-msvc`;
  formatting and diff checks passed. Ignored tests are not runtime evidence.
- Linux and native Windows were checked locally, not run. Their tests run in CI and in the
  Release workflow for the tagged commit.
- Authenticated macOS round trips with the 0.2.0 candidate passed through `self-test` with
  provider defaults (ask, result, `tell`, result, owned-session cleanup): Codex 0.160.1 in
  WezTerm, Terminal.app, iTerm2 and Ghostty, and Claude Code 2.1.291 in WezTerm.
- A session that `agent-bridge` 0.1.2 launched was inspected, continued with `tell` and closed
  by the `tabcli` candidate (Codex, WezTerm).
- Not exercised with this release: native Windows and Linux at runtime, Warp, Agy, Pi, a close
  after the owner died, and the default approval mode of the providers beyond the marker
  prompts of `self-test`.
- The limits recorded for 0.1.1 and 0.1.2 are unchanged.

Sessions and hashes are in the
