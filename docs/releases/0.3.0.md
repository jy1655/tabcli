# Terminal Agent Bridge 0.3.0

0.3.0 adds three read-only or user-set commands around one session observation and keeps
every existing command, record, provider transport, workspace trust rule, and close authority
as it was. `status` lists what a workspace's sessions are doing, `wait` waits for the first of
several requests, and `hold` lets you stop a session from taking further follow-ups until you
release it. The doctor report now states the scope of what it checked.

## Changes

- `status` lists the sessions of the current workspace from one observation per session:
  recorded state, the active request and its state, a reference to the latest published
  result, owner attestation, and attention flags derived from those facts. Closed sessions
  are excluded unless `--all`; `--all-workspaces` removes the workspace filter. A session
  whose records cannot be read consistently is reported in `incomplete_reasons` instead of
  being guessed. The command never repairs or writes; `sessions` keeps its repairing listing.
- `wait SESSION/REQUEST [...]` returns the first address whose wait-ending condition was
  observed, lists the others as `remaining`, and never cancels or resends. `result --wait`
  shares the same wait rule with unchanged output and exit codes. Command-side waits inside
  `ask` and `tell` are unchanged.
- `inspect` and doctor's record checks render the same observation that `status` uses, so a
  request has the same state in every query. doctor no longer re-reads request state from
  result JSON.
- The doctor report starts with `scope`: the validated executable and where it came from, the
  current version only when a probe succeeded, the manifest's launch overrides, the workspace,
  the probe flag and budget, and the consent state already observed. Pi credential evidence
  names the probed model and executable beside its existing fields. Check ids, reasons, texts
  and order are unchanged.
- `hold SESSION` records your request that a session take no further follow-up; `--release`
  lifts it. A held session refuses `tell` before any record changes; a hold set after a
  follow-up was claimed rolls that turn back as not sent, and a delivery already allowed to
  start, the current turn, the initial prompt, and direct input to the surface are not
  affected. `inspect` and `status` report `held`, and doctor adds a `hold` check. Closed
  sessions keep their hold record.

## Verification

See the [macOS verification record](../verification/2026-10-11-macos-0.3.0.md). Automated
fixtures and authenticated CLI checks are reported separately there.

Cancelling an in-progress turn ([#72](https://github.com/jy1655/tabcli/issues/72)) is not in
this release: no provider offers a first-party interrupt that Bridge can address today, and
the evidence needed to design one has not been recorded yet. Warp missing-binding recovery,
first-launch timeouts, and the broader redesigns deferred in the
[0.2.5 review disposition](../verification/2026-10-07-architecture-follow-up.md) remain outside
this release.
