# Terminal Agent Bridge 0.4.7

0.4.7 closes architecture review 5. One visible change: the `sessions` listing counts published
Results with the same rule as `status` and `result`. The rest moves knowledge to the module that
owns it without changing any output. Records written by 0.4.x are read as before.

## Changes

- `sessions` counts published Results. The `results` field of `sessions --json` and the plain
  listing now counts the event paths admitted by the publication predicate that `status` and
  `result` use (a journal that matches, no open claim), read lock-free from the receipts and the
  bounded journal. Before, it counted every regular file with a valid event name under `events/`, so
  an unpublished event could make `sessions` and `status` disagree about the same Session. Set-aside
  files were already excluded. One enumeration behind the session seam now walks the state root for
  `sessions`, `prune-sessions`, `status` and `search`, keeping each command's error policy, order,
  budget checks and strings.
- The two AppleScript adapters carry an internal automation dependency. iTerm2 and Terminal.app run
  their scripts through `Automation` (production `osascript`, a recording replay in tests), so their
  tests assert script, arguments and order; Terminal.app's close transaction guard is unchanged.
- Three placements and types from the review's speculative tail. The bounded command runner
  lives in `process_env` beside the child environment policy. The result-timeout diagnostic is a
  typed per-row view that each provider adapter declares a predicate for, so a renamed reason code
  can no longer fail silently; `doctor` still runs the bounded child report. The Windows
  console-control command is a typed request at the parser and a typed action in the Windows
  adapter, with the same positional contract, messages and precedence. The four pending-turn
  correlation records were investigated and left as they are: Pi's acceptance of a response without
  the marker is intentional and proven by its claim and input correlation.
