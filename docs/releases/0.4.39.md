# Terminal Agent Bridge 0.4.39

0.4.39 fixes one defect on macOS (#365): `ask claude --yolo` stopped at Claude's workspace trust
dialog and failed without naming it.

## What happened

Claude Code 2.1.321 shows its workspace trust dialog under `--dangerously-skip-permissions` on
macOS. Claude Code 2.1.319 started without it. Whether 2.1.320 shows it was not checked.

Bridge 0.4.38 and earlier skipped the guarded dialog answer for every macOS Claude launch under
bypass. A launch in a workspace that another provider already trusted, which Bridge answers
without `--yolo`, therefore stayed at the dialog. The request failed at the delivery deadline
with `Claude completion module readiness was not observed ...`, which did not mention the dialog.

## What changes for a caller

- **Claude on macOS with `--yolo`, workspace consent verified through another provider:** Bridge
  now answers the exact workspace trust dialog once, as it does without `--yolo`, and the
  request goes on. Consent rules are unchanged: without verified consent for the exact workspace
  Bridge answers nothing.
- **The same launch when Claude shows no dialog:** the wait ends when Claude's completion module
  reports the session's start. Nothing is typed.
- **The readiness error:** when Claude's own store records no trust for the workspace, the error
  adds that the session may be waiting at the workspace trust dialog and gives the
  `tabcli screen <session>` command. This is read from the store, not from the screen, so it is
  stated as a possibility.
- **A launch that neither shows an answerable dialog nor starts** still fails at its deadline as
  not sent with the readiness error.
- **Skill:** after a new session's first request fails before delivery, the caller reads that
  session's screen and reports it instead of launching again.

Unchanged: Claude without `--yolo`, Claude on native Windows, Claude launches without native
completion, terminals that take no guarded key (Ghostty, WezTerm, Warp), and Codex, Agy and Pi.

- Local on the merged change: the serial test suite (1691 passed, 0 failed), Clippy with
  `-D warnings` on the host and for `x86_64-pc-windows-gnu`, fmt, the language lint, the scripts
  tests and the integration check.
- Live on one Mac with iTerm2 and Claude Code 2.1.321, recorded in
  [the verification record](../verification/2026-11-10-macos-claude-trust-dialog-under-bypass.md):
  the failure reproduced with 0.4.38; with the fix, two workspaces trusted by Codex only
  completed after one dialog answer, a workspace Claude trusted completed with no answer, and a
  workspace nobody trusted failed with the added sentence.
- Not run: native Windows at runtime, Terminal.app, Claude Code 2.1.320, and a Claude under
  bypass that shows no dialog and never reports its start (tests only).
- No record schema changed. The fix applies to new launches.
