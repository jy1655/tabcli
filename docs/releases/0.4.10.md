# Terminal Agent Bridge 0.4.10

0.4.10 is the first checkpoint of the sixth architecture review: one rule now decides whether a
recorded process is still the process a record names, and the launch wrapper's exit settlement
lives beside the records it settles. On native Windows two dead-owner answers change (a dead
legacy owner no longer blocks prune; an uninspectable live owner stops repair instead of being
treated as dead) and a verified pid reuse is reported like on macOS. Records written by 0.4.x are
read as before; no record schema or command changed. `inspect`'s nested `owner.identity_matches`
now means "every recorded identity field matched" on every platform (#190).

## Changes

- One attestation of the recorded owner (#190). Five predicates in four files decided at four
  strengths whether a session's recorded owner is still alive, and six places compared a recorded
  pid and birth with the live process. `process_identity` holds the one classification rule
  (`Live`, `Gone(Exited)`, `Gone(Reused)`, `Unknown`; an inspection failure is never a death),
  `session::owner::attest_owner` applies it to the owner record and compares the control fields
  (tty, process groups) only for a live matching incarnation, and the platform observers report
  confirmed absence as such (raw `ESRCH` on macOS, `ERROR_INVALID_PARAMETER` or a signalled
  handle on Windows). Prune, repair, the command wait and the exact-intent close resume keep their
  own policy over that answer; close authority, the Terminal.app control proof and the Windows
  helper identity checks are unchanged. Behavior changes, each pinned by a test: a dead Windows
  owner without a recorded identity no longer blocks prune; an uninspectable live Windows owner
  makes repair fail instead of proceeding; a changed tty or process group of the same incarnation
  is no longer treated as death; an intermediate-schema owner record is compared on the fields it
  recorded; the Windows attestation compares executable paths case-insensitively without touching
  record equality; a verified Windows reuse projects `identity_matches: false` like macOS, so
  launch, wait, status and doctor react to it; the wait ends and the exact-intent close resumes on
  a reused incarnation.
- Every recorded incarnation goes through that rule (#191). Terminal.app, WezTerm and Warp, the
  reopen command's provider-process check and the Claude registry's creation-time comparison map
  its answer into their own vocabulary; messages, follow-up checks and authority stay with each
  adapter. The reopen command no longer turns an inspection error on a dead pid into a verified
  exit (the marker is retained). The typed Windows identity check is deleted; the tab host
  compares through the shared identity-value check.
- The launch wrapper's admission and exit settlement live in `session::launch` (#192). The
  wrapper no longer takes the claim lock by path or decides the session's terminal status itself;
  the tests of that settlement call the session interface instead of crossing `native.rs`.
  Pure move, no behavior change.
- Glossary: `CONTEXT.md` defines **Incarnation** (one run of a process, pid and birth) and
  sharpens **Attestation** with its four answers.

## Verification

See the [macOS verification record](../verification/2026-10-15-macos-0.4.10.md). The Windows-only
tests of #190 and #191 (the `ERROR_INVALID_PARAMETER` absence path, the retained exited process,
the legacy-owner prune and the case-insensitive attestation) ran on the Windows CI runner of each
pull request; no Windows live session was run for this release.

Warp (#63, #87), the Windows console large paste (#124) and notify payload limit (#127), the Windows
Terminal cold-start observation of #111, #147, #148, #149, the child-to-parent question channel
(#189) and Linux transport (#6) remain outside this release.
