# Terminal Agent Bridge 0.4.43

0.4.43 runs managed sessions on Linux (#6, #389). Each Linux session starts its own detached
tmux server; you watch or type by attaching to it. The release adds an x86_64 Linux archive.
macOS and Windows behavior is unchanged apart from the items marked below.

## What changes for a caller

- **Linux sessions through tmux (#389):** `ask`, `tell`, `screen`, `inspect`, `result`,
  `wait`, `cancel`, `hold` and `close-session` work on Linux with tmux 3.2 or later on an
  absolute `PATH` entry. tmux is the Linux default and `--terminal tmux` selects it; every other
  terminal is refused on Linux with `<Name> is not available on Linux; use tmux`, and `tmux` is
  refused on macOS and Windows. A Linux process inside WSL is not verified.
  - No window opens. `ask` and `tell` print `attach: tmux -S '<socket>' attach` in text output
    and `attach_command` in JSON; `inspect` prints both for a session whose active handle is
    tmux.
  - Each session has its own server, started with `-f /dev/null`, whose socket is
    `<state dir>/<session id>/tmux.sock`. A socket path of 108 bytes or more is refused before
    tmux runs; use a shorter `AGENT_BRIDGE_NATIVE_STATE_DIR`. Your tmux configuration and key
    bindings are not loaded for that server.
  - The pane reads no shell startup files: it has the environment of the process that ran
    `tabcli`. Provider CLIs and `node` (for the Codex and Pi npm launchers) must be on that
    `PATH`.
  - Agy and Pi follow-ups are pasted into the exact pane. Bridge never answers a dialog in
    tmux: a Claude or Agy workspace-trust dialog stops the launch with `the workspace trust
    dialog cannot be answered with a guarded key in tmux; ...`. Trust the workspace in the
    provider first, or attach and answer, then close the stopped session.
  - `close-session --explicit` ends the session's whole tmux server, including windows you
    added to it. The socket file stays until the session is pruned.
- **Linux command budgets (#389):** a provider command that Linux would not run (one argument
  over 128 KiB, or arguments and environment over the stack-derived limit) is refused before it
  starts, with nothing sent, at launch and for Codex `codex queue` follow-ups. Pass long
  material by path in the workspace.
- **Doctor (#389):** a new `tmux` check reports the executable on Linux and, with `--probe`,
  its version (`tmux_found`, `tmux_too_old`, `tmux_unavailable`). The `platform` check reports
  Linux as supported.
- **Error and help text (#389):** the unknown-terminal error and the `ask`/`self-test` usage
  list `tmux`. On macOS, an owner reuse diagnostic keeps its `(seconds, microseconds)` text.
- **Records (#389):** new optional fields `linux_birth` (owner and shell), `linux_host` and
  `tmux_socket` (terminal handle). Records written by 0.4.42 decode with the same meaning.
- **Integration packages:** list Linux among their platforms, and the shared setup guidance
  describes attaching to a Linux session.

## Install on Linux

The archive `tabcli-0.4.43-x86_64-unknown-linux-gnu.tar.gz` is built on Ubuntu 24.04 and needs
glibc 2.39 or newer. Verify `sha256sum -c tabcli-0.4.43-x86_64-unknown-linux-gnu.tar.gz.sha256`
before extracting, put `tabcli` on your `PATH`, and install tmux.

## Verification and upgrade

- Local on the release change (M8, Ubuntu 26.04, Linux 7.0, Rust 1.97.1): the serial test
  suite under umask 0002 and 022, Clippy with `-D warnings` on the host and for
  `aarch64-apple-darwin`, `x86_64-pc-windows-msvc` and `x86_64-unknown-freebsd`, fmt, the
  language lint, the scripts tests and the integration check.
- CI: the pull request and main push runs of #389, including the new Linux release build. A
  release rehearsal of `v0.4.42` on the branch passed every job, including the Linux build and
  the 14-asset publish verification.
- Live on Linux (tmux 3.6, branch builds; record in
  [the 2026-11-17 verification](../verification/2026-11-17-linux-6-tmux-3.6.md)): Codex,
  Claude, Pi and Agy ask, follow-up and close; Claude and Agy trust-dialog refusals in untrusted
  workspaces.
- No live macOS or Windows run was made for this release; their behavior is covered by the CI
  runners.
- A downgrade below 0.4.43 cannot use a tmux session: earlier releases refuse Linux. Close Linux
  sessions before downgrading.
