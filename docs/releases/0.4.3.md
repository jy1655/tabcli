# Terminal Agent Bridge 0.4.3

0.4.3 changes how Bridge is put together more than what it does. The terminal adapters declare
the facts Bridge used to decide by terminal kind, the session records live in the session module,
and every command is registered once. Two behaviours change: a Warp session's records are found
only through the session they belong to, and a close on a platform without a visible terminal
transport refuses instead of proceeding without an owner check. Records written by 0.4.x are read
as before.

## Changes

- The terminal adapters receive the session directory when they verify, probe or close a surface.
  Warp found its own records through the state-root variable before; it now requires the surface
  handle to name the session whose directory it was given, and refuses a mismatch instead of
  reading another session's records. Windows guarded dialog input checks the same before writing
  its temporary file.
- A launch that leaves an unconfirmed surface puts the residual-surface note into the stored status
  and into the error `ask` returns once each.
- Each terminal adapter declares whether a prompt is sent as a bracketed paste and whether it can
  answer a trust dialog with verified consent, next to the close facts it already declared. The
  bytes sent and the set of terminals that answer the dialog are unchanged.
- On a platform without a visible terminal transport (Linux, #6), `close-session` refuses with that
  reason and keeps the surface handle; before, it went ahead with no owner check.
- The session record schemas, their constants and the state-root helpers moved into the session
  module; the serialized records are unchanged.
- Every command is registered in one table, and a test checks that the usage list names the same
  commands. Command names, arguments, errors and help output are unchanged.
