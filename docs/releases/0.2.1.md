# Terminal Agent Bridge 0.2.1

0.2.1 fixes a race in closing a Warp session and corrects the documentation. Commands, output,
session records and provider transports are those of 0.2.0, and there is nothing to migrate.

## Fix

- Closing a Warp session could fail with "could not observe the stopped Warp foreground group"
  although the group had stopped (#85). Bridge stops the foreground process group of the tab and
  waits until it is gone before it closes the tab. On macOS the probe it uses reports a group
  that holds only exited, not yet reaped processes as "not permitted", and Bridge took that for
  a failure. It now keeps waiting until the group is gone or the existing 3-second limit passes.
  A group that does not disappear still ends in an error, and no tab close is sent. The test for
  this path failed once in CI for the same reason and no longer depends on timing.

## Documentation

- [macOS permissions](../macos-permissions.md) and the [release procedure](../releasing.md) are
  now in English. The README sent readers with an Apple Events permission error to a Korean page.
- `self-test` and workspace trust (#79). `AGENTS.md`, the help text and the testing guide said
  that the self-test never approves workspace trust. It follows `ask`'s workspace-consent rules:
  verified consent for the exact workspace is reused through the provider's own approval, and
  without that consent the self-test approves no workspace trust itself. An explicit `--yolo`
  only forwards the provider's own bypass option. The behaviour did not change; the three
  places now say what [the command reference](../cli.md#self-test) already said.
- Two statements of the permissions page are corrected. The startup gate that discards keys
  typed while a new surface is selected exists in iTerm2, Terminal.app, Ghostty and WezTerm;
  the Warp host does not discard startup input, and keyboard preservation in Warp is not
  verified. In the self-test report, cleanup is a step, not a field named `cleanup`.

## Repository

- The two `release-build` checks of the CI workflow are named by target only
  (`release-build (aarch64-apple-darwin)`, `release-build (x86_64-pc-windows-msvc)`). Their names
  used to carry the archive name and changed with every version, so the `main` ruleset could not
  require them.

## Verification and remaining limits

- macOS tests passed: 716 tests, no failures, 6 ignored (five live tests and one subprocess
  fixture). Clippy passed for the host, `x86_64-unknown-linux-gnu` and `x86_64-pc-windows-msvc`;
  formatting and diff checks passed. Ignored tests are not runtime evidence.
- Linux and native Windows were checked locally, not run. Their tests run in CI and in the
  Release workflow for the tagged commit.
- The Warp fix is covered by tests with real processes, which fail against the old code. No live
  Warp session was run.
- Authenticated macOS round trips through `self-test` with provider defaults (ask, result,
  `tell`, result, owned-session cleanup): with the release candidate, Codex 0.160.1 passed in
  WezTerm and iTerm2 and Claude Code 2.1.291 in WezTerm. That run happened with the screen
  locked, and Codex in Terminal.app and in Ghostty did not complete: one timed out waiting for
  the first result, the other in terminal automation. An earlier build of this release, which
  differs only in the Warp close path, had passed in all four terminals with the screen unlocked.
  Terminal.app and Ghostty were not run again with the screen unlocked.
- The Ghostty launch that timed out left its tab open, while the session was recorded closed
  (#86). The locked screen is noted in #80 as a condition to check when a launch times out in
  automation.
- Agy 1.3.0 in WezTerm passed with `--yolo`. In its default permission mode the first result
  timed out: Agy asked for approval to run a command although the prompt needs none (#82).
- Pi 1.0.4 is not verified. Its first result timed out; Pi has no login for the selected
  provider on the test machine, and Bridge reported a timeout, not that reason (#83).
- Not exercised with this release: native Windows and Linux at runtime, Warp, a close after the
  owner died, and provider approval prompts.
- The limits recorded for 0.1.1, 0.1.2 and 0.2.0 are unchanged.
