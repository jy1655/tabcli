# Terminal Agent Bridge 0.4.11

0.4.11 closes the sixth architecture review. One change is visible: with `--json`, `ask` and
`tell` now print a JSON error envelope when they fail before a request address exists (#200).
Everything else moves code to the module that owns it or names a rule once, without changing
behavior. Records written by 0.4.x are read as before; no record schema or command changed.

## Changes

- One turn report for `ask`, `tell` and `reopen` (#200). The three commands report their
  lifecycle through one value. With `--json`, a failure before a request address exists now prints
  one error envelope for every turn command: `ask` prints `{ok: false, error, schema_version}`,
  `tell` adds `session`, `reopen` is unchanged. Previously `ask` printed nothing and `tell` printed
  the envelope only for a hold refusal. Plain output, stderr and exit codes are unchanged;
  `docs/cli.md` states the fields.
- Session start is one operation (#203). `ask` and `reopen` start a session through
  `session_start` and a source adapter (`StartSource`) instead of two copies of the preamble.
- Reopen asks each provider once (#201): one `ReopenSupport` bundle per adapter replaces three
  separate questions.
- Close: each adapter's live-owner pre-close sits in its own `close_owned_session` (#197); close
  runs through a named attestation seam, and the test-only path wrappers and their twin module
  are gone (#198, #199).
- The recorded end of a session lifecycle has one name, `SessionState::ended()` (#205).
- Host commands are declared once and the Terminal.app, iTerm2 and WezTerm hosts share one
  bound-surface procedure (#206).
- The Pi extension's reads of the core `turn.claim` and `cancel.json` are a declared contract,
  tested against the real writers (#195; `AGENTS.md` "Current Pi Boundary").
- The Codex and Pi adapters are module directories, like Agy (#207, #209). Pure moves.
- The two Unix owner and mode questions ("no other account can change it", "no other account
  can reach it") are named once (`private_to_user`, #208); the Windows owner and access-list
  reader stays with consent.
- Smaller single homes: a provider's `--version` text (#211), a capped command output
  (#214), the cross-session message value is named `correlation_id` (#210), every Ghostty
  script runs through its runner (#212), and four integration tests build records with the
  shared support helpers (#213).
- `AGENTS.md` records the attestation boundary and the rule that a Windows claim is verified only
  on the Windows CI runner (#194).
