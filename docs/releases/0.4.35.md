# Terminal Agent Bridge 0.4.35

0.4.35 prints a per-command help page from the describe contract (#338) and adds
`capabilities.tell` and `capabilities.questions` to ordinary `inspect --json` output, next to
the `capabilities.cancel` of 0.4.34 (#339). There are no changes to provider transports,
completion protocols, permission policies, record schemas or the behavior of any action: `tell`
and `cancel` keep their lock order, gate order, error strings and `--json` kinds. This release
adds no way to answer a question.

## Per-command help

`tabcli <COMMAND> --help` (or `-h`) prints that public command's page: the summary and synopsis
block `tabcli describe <COMMAND>` prints, then its notes, its argv examples as `tabcli ...`
lines, its command-scoped features and its possible effects. The page and `describe` share one
registry entry and one data path, so they cannot drift. The page reads no provider, setting,
state root or session and exits with status 0.

`--help` must be the only argument after the command name: `tabcli ask --help extra` fails with
`--help does not accept arguments`. A hidden helper or an unknown name fails with the same
public-command error as `describe`, and the six commands of the removed embedded TUI (`open`,
`prompt`, `read`, `list`, `close`, `hook`) keep their migration message with or without
`--help`. `tabcli --help` is unchanged and keeps the runtime, session-policy and platform details
that the command pages leave out. Binaries before 0.4.35 print the main help for
`tabcli <COMMAND> --help`, so a caller that depends on the page should run `describe` first.
See [CLI](../cli.md#discover-the-command-contract).

## Follow-up admission observation

`capabilities.tell` reports what `tell`'s Bridge record gates would decide for the snapshot
`inspect --json` read, evaluated in the command's order under the shared lifecycle lock inspect
already holds, stopping at the first gate that does not pass: the hold, what interrupted-update
recovery and dead-owner repair would find about the owner's liveness (without performing
either), the recorded terminal handle, the owner record's side of the surface ownership check,
the stored state, an installed claim and the provider adapter's own record gate. `state` is
`admissible`, `refused` or `unknown`, never `available`, with a stable `reason` and, where the
command prints one, the command's own text in `detail`. The reason table is in
[CLI](../cli.md#inspect).

An admissible `tell` lists the gates this observation does not evaluate in `unevaluated`: the
terminal surface probe, reopened-conversation exclusivity, provider delivery readiness and the
adapter gates left to delivery (Claude native readiness, the Codex native-queue version floor and
thread, the Agy trust store and log readiness, and the native Windows Pi input receipt).
`admissible` is an observation, not a reservation or a delivery forecast: `tell` rechecks every
gate under its own locks, and an unevaluated gate can still refuse the follow-up or leave its
delivery uncertain. Unreadable or malformed records are `unknown`, never `refused`, and a legacy
session without a lifecycle lock file reports every capability `unknown` with
`lifecycle_lock_absent`, as `cancel` already did.

The Pi Windows input gate and the Claude legacy-completion gate are now decided by functions that
`tell` itself calls, so inspect and the action cannot disagree; parity tests pin the action's
text. Every provider adapter implements the two new read-only trait methods explicitly.

## Question observation capability

`capabilities.questions` has `emission_observation` and `response`. `emission_observation`
reports what the session's own launch records say was configured for observing question
emissions: `configured` for a Codex launch with injected lifecycle hooks
(`hooks_injected_unverified`) and for a native-mode Claude launch with the prepared question
plugin (`plugin_configured_unverified`); `unavailable` when the Codex hooks were not injected or
the Claude session uses legacy completion or predates the question plugin; `unsupported` for Agy
and Pi; `unknown` with `evidence_unreadable` for a malformed record or an unrecognized plugin
manifest. `configured` does not prove that the provider loaded or trusted the observer or that any
question will be observed.

`response` is `unsupported` with `no_addressed_answer_path` for every provider: Claude Code
2.1.318 has no official addressed path for answering an open question dialog from outside the
session, and Bridge supplies none. Observing a question emission is still not answering it.

## Verification and upgrade

Before the version bump, the complete local Rust suite passed (1,410 passed, 5
ignored) and the Python script suite passed (95 passed, 14 skipped). The macOS
branches of the new capability tests have run only in CI, not on a Mac. Runtime behavior of the
packaged release, and authenticated provider round trips with it, are verified separately and
recorded outside this repository.

The [open-session upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not downgrade a
binary used by an open session. The release includes macOS and Windows CLI archives and
Claude, Codex, Agy and Pi integration packages with checksums. Integration packages contain
instructions, not the engine binary; updating an integration takes effect in new host
conversations.
