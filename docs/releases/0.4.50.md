# TAB 0.4.50

0.4.50 makes several behaviors the same on macOS, Linux and Windows: the automatic terminal
choice inside an hc terminal, the refusal of a terminal the operating system does not run, and
the close of a Herdr terminal whose owner is gone. A verified git worktree now inherits its
repository's workspace consent, and Agy 1.5.17 or newer receives a consented workspace for one
session instead of showing its trust dialog. Two launch failures that surfaced as a timeout end
early with their reason. Commands and JSON output keep their form; consent records gain one
optional field.

## What changes for a caller

- **Automatic terminal inside an hc terminal (#413, #420):** every OS chooses the same way.
  TAB uses Herdr when the provider, at its installed version, can run there, and otherwise the
  terminal that OS uses outside Herdr: Ghostty on macOS, tmux on Linux, the managed console on
  Windows. In 0.4.49 an automatic `ask` with a Codex below stable 0.169.0 was refused on macOS
  and Linux; it now starts in the fallback terminal, and the session's `launch.log` notes why
  Herdr was not used. An explicit `--terminal herdr` that cannot be admitted is still refused.
  `doctor --provider <provider> --probe` reports the terminal `ask` would choose and its
  fallback. On Windows an automatic `reopen` now makes the Herdr caller check and uses Herdr
  where the provider runs there.
- **Reading the Codex version for Herdr (#413):** output with the `codex-cli` label is read as
  in 0.4.49. Output without the label is read only when exactly one word contains three
  dot-separated numbers and that word parses whole as a version. Anything else is unreadable:
  an automatic choice takes its fallback and an explicit `--terminal herdr` is refused.
- **Launch failures reported at once (#416):** a launch host refuses a session directory that
  is not private to its user. The caller now makes that check before any terminal exists and
  fails with the reason; in 0.4.49 the refusal went to `launch.log` only and `ask` waited for
  the launch deadline. A Herdr terminal that its core reports finished before startup was
  confirmed now ends the wait at the next probe instead of at the deadline.
- **Workspace consent in a git worktree (#417):** when no provider trusts the workspace
  exactly, a linked git worktree that Git verifiably registers under a main working tree
  inherits that main working tree's consent in TAB. Codex and Pi then receive their existing
  process-local trust options in the worktree. `tabcli consent revoke` or `consent reset` on
  the main working tree withdraws the inherited consent. Inherited consent never answers a
  trust dialog. A worktree registered under another spelling of its path, including one that
  differs only in case, inherits nothing until
  `git -c core.ignorecase=false worktree repair <worktree>` rewrites the registration.
- **Agy without the trust dialog (#417):** for a consented launch of an Agy identified as
  1.5.17 or newer, TAB passes the exact workspace through Agy's session-only `--settings`
  option. No key is sent and Agy's trust store is not written. This also serves exact consent
  from another provider, where 0.4.49 answered the dialog with a guarded key in iTerm2,
  Terminal.app and the native Windows console and failed the launch elsewhere. An older Agy
  behaves as before; an Agy whose version TAB cannot identify gets neither the setting nor a
  key. Every paste into Agy still needs that process's own workspace-load line in `agy.log`,
  and native Windows follow-ups now wait for it as well.
- **A consent check when the provider starts (#417):** a Codex, Pi or Agy command that carries
  a trust option is checked again just before the provider starts and is not started when its
  consent no longer holds.
- **A terminal the OS does not run (#414):** a stored handle of such a terminal is refused at
  the same step on every OS with `<Name> is not available on <OS>; use <the kinds that OS
  runs>`, and `--terminal` with such a kind is refused before a session exists; macOS used to
  create the session and fail when it opened the terminal. On Windows a send to such a handle
  is now known not sent and `doctor --probe` reports the surface as unverified, where 0.4.49
  could report an uncertain delivery or a missing surface. A handle that belongs to another
  session is reported as unbound before its kind is judged.
- **Closing a Herdr terminal whose owner is gone (#415):** the rule is now the same on every
  OS. When no live owner of the session is verified, `close-session --explicit` never ends a
  running Herdr terminal. It removes a finished terminal that the verified core identifies as
  the one the session created, settles the session when that core reports the recorded
  terminal as not found, and refuses a running one, naming the commands to inspect and end it
  on the recorded core. Dead-owner Repair leaves a Herdr terminal for that close.
  - No longer ended: in 0.4.49 Windows Repair ended a running terminal of a gone owner, and
    on every OS an explicit close ended one after a failed start or before the wrapper had
    recorded its owner; on macOS and Linux so did a resumed close whose owner had gone.
  - Now closable: on macOS and Linux, 0.4.49 refused a finished or absent terminal for any
    owner record other than a complete, bound record of an exited owner (a reused PID, an
    unbound or unreadable record, a process that could not be inspected). Such a session can
    now be closed.
  - Stricter on Windows: a finished terminal is removed only when its launch label matches
    the handle's, as on macOS and Linux.
  - On Windows an attached `ask` or `tell` now stops waiting once the recorded owner is
    verified gone, as on macOS and Linux.
  - A session with a saved teardown intent (macOS and Linux) still replays under 0.4.49's
    rules. Other terminal kinds keep their platform's rule.
- **Fixes (#418):** on Linux, a `/proc/<pid>/stat` entry read after the task's signal state
  was released no longer makes a repeated tmux close fail with `invalid digit found in
  string`; the tmux server check decides through a pidfd. On macOS and Linux, a reply that a
  Herdr core sent before it closed its socket is no longer lost and reported as unanswered.

## Verification and upgrade

- Tests: on the release source the serial suite passed on macOS 27.2.1 with Rust 1.98.1
  (2,252 tests, 6 ignored), with fmt, Clippy with `-D warnings` on the host and for the
  Windows and Linux targets, and the build check for an operating system without a terminal
  transport. CI ran the suite on macOS (2,252 tests), Linux (1,868) and Windows (1,914) on
  the last code change, and passed on each pull request.
- Live, on macOS only, with a build of the release source (record in
  [the 2026-11-27 verification](../verification/2026-11-27-0.4.50.md)):
  - Codex, Claude and Agy round trips on Herdr; the Agy session used the session-only
    setting.
  - The refusal of `--terminal tmux` and `--terminal windows-console` before a session
    exists.
  - An explicit close after a Herdr session's owner was ended outside TAB: the finished
    terminal was removed and the session closed.
  - On the head of #417, with Agy 1.5.18: a new git worktree inherited consent and started
    without a trust dialog, and an empty folder without consent showed the dialog.
- Not run live: Linux and Windows; Pi; every terminal other than Herdr; the fallback from
  Herdr with an old Codex and its launch-log line; the launch failures of #416; a stored
  handle of a terminal the OS does not run; a running Herdr terminal without a live owner;
  an Agy older than 1.5.17. They are covered by tests only.
- Upgrade: consent records gain the optional `repository_root`, and a session directory can
  hold `workspace-consent.lock` and `agy-session-trust-<random>.json` files until
  `prune-sessions` removes it. Records without the new field keep their earlier bytes. On
  Windows the consumption marker now carries the close's `reason`, as on macOS and Linux.
  No other Record changes. After a rollback, 0.4.49 reads an inherited consent record as
  `source-reset` and never grants it, handles a Herdr session that this build left open
  under its own rules (on Windows its Repair ends a running terminal), and its Windows
  replay of a consumption marker ignores the `reason`. Continuing a running session across
  the upgrade, and a rollback, were not exercised live.
