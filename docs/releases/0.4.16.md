# Terminal Agent Bridge 0.4.16

0.4.16 closes the three Windows issues of the open-issue round of 2026-10-17 that only a Windows
PC could verify, and one test defect found while verifying them: a character outside the Basic
Multilingual Plane now survives the Windows console paste into Codex (#147, #241); the two names
the Claude Code Codex plugin gives the caller's session are dropped from every launch (#149,
#242); a reopened Claude session assesses workspace consent for itself, exactly as `ask` does,
and every session start assesses consent before anything is created (#202, #243); and the doctor
test's Agy store fixture is private, so the serial suite passes on a PC with the Codex sandbox
(#240, #244). No record schema changed and no record field was added; records written by 0.4.x
are read as before. One behaviour note: the shared consent record under `workspace-consent/`
can now be written by an `ask` or `reopen` that later fails before its launch, because the
assessment precedes the creation of the session (see Changes).

## Changes

- Windows console surrogate pairs (#147, #241). Bridge pastes a prompt into the managed console
  as key events, one key-down and one key-up per UTF-16 unit. Codex reads the console through
  crossterm, which buffers a surrogate unit regardless of its key state and combines it with the
  next surrogate event, so the high surrogate's key-up broke the pair and an emoji never reached
  the composer. A surrogate unit is now written as a key-down event only; BMP text, the
  `Shift+Return` soft newline and the submission Returns are unchanged, and Pi's and Agy's console
  readers ignore key-up records, so nothing changes for them. Verified live with codex-cli
  0.163.0: U+1F600 reached Codex's own record of the user message. Documented in
  [docs/providers.md](../providers.md).
- Codex plugin caller-session names (#149, #242). The Claude Code Codex plugin's SessionStart
  hook exports `CODEX_COMPANION_SESSION_ID` and `CODEX_COMPANION_TRANSCRIPT_PATH`, the caller's
  session id and transcript path, and its tracked-jobs runtime reads the id to attribute jobs to
  the current session; a managed Codex session inherited the caller's id. Both names join the
  Claude adapter's caller-session markers, so managed and messenger Claude launches, the probes,
  and the non-provider children on macOS and native Windows drop them; the plugin's app-server
  endpoint, pid-file and log-file names are user configuration and stay. Verified live on a
  Windows Terminal tab from a caller with sentinel values. Documented in
  [docs/providers.md](../providers.md).
- Reopen consent (#202, #243). `reopen` never assessed workspace consent for the new session, so
  `authorized` stayed false for it and the guarded trust-dialog answer that a fresh `ask` can
  take was never available to a reopened session. A reopened session now assesses the source's
  recorded workspace for itself, from the current trust stores and shared consent records,
  never from the source session's records (a new Trust Store Boundary bullet in AGENTS.md). The
  independent review moved the step twice: the assessment is part of the resolution, before
  anything is created, and `create` records it with the session before anything else binds to
  that session, so a failed assessment consumes nothing and an unwritable record fails the
  creation and, for a reopen, releases the source reservation. Verified live three times (`ask
  claude`, close, `reopen`: the reopened session has its own verified assessment and the source's
  record is unchanged). Documented in [docs/cli.md](../cli.md) and
  [docs/security-and-data.md](../security-and-data.md). The pre-existing window in which a
  `result_extra` or initial claim failure after `create` leaves a reopen's source consumed is
  unchanged and tracked as #245.
- Doctor test fixture (#240, #244). `agy_workspace_trust_rows_are_observed_from_the_callers_home`
  wrote Agy's store fixture under a plain temporary home, which the Codex sandbox account on
  `%TEMP%` makes refusable as evidence, so the serial suite failed on this PC on every branch
  and, because `cargo test` stops at the first failing binary, skipped the later integration
  binaries. The temporary home is now private before the store is written (on Windows one
  full-control rule for the current token's SID; Unix unchanged). Test only.

## Why

The 2026-10-17 round over the open issues took the Windows items that this PC could reproduce
and verify: the emoji loss and the plugin variable were observed defects of every delegation
from a Claude Code session on native Windows, the reopen asymmetry was an undocumented gap
against the Trust Store Boundary, and the fixture defect hid the rest of the serial suite on
this PC.

## Verification

See the [Windows verification record](../verification/2026-10-17-windows-0.4.16.md). Every
change was verified live on native Windows 11 with codex-cli 0.163.0 and Claude Code, and each
pull request's six CI jobs passed before its merge; the Unix-only alias test of the consent
change (`consent_receives_original_alias_not_canonical_spec_workspace`) ran on the Ubuntu and
macOS CI jobs. No macOS live session was run for this release.

The Windows console large paste (#124), the stranded Codex completion of #127, the Windows
Terminal cold-start observation of #111 (not observable from a caller inside Windows Terminal,
see the issue), the self-test's inference of delivery certainty from error wording (#204),
Pi-owned records for the extension's claim and cancel reads (#196), Codex, Claude and Agy usage
(#55), the child-to-parent question channel (#189), the Ghostty cold launch (#104), Warp (#63,
#87), workspace-trust consolidation evidence (#28), Linux transport (#6) and the reopen
pre-launch window (#245) remain outside this release.
