# Terminal Agent Bridge 0.4.30

0.4.30 adds Claude completion diagnostics and two offline tools for saved verification
data. It also strengthens Claude inbound-interference regression coverage and keeps Status
observations typed until their public JSON is rendered.

## Claude completion diagnostics

`tabcli doctor SESSION --json` now reports the recorded Claude completion mode and
readiness, plus the latest stored completion rejection diagnostic. The observations are
bounded, read-only and separate from the actual delivery gate. A missing record alone
does not establish that a session predates native completion, and recorded readiness
does not prove that a session is currently ready. The rejection record has no request
identity or timestamp and cannot identify the affected request or establish recency.

See the [doctor reference](../cli.md#doctor) for the status and reason categories.

## Offline verification tools

`scripts/compare_self_test.py` compares saved self-test experiments without starting a
provider. It checks declared conditions and input identities, retains failed and missing
observations, and reports timing distributions only with their recorded provenance.
Comparable metadata remains the experiment owner's attestation. The tool does not
establish a performance improvement, token usage or cost. Collection instructions and
the input format are in [Compare saved self-test experiments](../self-test-comparison.md).

`scripts/share_diagnostics.py` reads an existing doctor, status, inspect or timeline JSON
response from stdin and emits an allowlisted Markdown or JSON summary. It omits arbitrary
text and identifiers, retains supported categories and counts, and starts no command,
reads no session directory and uploads nothing. Unknown fields and category values are
omitted; the output describes supplied data rather than authenticated runtime evidence.
See [Offline diagnostic summary](../cli.md#offline-diagnostic-summary).

Both scripts use the Python 3.9+ standard library and are available in the source tree;
the CLI and host integration archives do not bundle these scripts.

## Observation and regression coverage

Status now passes owned active/latest metadata and the selected question focus from its
Observation to its renderer, replacing intermediate JSON and duplicate focus selection.
Public JSON, missing-versus-unreadable distinctions, event decode reuse, question focus,
deadline checks and lifecycle-lock release order are preserved. Status scan tests also
use the existing Clock seam for deterministic budget checks.

Claude inbound-interference fixtures separate successful messenger delivery from a
correlated target turn and check rewritten input, late frames and markers, and successor
claims. These are automated regression checks, not new provider capability or live
verification claims.

## Verification and upgrade

Automated source, fixture and CI checks are distinct from authenticated provider or
terminal runtime checks. This release adds no new authenticated runtime verification.
The documented Ghostty 1.4.0 checks were performed with the published 0.4.29 binary;
they are not runtime evidence for 0.4.30. No new timeout or performance guarantee is made.

The existing [open-session upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not
downgrade binaries used by open sessions. The release includes macOS and Windows CLI
archives and the Claude, Codex, Agy and Pi integration packages, with checksums.
Integrations contain instructions and no engine binary. Publishing these files does
not install or update a local binary or host integration.
