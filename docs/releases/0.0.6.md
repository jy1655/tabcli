# Agent Bridge 0.0.6

Agent Bridge 0.0.6 adds session inspection, request-scoped result lookup, and diagnostics that explain the conditions needed to continue a native CLI session.

## Highlights

- `inspect <session> [--json]` reports recorded launch configuration, session state, observed owner identity, and request/result references.
- `ask` and `tell` return a public `request_id` after accepting a request. `result <session> --request <id>` retrieves that exact request, including after a caller timeout or session close. `--event`, `--latest`, and `--list` also address stored results. An unknown request is never replaced with the latest result.
- `result --wait --timeout-secs N` waits for the selected result without resending, cancelling, repairing, or closing the session. Pending recovery, failed results, unresolved requests, and timeouts remain distinct from completed results.
- `sessions` adds provider/state filters and updated-time sorting. Its existing recovery behavior remains explicit; `inspect` and `result` are read-only.
- `doctor <session>` and `doctor --provider <name>` explain local session/provider conditions using `available`, `unavailable`, or `unknown`, with reason codes, observation times, evidence, and next actions. A successful report is not a guarantee of message delivery.
- `doctor --probe` additionally queries the current CLI version and, for Codex, local daemon information. The probes share a five-second budget, cap each probe's combined output at 64 KiB, and clean up their helper processes. They do not call a model, send a message, start a daemon, control a terminal, or change settings.
- Provider adapters own their diagnostic conditions. Codex reuses the sender's native queue gates; Claude's saved inbound setting does not establish runtime messaging availability. Uncertain delivery points to the same request's result rather than another `tell`.

## Compatibility and requirements

- Provider delivery transports, completion identities, permission behavior, and explicit close semantics are preserved. Public request IDs do not replace provider-owned turn IDs or private claim tokens.
- Existing session/event records remain readable. Receipt corruption does not prevent the provider's independently verified completion from being recorded.
- Rust 1.97.1 or newer is required to install from source. Native Windows managed consoles require PowerShell 7. Provider CLIs must already be installed, authenticated, and initialized.
- Minimum provider versions remain Codex 0.147.0, Claude Code 2.1.234, Agy 1.1.12, and Pi 0.84.1.
- macOS iTerm2/Terminal.app and native Windows retain their existing support boundaries. Ghostty stays fail-closed, Linux visible-terminal transport is not implemented, and existing independent CLI processes cannot be attached after launch.

## Verification boundary

- The feature candidate in [PR #40](https://github.com/jy1655/agent-bridge/pull/40) passed 247 local tests (197 unit, 13 doctor, 22 policy, and 15 observability), Clippy with warnings denied, formatting, and diff checks. Four authenticated live harness tests remain ignored by design.
- The feature candidate passed the MSRV and macOS/Linux/Windows CI checks and both macOS/Windows package builds. An initial Windows fixture failure was corrected by comparing file contents before and after the mandatory lock, while keeping the actual diagnostic call under the lock.
- Authenticated macOS iTerm2 checks covered Codex/Claude request-specific results, repeated response text in distinct turns, timeout recovery, lookup after close, and unchanged session file bytes/modes around passive and opt-in diagnostics. Task-owned sessions were explicitly closed.
- CLI version probes were exercised with Codex 0.156.0, Claude Code 2.1.280, Agy 1.2.9, and Pi 0.84.4. The Agy/Pi checks cover version queries only.
- Native Windows authenticated CLI behavior, Terminal.app behavior for these additions, and Agy/Pi live input/completion were not revalidated for this change. CI and fixture success do not imply those runtime checks passed.
- On the development Mac, existing short-deadline Codex fixtures can fail under load, including on the unchanged baseline. Isolated and final single-threaded runs passed; hosted feature CI also passed with its normal test execution.

Result handoff automation, full-history search, and reopening closed provider sessions remain separate proposals. This release does not record Git state alongside results.
