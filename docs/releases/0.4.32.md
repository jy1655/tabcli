# Terminal Agent Bridge 0.4.32

0.4.32 stops Bridge launches from carrying a Codex caller's session and daemon-control
variables, closes the remaining cards of the 2026-10-29 architecture review, and makes two
behavior changes decided on 2026-10-30: Pi installs a pending turn only for a live session,
and the five macOS terminal hosts admit their session directory in one order with one
refusal vocabulary. Apart from the changes described below, public JSON, text output, error
messages, help text and record schemas are unchanged.

## Codex caller variables (#332, #111 follow-up)

A `tabcli` started from a Codex tool shell inherits Codex's caller context. On native Windows
the Terminal, tab host, PowerShell root and managed Claude were observed carrying
`CODEX_SESSION_ID`, `CODEX_THREAD_ID`, `CODEX_TOOL_CALL_ID`, `CODEX_DAEMON_SHUTDOWN_FILE` and
`CODEX_DAEMON_SHUTDOWN_SOCKET` (names only, 2026-10-29). In Codex 0.166.0 the first three name
the caller's session, thread and tool call, and a managed Codex's command hooks and legacy
notify replay them from the inherited environment; on Windows the socket marker lets a
control-socket app-server accept the PID-checked shutdown route, and the file marker is one
updater's shutdown request path.

The Codex adapter now owns these five names as caller markers. Every adapter drops them from
its probes and managed launches, Claude also from its messenger, and the Codex queue from its
follow-up command; non-provider helpers, including `wt.exe`, the tab host and the PowerShell
roots on Windows, drop them through the union of the adapters' lists. Nothing is stripped by
prefix: `CODEX_HOME`, CA and authentication settings, install hints, `CODEX_CI`,
`CODEX_VERSION`, the permission profile, patch compatibility and sandbox or proxy context are
kept. A hook or script inside a managed session that relied on the outer caller's Codex ids
no longer receives them. Claude's doctor check for an inherited Claude Code session still
reads only the Claude markers. See [providers](../providers.md#codex) and
[the source notes](../verification/2026-10-30-codex-caller-environment-source-notes.md).
An already running terminal application keeps the environment it started with; restart it.

## Pi pending turn (#331)

Pi installs a pending turn, for the launch plan while the session is launching and for a
follow-up before delivery, only for the current Claim of a session that has no close
tombstone and whose stored state is not ended; this was previously a token-only check. A Pi
session whose process has exited or failed, or that is closed, with its Claim still installed
no longer gets a pending-turn record: the `tell` fails with
`Pi session ended; no pending turn installed` instead of failing later at the paste. A corrupt
status or tombstone record now fails the installation with its read error. On native Windows
the initial-input wait refuses an ended session at once
(`Pi session ended; no initial console input was sent`) instead of waiting for its deadline.
The rollback cancel still removes the exact Claim's pending record in any state.

## macOS host admission (#330)

The shared session-directory admission routine for Terminal.app, iTerm2, WezTerm, Ghostty and
Warp now checks paths in one order (absolute path, session-id file name, existing path, real
directory and not a symlink, private to the user) with one set of refusal texts. Only a
defective session directory, which no normal launch produces, is reported differently: a
symlink or non-directory as such instead of "not private", a relative path as "must be
absolute", a missing directory with one text for every host, an invalid session name before a
directory privacy error, and Warp's host texts through the shared template. Nothing previously
refused is admitted. Host command-line argument validation is unchanged and can reject an
invalid id or relative path before this admission routine runs.

## Diagnostics vocabulary (#329)

`status` attention flags, `doctor` check ids and reason codes, and the self-test report words
are declared once and checked against the committed `tests/fixtures/public_vocabulary.json`
from both the Rust side and the standalone scripts. Every emitted string is unchanged.
`scripts/share_diagnostics.py` no longer allows the reasons `session_busy` and
`terminal_closed`, which nothing emits; an input that still carries one is reported as
`unrecognized` instead of copied. `docs/cli.md` lists the `question_emitted` attention flag.

## Internal ownership (#322 to #328)

The remaining cards of the 2026-10-29 architecture review move rules to one owner with no
change to JSON, text, error messages or exit codes: the Request outcome vocabulary
(`query/request.rs`, #322), Agy input evidence (`agy/evidence.rs`, #323), the Claim-currency
guard (`session::turn`, #324), lifecycle, owner verification and unreadable-elapsed judgments
(#325), adapter dispatch for read-only observations (#326), the bounded command executor and
doctor probe (`process_env`, #327), and the macOS close transaction and binding check (#328).
`CONTEXT.md` gains **Request outcome**, **Input evidence**, **Claim currency** and
**Public vocabulary**.

## Verification and upgrade

Automated source, fixture and CI checks are distinct from authenticated provider or
terminal runtime checks. On macOS the candidate binary passed the Codex and Claude
self-test, and a caller carrying synthetic Codex caller markers ran `ask`, `tell` and
`close-session` for both providers: the Codex queue and Claude messenger started by the
installed 0.4.30 carried all five values, and those started by the candidate carried none;
see [2026-10-30 macOS 0.4.32](../verification/2026-10-30-macos-0.4.32.md).
[PR #331](https://github.com/jy1655/tabcli/pull/331) reports a successful Pi self-test on
iTerm2, and [PR #330](https://github.com/jy1655/tabcli/pull/330) reports successful Codex
self-tests on iTerm2 and Ghostty, using their respective PR candidate binaries. These were
normal round trips. The new ended-session and tombstone refusals and the defective-directory
admission cases were covered by deterministic tests; the Windows Pi startup refusal was not
live-verified.
Native Windows runtime was not exercised for this release; its coverage is the Windows CI
job, which runs the `cfg(windows)` caller-marker tests, and #111 stays open for the cold
Windows Terminal and later user-tab checks.

The existing [open-session upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not
downgrade binaries used by open sessions. The release includes macOS and Windows CLI
archives and the Claude, Codex, Agy and Pi integration packages, with checksums.
Integrations contain instructions and no engine binary. Publishing these files does
not install or update a local binary or host integration.
