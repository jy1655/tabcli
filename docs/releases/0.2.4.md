# Terminal Agent Bridge 0.2.4

0.2.4 consolidates launch waits, delivery settlement, result-timeout diagnostics, and residual
surface evidence behind their owning modules. It also fixes late delivery refusals changing a
later turn and preserves the reason when a not-sent follow-up releases its claim. Provider
transports, fallback decisions, correlation, permissions, and command deadlines remain unchanged.

## Changes

- The session launch module owns the full macOS binding wait: record reads, validity checks,
  deadlines, and retries. iTerm2, Terminal.app, and WezTerm adapters supply surface identity
  checks. Existing validation order, errors, and per-adapter deadlines are preserved.
- A Claim owns sent, not-sent, and uncertain delivery settlement. Only the installed claim can
  change the turn's status; a late refusal cannot overwrite a completed or successor turn.
  Not-sent follow-ups return to ready with their failure reason preserved. Uncertain input
  stays claimed even when writing its diagnostic fails. Settlement does not publish a result
  or retry input. A cleanup error after a successfully sent initial cross-session prompt is
  recorded as uncertainty, consistently with initial terminal delivery.
- Agy and Pi adapters select the observations that can explain a self-test result timeout.
  Doctor assembles the read; self-test owns its existing execution bound. Agy still requires
  the matching request, Pi credential readiness remains session-level, and neither changes
  the request's result or claim.
- Residual-surface evidence survives changes to human-readable errors, repeated handle-less
  close, and tombstone recovery. `inspect --json` optionally reports
  `residual_surface: "unverified"`; ordinary inspection output is unchanged. An exact adapter
  close or absence confirmation clears it. The observation grants no close authority.
  Failure to persist a retained launch handle also preserves this warning. Older records
  containing the legacy warning are recognized without a migration or query write.

## Verification and limits

Verification results and the exact tested candidate are recorded in the
[macOS verification record](../verification/2026-10-07-macos-0.2.4.md).

The changes do not add an atomic exclusion between a pre-delivery check and a concurrent
close, or a crash journal for not-sent rollback. Warp's missing-control-binding recovery and
its live verification remain open. Tests of record write failures and lifecycle interleavings
are deterministic fixtures, not claims that those failures were observed live.
