# Terminal Agent Bridge 0.4.28

0.4.28 fixes iTerm2 session lookup when the front-to-back window order changes during
a lookup. It also records the macOS human-origin workspace-consent checks for #28.

## iTerm2 window lookup

The unevaluated AppleScript `windows` collection retained ordinal window references.
Selecting or opening another window could redirect a nested tab lookup to a different
window and fail with `Invalid index (-1719)`. This interrupted trust-screen observation
and follow-up delivery during the live checks.

Bridge now obtains iTerm2's window-ID specifiers before traversing the five session
lookup paths. Exact session UUID, ownership, lifecycle and screen checks remain in place.
This does not freeze tabs, panes or the renderer and grants no new input authority.
Provider adapters, consent policy and permission flags are unchanged.

## Workspace-consent verification

The operator personally approved fresh directories in external Codex and managed Agy.
Bridge then reused the exact provider-owned decisions across the other providers without
another manual workspace approval. Unapproved Claude and revoked Pi controls retained
their trust dialogs. Tests used ordinary permissions, with no `--yolo`; provider trust
stores were not edited by the harness.

The [2026-10-27 record](../verification/2026-10-27-macos-28-consent.md) identifies every
baseline and candidate case, including failures and terminal layouts. It covers macOS
26.5.2, iTerm2 3.7.6, Terminal.app 2.15, Codex 0.164.0, Claude Code 2.1.311, Agy 1.4.7
and Pi 1.4.0. The candidate iTerm2 checks completed initial and follow-up requests for
all four providers and closed each session. Pi added a period to follow-up markers;
those completed responses are not exact-text compliance passes.

Claude and Agy still require the complete exact workspace path on one screen line.
Wrapped paths require a wider terminal or manual approval in the provider. The checks
used an explicit wider layout, and do not establish wrapped-path support. Their dialog
response remains unsupported in Ghostty, WezTerm and Warp. Ordinary permission prompts,
locked screens and arbitrary simultaneous typing were not newly exercised live.

## Verification and upgrade

- A deterministic AppleScript model failed before the fix and passed afterward. A separate
  live comparison of task-owned iTerm2 windows reproduced the baseline error and verified
  the candidate's session lookup after reordering.
- The pre-version-bump candidate passed 1,533 serial Rust tests, with 6 ignored live tests,
  host and Linux/Windows cross-target Clippy, formatting and language checks. The live
  debug binary still reported 0.4.27; its exact hash is in the verification record.
  Those authenticated checks are separate from the subsequently packaged 0.4.28 binaries.
- Native Windows human-origin consent evidence remains the separate
  [2026-10-19 record](../verification/2026-10-19-windows-reopen-and-consent.md#claude-workspace-consent-28-258).
  This macOS-only fix adds no new authenticated Windows or Linux runtime claim.
- [0.4.25's upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not downgrade binaries
  used by open sessions.

The release includes macOS and Windows CLI archives and the Claude, Codex, Agy and Pi
integration packages, with checksums. Integrations contain instructions and no engine binary.
