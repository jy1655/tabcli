# Terminal Agent Bridge 0.2.6

0.2.6 concentrates the remaining Turn, Request, Reopen, and Agy Result rules from the
October 7 architecture review. Commands, JSON output, session records, provider transports,
workspace trust, and terminal close authority keep their existing behavior.

## Changes

- Turn completion and failure use the existing provider `Report` path. The unused
  owning-command completion methods on `Claim` are removed; delivery and interrupted
  completion tests now exercise the same completion path as provider adapters.
- Request observations carry their meaning before JSON is rendered. Context attachments
  use one observation operation that checks publication, incomplete receipt indexes, exact
  event names, strict event decoding, and provenance. Result, timeline, and search keep
  their distinct read policies and existing output.
- Reopen owns source reservation, new-session provenance, launch refusal, and cleanup
  settlement in one module. Doctor uses that module's read-only marker interpretation.
  Existing holder checks run at the same launch and delivery points; a later refused
  follow-up cannot release the marker of an initial prompt that may have been delivered.
- The Agy adapter shares full-result resolution and turn correlation between its incremental
  transcript monitor and read-only diagnostics. An incomplete full result does not bind a
  turn; diagnostics publish nothing. Result-before-failure ordering is unchanged.

## Verification

See the [Windows verification record](../verification/2026-10-07-windows-0.2.6.md).
Automated fixtures and authenticated CLI checks are reported separately there. Earlier
macOS live results do not establish a live pass for this version.

The broader provider, terminal, and record redesigns deferred in the
[0.2.5 review disposition](../verification/2026-10-07-architecture-follow-up.md) remain
outside these four changes. This release does not add Warp missing-binding recovery or
claim to resolve first-launch timeouts.
