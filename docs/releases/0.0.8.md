# Agent Bridge 0.0.8

Agent Bridge 0.0.8 detects provider launches that never start, preserves launch diagnostics without breaking the provider TUI, and adds the first Pi Windows startup-input protection from workspace trust issue #28. It integrates PRs #47, #49, and #51 and the release-procedure follow-up from #45.

## Changes

- `ask --detach` waits for confirmed provider spawn, for at most 30 seconds and within the overall request deadline. A terminal accepting the wrapper command is no longer sufficient for a successful launch response.
- A durable `launch.json` and the lifecycle lock serialize timeout/cancellation with spawn. Confirmed pre-spawn failures record `failed`, preserve the reason, and release only their own claim. A late wrapper cannot execute a cancelled request. If a process might already have started, the claim stays retained and input is not resent. `sessions` can settle expired new launches after the original caller exits.
- `launch.log` records wrapper stages, errors, and exit codes. On macOS it captures bootstrap stdout/stderr while the provider keeps real terminal stdin/stdout/stderr. The bootstrap is sourced from a private `launch.sh` through a short command, avoiding truncation of long commands during terminal startup. Auxiliary logging failures do not cancel a healthy launch.
- Read-only `doctor` and request-scoped `result --wait` report launch failure or expiration. `doctor --probe` checks the recorded live terminal surface and distinguishes absence from an inspection error; its successful exit still means that a diagnostic report was produced.
- Pi on native Windows waits for the official `session_start(reason=startup)` receipt for the exact initial claim before pasting input. This means the project-trust procedure has finished, including a possible decline. It is not consent and is never imported as shared trust. Pi's explicit `--yolo` to `--approve` mapping is unchanged.
- Official local, CI, and release test commands use serial test-harness execution. Concurrency exercised inside individual tests remains enabled.
- `docs/releasing.md` documents the verified main-CI-artifact publication procedure as the official alternative when the immutable-release read secret is unavailable. Immutable settings, tag identity, artifact and asset hashes/bytes, and publication attestations remain required.

## Compatibility

Existing records remain readable. Sessions created by older versions without a launch receipt are not automatically declared unsent or released merely because their owner/process file is missing. The longer `ask --detach` startup wait confirms spawn, not model readiness or completion. Provider-native transports, permissions, and result identities remain provider-owned.

Rust 1.97.1+, macOS iTerm2/Terminal.app, native Windows with PowerShell 7, and the existing minimum provider versions are unchanged. Ghostty remains unsupported before surface creation; Linux visible-terminal transport is still tracked in #6.
