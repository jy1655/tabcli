# Terminal Agent Bridge 0.4.19

0.4.19 fixes two native Windows launch problems: a failed Claude reopen can recover its source
reservation when no provider can still own the conversation, and a previously approved workspace
can pass Claude's workspace-trust dialog even when the session uses `--yolo`.

## Changes

- Reopen launch recovery (#248, #257). A launch failure records a typed `launch-failed` refusal
  tied to the original claim and launch receipt. Bridge releases the source reservation only
  when the failed launch demonstrably cannot hold the provider conversation. A subsequent
  reopen can reconcile an interrupted refusal. Live or unverifiable provider identities keep
  the reservation; read-only diagnostics do not release it. Existing provider-specific launch
  gates retain their precedence.
- Windows Claude workspace consent (#28, #258). Claude Code 2.1.302 still displays workspace
  trust under its bypass-permissions flag. For an exact workspace already approved by the user,
  Bridge recognizes native and slash-separated Windows path renderings and waits for one second
  of unchanged recognized dialog observations before its one guarded response. It retains the
  original deadline and claim, rechecks consent and session state, and confirms success through
  Claude's own trust store. This timing remains a best-effort workaround for the observed input
  guard and selector remount, not proof of atomic UI readiness. Other providers retain zero
  settle delay.
- Consent diagnostics distinguish a helper's proven pre-write refusal from an uncertain
  response, and distinguish confirmed provider trust from a failed Bridge marker update.
  Neither condition retries input.

## Verification and limits

The [Windows live record](../verification/2026-10-19-windows-reopen-and-consent.md) separates
independent actual parent/head runs, component coverage and earlier owner observations.
Opus verification reproduced the reopen failure on the parent and confirmed a same-conversation
retry on the head without changing source history. Workspace consent passed on a Windows
Terminal tab and native console fallback, using both external Codex and managed Agy approval
origins. Every owned fixture was closed.

The combined fix head passed the native serial suite (1,117 passed, 5 ignored), Clippy, fmt,
diff check and Linux/Windows target checks. Independent Claude Opus correctness and comment
reviews passed. Ignored tests are not live evidence.

macOS live consent verification and the cold Windows Terminal test (#111) are not claimed.
Claude first-Stop finality (#249), Pi input acknowledgement (#254), further provider usage (#55),
parent questions (#189), Pi record ownership (#196), structured self-test failures (#204),
Ghostty/Warp and Linux support remain outside this release.
