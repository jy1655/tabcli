# Terminal Agent Bridge 0.4.27

0.4.27 carries producer-owned failure hints to self-test, so an uncertain initial
prompt or terminal-paste follow-up is classified from its delivery result (#204).
This keeps NotVerified even when the error mentions a timeout or the recorded request
state cannot be read. It also guards against restoring Windows SID-query subprocesses
and retains Windows CI and Release test timings (#308).

## Failure diagnostics

Error JSON may include `failure_kind`: `delivery_uncertain`, `timed_out`, or `unsupported`.
Self-test recognizes those exact values, with delivery uncertainty before timeout and
timeout before unsupported. The existing `timed_out: true` also takes precedence over an
unsupported hint. A recognized hint wins over contradictory reason text.

The hint comes from the actual delivery result, selected in-process deadline checks,
real platform/version gates, or the observed result-wait deadline. Self-test also uses
its own bounded subprocess runner's deadline evidence, including expiration before
launch. The existing error text, other JSON fields, schema version, claim settlement
and cleanup behavior remain unchanged. A hint does not authorize a retry, and its
absence never proves that a prompt was not sent.

Absent, unknown and malformed hints retain the old string classifier. This includes
its accidental Unsupported matches for schema and quote errors. String-flattened
provider events, wrapper/helper failures, stderr-only close errors and parser failures
remain on their existing paths. Queries do not backfill hints into stored records.

## Windows CI regression checks

A source-policy test rejects subprocess-based current-user SID lookup in the Windows
private-permission implementation. The Windows timing recorder keeps the full Cargo output,
libtest's per-suite durations, per-test output intervals and a summary of the longest
intervals in a separate workflow artifact. The intervals include buffering, fixture and
harness work and are not profiler timings. Publication downloads only the named CLI and
integration artifacts, so timing logs are excluded from release assets.

Malformed or overflowing timing values stop being interpreted as numbers without
stopping Cargo or replacing its exit status. A broken output capture still fails the
recorder; an existing nonzero Cargo exit remains the command's result. The source-policy
check's ancestor-module/re-export limitation is documented in the testing guide.

## Verification and upgrade

- The final local native Windows candidate passed the full serial Rust suite (1,333 passed,
  5 ignored), Clippy with all features and warnings denied, formatting, language and diff checks.
  The Python suite succeeded (60 tests, 14 skips); generated integrations
  passed their source check. Ignored live tests are not runtime passes.
- The connection tests exercise actual delivery/deadline producers through printed JSON and
  the self-test reply parser. They cover uncertain timeout causes, a real missing-status read
  fallback, preserved addresses and error text, one send with a retained claim, result-wait
  record nonmutation, marker precedence, and legacy/unknown/malformed hints. Ordinary pending
  uncertainty was already NotVerified under the legacy rule; the changed cases are timeout
  causes and an unreadable request state. The other-OS terminal refusal now reports Unsupported;
  its shared module is tested, but no CI target boots an otherwise unsupported operating system.
- Twelve actual CLI refusal cases compared the local 0.4.27 candidate with installed 0.4.26.
  The five unsupported terminal JSON outputs added only `failure_kind`; stderr, exit codes
  and all other output bytes matched.
- Native Windows ordinary self-tests passed with Claude Code 2.1.310 and codex-cli 0.164.0,
  using `windows-console`, `--yolo` and the existing development workspace. Both completed ask,
  initial result, tell, follow-up result and confirmed close. This checks ordinary completion,
  not a newly approved workspace or a deliberately uncertain live send. Agy, Pi and authenticated
  macOS runtime checks were not repeated for this diagnostic change.
- [0.4.25's upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not downgrade binaries used
  by open sessions.

The release includes macOS and Windows CLI archives and the Claude, Codex, Agy and Pi
integration packages, with checksums. Integrations contain instructions and no engine binary.
