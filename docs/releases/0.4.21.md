# Terminal Agent Bridge 0.4.21

0.4.21 makes the Windows console protocol and session observations easier to verify
while retaining provider-specific delivery and completion behavior.

## Changes

- Consolidate the Windows console helper's encoding, decoding, replies, and failure
  classification. The in-process test adapter now uses the production decoder and
  provider resolver. A possible write remains uncertain; no input is retried.
- Expose typed consent and request observations to diagnostics without changing the
  strict authorization path or the permissive handling of incomplete records.
- Use the existing Clock seam for legacy Codex submission polling and console input
  drain, preserving their different deadline and Claim checks.
- Exercise the production owner verifier through lazy process and TTY observers,
  replacing the test-only copy. Add paired Codex screen fixtures that preserve the
  distinction between an empty composer and an addressed pasted draft.
- Clarify Ghostty handle retention and close intent. No new close authority is added.

The [architecture review record](../verification/2026-10-19-architecture-review-follow-up.md)
explains all nine dispositions, including the broader abstractions that were declined.

## Verification and limits

The [Windows runtime record](../verification/2026-10-19-architecture-runtime.md)
records the exact binaries, providers, terminal surfaces, caller environments, and cleanup.
Local automated validation passed 1,185 tests with five ignored; the ignored tests
are separate from authenticated runtime verification.

Native Windows runtime does not verify authenticated macOS operation, Automation
permissions, or live TTY ownership. Linux managed sessions remain unsupported.
