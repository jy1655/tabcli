# Terminal Agent Bridge 0.4.1

0.4.1 keeps Claude Code's session markers, and Bridge's own per-session variables, out of the
processes Bridge starts on macOS other than the provider (#108). A terminal application that
Bridge starts from inside a Claude Code session no longer passes those markers to the shells and
`claude` sessions you open in it later. Every record, transport, trust rule and close authority
stays as it was.

## Changes

- The commands that can start a terminal application (osascript, Warp's `open -a` and control
  CLI, the `wezterm` GUI and CLI) and Bridge's helpers (`ioreg`, the Claude workspace `git` probe,
  self-test children) drop the caller-session markers that the provider adapters declare and
  `AGENT_BRIDGE_NATIVE_STATE_DIR`, `AGENT_BRIDGE_NATIVE_SESSION_DIR`,
  `AGENT_BRIDGE_NATIVE_SESSION_ID` and `AGENT_BRIDGE_EXECUTABLE`. User configuration such as
  `PATH`, `HOME`, `CLAUDE_CONFIG_DIR` and `ANTHROPIC_*` is inherited as before. Provider launches,
  version and doctor probes, the Claude messenger and the Codex queue keep their own adapter's
  list. Native Windows keeps its environment until #111.
- `AI_AGENT` and `CLAUDE_CODE_BRIDGE_SESSION_ID` join the Claude Code markers Bridge removes,
  including from the managed Claude session and the messenger.
- Self-test passes its state root to the commands it runs in both modes; the ordinary mode relied
  on inheritance before.
- Terminal.app's send and screen scripts stop when Terminal.app is not running instead of
  starting it.

A terminal application started by an earlier version still holds the markers it inherited;
quit it and start it again.
