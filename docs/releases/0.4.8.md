# Terminal Agent Bridge 0.4.8

0.4.8 ships the four changes that were open after 0.4.7 on native Windows and in the documentation
(#122, #123, #126 and #111; #111 stays open for one observation). Two visible changes on the Windows
console: a multi-line Codex prompt keeps its line feeds, and a managed launch no longer hands the
caller's Claude Code session markers to Windows Terminal and the console roots. Records written by
0.4.x are read as before.

## Changes

- A Codex Windows console paste preserves line feeds (#126). The Codex adapter declares, beside its
  submission count, that the console should encode a line feed as Shift+Return, which Codex's default
  keymap binds to newline insertion and which an active paste burst absorbs as a newline; the console
  encoder applies that mode to line feeds only, and both submission Returns are unchanged. Before,
  every line feed was a key event with virtual key 0 that Codex's console reader discards, so a
  281-line prompt reached the model as one line. Tabs cannot be sent the same way (Codex's default
  queue key is plain Tab), so the Codex initial paste on the Windows console refuses a prompt that
  contains a tab before anything is written; the native queue follow-up, Agy, Pi and macOS are
  unaffected. Agy and Pi keep the previous line-feed encoding, now declared explicitly.
- Non-provider children on native Windows drop the caller's session context (#111). `wt.exe`, the tab
  host, both PowerShell roots, the console-control helper and the `whoami.exe` security helper no
  longer receive the union of the adapters' caller-session markers and Bridge's four session variables;
  the environment block is built by one function that both roots share, so the tab root and the
  console-window root keep identical environments. What a child needs still reaches it explicitly: the
  console-control helper gets the selected state root back, the bootstrap sets it for the wrapper, and
  the wrapper gives the new session's directory, id and executable to the provider and its hooks.
  An already contaminated terminal application is not cleaned retroactively and must be restarted.
- The README Install section names the Cargo version (#123). A policy test reads the Install section
  and requires every version there to equal `CARGO_PKG_VERSION`, so a release that forgets the README
  fails its own suite; the release preparation step lists the README among the places that must agree.
- The claim and close hand-off tests wait for the other thread instead of one second (#122). On
  Windows a close replaces several records through a bounded rename retry, which once exceeded the
  tests' one-second hand-off on a Release run. Test-only change.

## Verification

See the [Windows verification record](../verification/2026-10-12-windows-0.4.8.md). Automated
fixtures and authenticated CLI checks are reported separately there.

Warp (#63, #87), the Windows console large paste (#124) and notify payload limit (#127), the Windows
Terminal cold-start observation of #111, the console paste's loss of a non-BMP character (#147), the
environment block's Unicode uppercasing (#148), the inherited plugin marker (#149) and Linux transport
(#6) remain outside this release.
