# Terminal Agent Bridge 0.4.15

0.4.15 closes four issues of the open-issue round of 2026-10-17 and adds the first provider of
#55: a Codex turn steered by a message typed into the managed TUI is correlated (#65, #235);
Windows environment names are compared as Windows compares them and the console helper test no
longer depends on PowerShell startup time (#148, #180, #236); the Windows notify payload limit is
documented and estimated by a doctor check (#127, #237); and the usage Pi reports for a request is
recorded beside its result (#55, #238). No record schema version changed. Two optional fields were
added to the session event (`usage`, `usage_error`) and two to the Codex pending-turn record
(`framed_prompt_chars`, `framed_prompt_units`); records written by 0.4.x are read as before, and
0.4.14 reads these records while ignoring the new fields. One boundary is new: a Pi session whose
turn this version journaled must not be served by a downgraded binary while it is open (see
Changes).

## Changes

- Codex steered turns (#65, #235). codex-cli 0.163.0 steers a message typed into the TUI while a
  turn runs into that turn: the completion's `input-messages` carries Bridge's framed prompt first
  and the typed text last, and the answer serves both. The correlation accepted only the last
  element, so the request stayed `pending`. It now accepts the framed prompt in any position; the
  header requirement is unchanged, so Codex's title turn (#61) is still rejected. The recorded
  result is the answer to both inputs. Reproduced live on macOS with recorded payloads.
- Windows environment block (#148, #236). The block for `wt.exe`, the tab host's PowerShell root
  and the console-window root keyed names by Rust's full Unicode uppercase, which maps `ß` to `SS`
  and merged two names Windows keeps apart. Names are now compared as the standard library's
  `EnvKey` compares them, `CompareStringOrdinal` ignoring case over the UTF-16 units; ASCII case
  variants still merge, hidden `=C:` names stay, and the block stays sorted by that rule.
- Windows console helper test (#180, #236). `close_deadline_console_helper_is_bounded` allows
  25 s for the timeout case and gives the stderr case a 120 s deadline, so a loaded runner no
  longer decides the result; the properties the test states are unchanged.
- Codex notify payload limit on native Windows (#127, #237). Codex runs the notify command with
  the whole payload as one argument, and Windows refuses a command line of 32,767 UTF-16 units or
  more, so a long prompt with a long answer never reaches Bridge and the request stays pending.
  [docs/providers.md](../providers.md) documents the limit, the mitigation and the recovery;
  `doctor <session>` gains `codex_notify_payload_budget`, an estimate (not a measurement) of the
  pending turn's command line from the framed prompt's size, which the Codex pending-turn record
  now keeps for the initial turn and for each follow-up (`framed_prompt_chars`,
  `framed_prompt_units`, sized before delivery). Documented in [docs/cli.md](../cli.md). The
  stranded completion itself is not fixed; #127 stays open.
- Pi-reported usage (#55 stage 2, Pi only; #238). Pi documents `usage` as a required field of
  every assistant message. The extension sums it over every run of the correlated claim until
  settlement and sends it, or a bounded `usage_error`, with the hook payload and the hook-failure
  signal. The event keeps `usage` (`source: pi_extension_agent_end`, `scope: request`,
  `coverage: complete | uncertain`, `runs`, `assistant_messages`, input, output, cache read, cache
  write, optional reasoning and total tokens; no cost) and `usage_error`. `result`, the `--wait`
  reply, the `--list` arrays and the timeline's request summaries report `usage`, `usage_reason`
  (`not_reported`, `malformed`, `omitted_size`, `no_published_result`) and `usage_error`; human
  `result` prints one usage line. Usage never changes the outcome: the size policy drops the
  usage, then the usage error, before it fails a message that fits on its own; a malformed operand
  or sum records no partial figure. Compaction summaries, nested tool usage and Pi's computed cost
  are not collected. Boundary: an older binary drops the new event fields and sees a journaled
  completion as `Mismatched`, so do not downgrade the installed binary or
  `AGENT_BRIDGE_EXECUTABLE` while a Pi session whose turn this version journaled is open;
  upgrading is supported. Codex, Claude and Agy usage remain open under #55. Verified live
  against Pi 1.2.0's session JSONL. Documented in [docs/cli.md](../cli.md) and
  [docs/providers.md](../providers.md).

## Why

The 2026-10-17 round over the 18 open issues took the items this Mac could finish: the Codex
correlation defect blocked `tell`-less direct interaction with a managed TUI, the two Windows
fixes were small and verifiable on the Windows CI runner, the notify limit needed at least a
diagnosis and a warning, and Pi was the one provider whose consumed signal already carries
documented usage.

## Verification

changes (#148, #180, the `cfg!(windows)` branch of the doctor check) are verified by the
`rust (windows-latest)` CI job of each pull request, which ran the two changed Windows tests;
no Windows live session was run for this release.

the extension's claim and cancel reads (#196), workspace consent for a reopened Claude session
on native Windows (#202), Warp (#63, #87), the Windows console large paste (#124), the stranded
Codex completion of #127, the Windows Terminal cold-start observation of #111, #147, #149,

launch (#104), workspace-trust consolidation evidence (#28) and Linux transport (#6) remain
outside this release.
