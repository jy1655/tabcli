# Terminal Agent Bridge 0.4.12

0.4.12 answers issue #216: Codex's background memory consolidation delegated work through
`tabcli ask` from its memory workspace and left the sessions open, and nothing reported them.
Two changes are visible. A launch in the Codex memory workspace is refused by default (#217),
and every query now reports a session's origin, with `close-session` listing the open sessions
that were started from the session it closed (#218). Records written by 0.4.x are read as
before; no record schema changed.

## Changes

- Launch admission for the Codex memory workspace (#217). The new setting
  `tabcli settings codex-memory-workspace refuse|allow`, default `refuse`, makes `ask`, `reopen`
  and `self-test` refuse a workspace that is `$CODEX_HOME/memories` (or `~/.codex/memories`
  without `CODEX_HOME`, read from the caller's environment) or lies inside it, for every
  provider, before any session directory, record, consent record or surface exists. Paths are
  compared after link resolution by whole components. `reopen` reports the pre-create gate
  `workspace-refused`; `self-test` applies the admission before creating an isolated root and
  reports a single `admission` step, with `state_root: null` in isolated mode. The Codex adapter
  declares the location; the shared admission applies the setting (`AGENTS.md`, "Current Codex
  Boundary").
- Origin observation (#218). `CONTEXT.md` names the *Request source* (the managed session a
  request was issued from, or `external`), a session's *Origin* (the request source of its
  initial prompt, identified by the launch claim's receipt) and *Origin ended* (a closed
  tombstone, a closed, failed or exited status, or an attested owner process that is gone).
  `status`, `sessions --json`, `inspect` and `doctor` render the same `origin` and
  `origin_observation` fields; `status` adds the attention flag `origin_ended` and `doctor` the
  check `origin`. The observation reads records only, within a bounded budget, and grants no
  close authority.
- `close-session` reports the sessions started from the closed session (#218). After a
  successful close, a bounded one-shot scan of the state root lists, as `started_from`, the open
  sessions whose origin is the closed session, with `incomplete` and its reasons when a bound
  was reached. Human output adds the list after `closed SESSION`. A scan failure never fails
  the close, and nothing is closed on the user's behalf.
