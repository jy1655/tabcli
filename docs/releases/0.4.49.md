# TAB 0.4.49

0.4.49 is mainly an internal restructuring. Six parts of the terminal and launch code now
have one owner each: the identity of a Herdr terminal (#406), the Windows adapter lookup
(#407), the launch-host contract (#409), the Codex surface decision (#408), the rule for a
terminal that outlives its owner (#410), and the choice of a launch's terminal (#411).
Commands, records and JSON output keep their form. Two behaviors change, both on Herdr.

## What changes for a caller

- Codex on Herdr, macOS and Linux (#408): a Codex older than stable 0.169.0, a prerelease,
  or a version that cannot be read is refused right after the version probe, before a
  consent record, a session directory or a Herdr terminal exists. Earlier releases refused
  it during the launch, after the session and its terminal had been created. The error reads
  `codex on Herdr is unsupported: <reason>`.
- Reading the Codex version for Herdr (#408): the word after the `codex-cli` label in
  `codex --version` is the version, read whole as an optional `v` and a SemVer version.
  Output without the label is accepted only when it is a single word. Anything else is
  refused, including a longer unlabelled line such as `OpenAI Codex (v0.170.0)`, which the
  launch check in 0.4.48 accepted. Other uses of the Codex version (the follow-up queue,
  hooks and doctor) read it as before, so existing sessions and launches in other terminals
  are unaffected.
- Herdr launch failures on Linux and Windows (#409): when the launch host cannot flush the
  terminal's startup input, or cannot start bash on Linux or PowerShell on Windows, `ask`
  fails with `input_flush_failed` or `launch_shell_exec_failed` as soon as the host records
  it. Earlier releases wrote these failures to the launch log only, and the launch waited
  for its deadline before reporting a timeout. Doctor's `launch_stage` check points to
  `inspect --timeline` for both reasons.
- Texts (#409): the fallback detail of doctor's `launch_stage` check now names the Linux
  and Windows Herdr startup failures, and a PowerShell wait error after a successful start
  says `cannot wait for the PowerShell root`.

Everything else behaves as in 0.4.48. In particular, Windows still refuses Codex on Herdr
and directs it to `--terminal windows-console`, and the differences between Windows and
macOS or Linux in closing a Herdr terminal whose owner has exited are unchanged.

## Verification and upgrade

- Tests: the serial suite passed on macOS 27.2.1 (2,062 tests, 6 ignored), Ubuntu 26.04
  (1,673 tests, 1 ignored) and Windows 11 (1,749 tests, 5 ignored), with fmt and Clippy with
  `-D warnings` on each host. The Linux and Windows runs used the source before the version
  change (`36f4a24`). CI passed on each pull request.
- Live, with builds of that source (record in
  [the 2026-11-26 verification](../verification/2026-11-26-0.4.49.md)):
  - macOS: Codex and Claude on Herdr, Codex in WezTerm, and an explicit close after a Herdr
    terminal's program was ended outside TAB.
  - Linux: Codex and Claude on tmux, and Claude on Herdr.
  - Windows: Pi on the managed console and on Herdr, and the refusal of Codex on Herdr.
- Not run live: Agy on any platform; Codex and Pi on Linux Herdr; Claude, Codex and Agy on
  Windows; iTerm2, Ghostty, Terminal.app and Warp on macOS. The launch-host failure reports
  of #409 are covered by tests only.
- Records keep their format, and a session started by 0.4.48 continues under 0.4.49. The
  launch-host failure record uses the existing schema, which 0.4.48 reads.
