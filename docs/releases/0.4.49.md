# TAB 0.4.49

0.4.49 refuses an unsupported Codex on Herdr earlier, and reports two Herdr startup failures
on Linux and Windows by their reason instead of a timeout. The terminal and launch code was
also reorganized (#406, #407, #408, #409, #410, #411). Commands, records and JSON output keep
their form.

## What changes for a caller

- **Codex on Herdr, macOS and Linux (#408):** once Codex passes the general version check,
  TAB applies Herdr's minimum of stable 0.169.0 and its version-reading rule before it
  records consent or creates the session or its terminal. In 0.4.48 the Herdr check ran in
  the launch wrapper, after both existed. The refusal reads
  `codex on Herdr is unsupported: <reason>`. A Codex below the general minimum of 0.147.0, or
  output with no readable version, is refused by the general check as before.
- **Reading the Codex version for Herdr (#408):** when the `codex --version` output contains
  the `codex-cli` label exactly once, the next word on the same line is the version, read
  whole as an optional `v` and a SemVer version. Output without the label is accepted only
  when it is a single word. Anything else is refused: a repeated label, a label with no word
  after it on its line, and longer unlabelled output such as `OpenAI Codex (v0.170.0)`, which
  the launch check in 0.4.48 accepted. Words before the label are no longer read as the
  version: a line `plugin 0.160.0` followed by a line `codex-cli 0.170.0` is now accepted,
  where 0.4.48 read `0.160.0` and refused. Other uses of the Codex version (the follow-up
  queue, hooks and doctor) read it as before.
- **Herdr startup failures on Linux and Windows (#409):** a launch host that is bound to its
  Herdr terminal, verifies its own process identity and still owns the pending launch now
  records two failures. `input_flush_failed` means it could not flush the terminal's startup
  input, or on Windows could not open console input. `launch_shell_exec_failed` means it
  could not start bash on Linux, or prepare or start PowerShell on Windows. `ask` then fails
  with that reason, with `awaiting_host` as the last recorded stage, instead of waiting for
  the launch deadline. Doctor's `launch_stage` check points to `inspect --timeline` for both
  reasons. Other host refusals are written to the launch log only, and a launch that remains
  unconfirmed can still time out. They include a session directory that fails the
  private-directory check, a host that cannot verify its identity or no longer owns the
  launch, and an error while waiting for a PowerShell that already started.
- **Stored handles of other terminals on Windows (#407):** Windows never creates a Ghostty,
  Warp, WezTerm or tmux handle, but it can read one. A screen read of a Ghostty or Warp
  handle, and guarded dialog input for a Ghostty, Warp, WezTerm or tmux handle, used to be
  refused by the console helper. They are now refused earlier, with that terminal's own
  message.
- **Diagnostic messages (#409):** an unavailable native launch host reports
  `this native launch host is unavailable on this platform` (was
  `native launch hosts are only available on macOS`). The fallback detail of doctor's
  `launch_stage` check names the Linux and Windows Herdr startup failures. An error while
  waiting for a started PowerShell says `cannot wait for the PowerShell root`.

Windows still refuses Codex on Herdr and directs it to `--terminal windows-console`. The
differences between Windows and macOS or Linux in closing a Herdr terminal whose owner has
exited are unchanged.

## Verification and upgrade

- Tests: the serial suite passed on macOS 27.2.1 with Rust 1.98.1 (2,062 tests, 6 ignored),
  on Ubuntu 26.04 with Rust 1.97.1 (1,673 tests, 1 ignored) and on Windows 11 with Rust 1.97.1
  (1,749 tests, 5 ignored), with fmt and Clippy with `-D warnings` on each host. The Linux and
  Windows runs used the source before the version change (`36f4a24`); macOS ran that source
  and the release change. CI passed on each pull request.
- Live, with builds of that source (record in
  [the 2026-11-26 verification](../verification/2026-11-26-0.4.49.md)):
  - macOS: Codex and Claude round trips on Herdr, a Codex round trip in WezTerm, and an
    explicit close after a Herdr terminal's program was ended outside TAB.
  - Linux: Codex and Claude round trips on tmux, and a Claude round trip on Herdr.
  - Windows: Pi round trips on the managed console and on Herdr, and the refusal of Codex on
    Herdr.
- Not run live: every other provider and terminal combination, including all of Agy, and Pi
  on macOS and Linux. The Codex version refusals on macOS and Linux, the startup failure
  reports of #409 and the Windows handle refusals of #407 are covered by tests only.
- Upgrade: the record format is unchanged. Source inspection shows that the 0.4.48 reader
  accepts the new failure record. Continuing a running session across the upgrade, and
  reading a failure record written by 0.4.49 after a downgrade, were not exercised live.
