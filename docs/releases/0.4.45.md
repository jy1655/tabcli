# Terminal Agent Bridge 0.4.45

0.4.45 adds a macOS terminal adapter for Herdr Core (`hc`). Bridge sessions can stay
inside Herdr while retaining request-addressed results and provider-specific completion.

## Changes

- **Herdr surface:** `--terminal herdr` (aliases `hc` and `herdr-core`) creates a new terminal in an
  already running local core. Inside Herdr, detection recognizes `HC_TERMINAL_ID`
  alongside its Ghostty terminal identity. An explicit terminal choice still wins.
- **Bound control:** the adapter retains the core and terminal identities for screen
  reads, input and close. It never starts or restarts the core, addresses remote hc
  machines, or closes unrelated terminals. Lost responses and uncertain input are
  not retried automatically.
- **Provider behavior:** Codex requires stable 0.169.0 or newer on Herdr and receives
  `--no-daemon` so its tools run inside that terminal. Its follow-ups still use the
  native queue; Claude still uses official messaging. Agy and Pi use addressed
  terminal input. Other surfaces retain their existing provider launch options.
- **Startup environment:** the launch host removes inherited provider caller markers
  before starting the CLI, including markers retained by an existing hc core.
  It does not change the core's environment for other terminals.

## Limits and upgrade

This adapter is macOS-only and targets Herdr Core, not the older Herdr TUI. Open Herdr
or start hc before launching. Bridge cannot compare a workspace trust dialog and send
a key atomically through hc; answer such dialogs through Herdr or `hc attach`.
Herdr's OSC status is presentation only, never Bridge result or close authority.

The new terminal record is additive. Older binaries cannot interpret a Herdr surface;
finish and close these sessions before downgrading. Existing provider protocol
downgrade restrictions also remain in effect.

See [Herdr setup and behavior](../terminals.md#macos--herdr-core).
