# Terminal Agent Bridge 0.4.33

0.4.33 prevents directly spawned Codex, Agy and Pi commands from inheriting a Claude
caller's session identity and messaging context (#335). Execution settings remain available
to those commands. There are no changes to provider transports, completion protocols,
permission policies, public output or record schemas.

## Claude caller identity

The Claude adapter owns a ten-name identity subset of its existing removal list. Codex,
Agy and Pi select that subset by reference for provider probes and launch plans, alongside
the five Codex caller variables already removed in 0.4.32. The Codex follow-up queue uses
the same adapter selection. This covers version preflight, doctor probes and Pi credential
probes as well as the queue command.

The removed names are `CLAUDE_CODE_BRIDGE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`,
`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_PID`, `CLAUDE_CODE_MESSAGING_SOCKET`,
`CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_SESSION_ATTENDED`,
`CODEX_COMPANION_SESSION_ID` and `CODEX_COMPANION_TRANSCRIPT_PATH`.

Direct non-Claude commands retain `AI_AGENT`, `CLAUDE_EFFORT`, `CLAUDE_CODE_ENTRYPOINT`
and `CLAUDE_CODE_EXECPATH`. Configuration, credentials and unrelated variables are not
filtered by prefix. Claude's own full removal list and caller diagnostic remain unchanged.
Non-provider helpers still remove the existing union; this change does not restore hints
that a terminal or helper already removed. A command that relied on the caller's identity
will no longer receive those values. An already running terminal application retains its
startup environment until restarted.

## Verification and upgrade

The implementation was checked with fixed-name regression tests, complete launch-plan
fixtures and actual probe subprocesses. On macOS, synthetic provider executables observed
all ten identity values on published 0.4.32 and none on the implementation candidate, while
the four execution hints survived. These fixtures do not establish authenticated provider
behavior.

Separately, the implementation candidate completed authenticated Codex 0.166.0, Agy 1.4.11
and Pi 1.4.0 round trips on iTerm2. Five samples of its actual Codex queue process contained
none of the ten identity sentinels and retained `AI_AGENT` and a positive control. All task
sessions were closed. This candidate still reported version 0.4.32; its exact binary and
source identities are in the [macOS verification record](../verification/2026-10-30-macos-335-caller-identity.md).
These checks do not establish runtime behavior of the subsequently packaged release.
Native Windows authenticated runtime remains unverified; #111 remains open for its
cold-terminal and later user-tab checks. Windows CI and cross-target checks are separate
evidence.

The [open-session upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not downgrade a
binary used by an open session. The release includes macOS and Windows CLI archives and
Claude, Codex, Agy and Pi integration packages with checksums. Integration packages contain
instructions, not the engine binary; updating an integration takes effect in new host
conversations.
