# Agent Bridge 0.0.7

Agent Bridge 0.0.7 adds workspace-scoped search over stored results, explicit result handoff from one request to the next with provenance, and a fix that lets managed Claude sessions be reached when Agent Bridge is invoked from inside a Claude Code session.

## Highlights

- `search <query> [--workspace PATH | --all-workspaces] [--provider <name>] [--limit N] [--json]` performs case-insensitive literal substring search over published result bodies under the Agent Bridge state root. It defaults to the current canonical workspace. For each hit, the command returns the session, provider, workspace, title, request id (null for legacy events without a receipt), event id, creation time, a sanitised excerpt of at most 200 displayed characters, and the exact `result` command to re-read the body.

- Search is read-only: it never recovers, repairs, sends, closes, or writes, and reads only session records. Budgets of 5,000 events, 64 MiB of event bytes, and 10 seconds bound the scan; exceeding one, a busy snapshot, an unreadable or corrupt manifest/status/event, a missing or non-directory `events` folder, or a damaged request index marks the response `incomplete` with per-session reasons. `truncated` (more hits than `--limit`) is distinct from `incomplete`, and an incomplete zero-hit scan is never reported as "no results". Legacy events without receipts are searchable only when the request index of their session is fully readable.

- `ask` and `tell` accept `--context-result <session>/<request-id|event-id>`, repeatable up to 8 times. Each value is resolved before any claim, receipt, terminal launch, or delivery: only a published successful result (`request_state` `completed`) is attachable. A state of `pending`, `failed`, `unresolved`, `recovery_required`, or `unavailable`, a pruned session (`missing`), a corrupt, invalid-UTF-8 or case-mismatched record (`unreadable`), an unverifiable mapping behind a damaged request index (`unverifiable`), or a busy snapshot (`busy`) fails the command before anything is sent or created, with the exact `result` query to verify.

- Attached bodies are appended after the prompt as delimited reference data with a per-attachment nonce, never modified or silently truncated; bodies with terminal control characters or a total over 256 KiB are refused. The receipt of the new request records `context_sources` (session, request id, event id, provider, creation time), which `inspect`, `result`, and the `ask`/`tell` JSON responses expose. Old receipts without the field still load.

- The Claude adapter removes Claude Code session markers (`CLAUDE_CODE_CHILD_SESSION`, `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_PID`, `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_EXECPATH`, `CLAUDE_EFFORT`) from the environment of the managed session and the messenger. A managed `claude` that inherited `CLAUDE_CODE_CHILD_SESSION` treated itself as a nested child session and never registered its cross-session inbox, so `ListAgents` could not discover it and delivery failed; on native Windows, where the initial prompt also travels through the messenger, `ask claude` failed outright when invoked from inside Claude Code (issue #42). User configuration such as `ANTHROPIC_*` and `CLAUDE_CONFIG_DIR` is left untouched. `doctor` reports the markers present in the caller environment as `claude_caller_markers`.

## Compatibility and requirements

- Provider delivery transports, completion identities, permission behavior, and explicit close semantics are unchanged. The removal list is owned by the Claude adapter; Codex, Agy, and Pi adapters return an empty list and are otherwise untouched.

- Existing session, event, and receipt records remain readable; `context_sources` is optional on receipts.

- `search` and `--context-result` reuse the read-only snapshot machinery of `inspect`/`result` and add no new state files beyond the receipt field.

- Rust 1.97.1 or newer is required to install from source. Native Windows managed consoles require PowerShell 7. Provider CLIs must already be installed, authenticated, and initialized.

- Minimum provider versions remain Codex 0.147.0, Claude Code 2.1.234, Agy 1.1.12, and Pi 0.84.1.

- macOS iTerm2/Terminal.app and native Windows retain their existing support boundaries. Ghostty stays fail-closed and Linux visible-terminal transport is not implemented.

## Verification boundary

- The integration branch passed 267 local tests on Windows (200 unit, 9 context_result, 9 doctor, 19 policy, 15 observability, 14 search, 1 live-harness self-test with 4 authenticated live tests ignored by design), Clippy with warnings denied, formatting, and diff checks. Each feature commit was reviewed by Codex through Agent Bridge and the review findings were fixed in follow-up commits before integration.

- Native Windows authenticated checks on 2026-09-24 (Windows 11, PowerShell 7.5.4, Codex 0.156.1, Claude Code 2.1.281, Agy 1.2.10, Pi 0.84.4): the four provider live smokes in `tests/native_live.rs` passed on `windows-console`, including Codex invoked from cmd.exe and Windows PowerShell 5.1; the Claude smoke failed before the marker fix when run from inside Claude Code and passed after it with the caller environment inherited as-is; `search` ran against the real state root and its hit addresses were re-read with `result`; a Codex `ask --context-result` attached a Claude result and returned it with `context_sources` recorded.

- macOS runtime behavior for this release, including the `tell` path of the Claude marker fix on macOS, was not revalidated; static review indicates the same messenger path applies.

- Windows Agy initial-prompt console paste was observed to be lost intermittently for long multi-line prompts (issue #43); this release does not change that path.

- Codex 0.156.1 on native Windows exposes daemon subcommands whose control socket connection fails; Agent Bridge treats the daemon as unavailable and keeps the console follow-up path, which was verified.

Reopening closed provider sessions in a new terminal remains a separate proposal and is not part of this release.
