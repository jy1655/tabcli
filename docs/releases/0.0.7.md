# Agent Bridge 0.0.7

Agent Bridge 0.0.7 adds workspace-scoped search over stored results, explicit result handoff with provenance, reopening of closed
Claude Code sessions on native Windows, a readiness gate and input receipt for every Agy paste (the native Windows initial prompt and
every follow-up on native Windows and macOS), and lifecycle hardening for completion, close, dead-owner repair, and durability. It also
fixes managed Claude sessions being unreachable when Agent Bridge is invoked from inside a Claude Code session. This candidate was
verified on native Windows and on macOS; Linux stays unsupported.

## Highlights

- `search <query> [--workspace PATH | --all-workspaces] [--provider <name>] [--limit N] [--json]`: case-insensitive literal substring
  search over published result bodies under the state root, scoped to the current canonical workspace by default; each hit carries
  session, provider, workspace, title, request id (null for legacy events without a receipt), event id, creation time, a sanitised excerpt
  of at most 200 displayed characters, and the exact `result` command. Read-only; budgets of 5,000 events, 64 MiB of event bytes, and
  10 seconds; damaged records, a damaged request index, a missing or non-directory `events` folder, and busy snapshots mark the response
  `incomplete` with per-session reasons; `truncated` is distinct from `incomplete`; journaled results are read at their scan position so
  results do not change after `sessions`. A link at a session's `manifest.json` or `requests/` is refused like a linked `events/` (the
  session is reported unreadable or its index incomplete), so nothing outside the state root can decide a session's scope or supply
  request identity for its events; `result`, `inspect`, and `--context-result` share the refusal (found by the Codex review of the macOS
  verification).
- `ask` and `tell` accept `--context-result <session>/<request-id|event-id>` up to 8 times. Each value is resolved before any claim, receipt,
  launch, or delivery: only a published successful result is attachable; other states (`pending`, `failed`, `unresolved`, `recovery_required`,
  `unavailable`, `missing`, `unreadable`, `unverifiable`, `busy`) fail the command before anything is sent, naming the exact `result` query.
  Bodies are attached verbatim between nonce delimiters, never truncated silently; control characters or more than 256 KiB total are refused.
  The new receipt records `context_sources`, exposed by `inspect`, `result`, and the `ask`/`tell` JSON. Old receipts still load.
- `reopen <closed-session> (--prompt | --prompt-file) [--title] [--model] [--effort] [--terminal] [--yolo] [--timeout-secs] [--detach] [--json]`
  continues a closed Claude Code conversation in a new managed session through the official `claude --resume <conversation uuid>` with a new
  private settings file and a new session name, on native Windows only in this release; Codex, Agy, and Pi refuse with an adapter-owned reason.
  Gates are read-only and fail closed: source closed and converged, a Claude event supplies the conversation uuid, every receipt resolves to
  a readable event, and the Claude session registry shows no other live holder (pid alive with matching process start time). One reopen per
  source is serialised by a source marker claimed under the source's turn-claim lock. Ownership is rechecked immediately before spawn, after
  launch once the new process registers, before the initial prompt, and before every follow-up; a conflict fails only the new session and
  closes only its surface. Because Claude Code permits concurrent resumes, this is best-effort detection, not exclusion. The source marker
  is released only when the recorded provider process is verified gone (dead, or a reused pid with a different identity) or no process was
  spawned. Model, effort, and permission mode are never copied from the Bridge source manifest; Claude's own resume rules decide what the
  conversation restores. `resumed_from` is recorded beside the manifest and shown by `inspect`; `doctor` gains `reopen_marker` and
  `claude_resumed_conversation_holders`.
- Agy on native Windows: the initial prompt is pasted only after Agy's own log shows `CLI startup completed` and a later full redraw, after
  either the deferred skills reload has happened (a skills reload logged within one second of startup is the startup reload and does not count) or 45 seconds have passed since startup, and after a 3.5 second quiet window with no reload
  or redraw lines, all timed concurrently; log continuity is checked over every observed byte and evidence resets on any discontinuity.
  After every paste (initial prompt and `tell`) a receipt is required within 60 seconds (capped by the request deadline): a complete `HandleUserInput` line after the pre-paste offset carrying
  the full turn marker. A missing receipt is delivery-uncertain (claim kept, no second paste, session `working` with the reason in
  `status.error`); only a readiness timeout before any paste is `not_sent`. `doctor` gains `agy_input_receipt`.
- Agy on macOS: the initial prompt stays a `--prompt-interactive` launch argument, so the first `tell` is the first paste and meets the
  same startup burst. Every macOS follow-up now waits for the same gate without the redraw marker (Agy logs no `Full redraw completed`
  on macOS) and with a 60 s deferred-reload window (the reload arrived 11.2 s and 55.4 s after startup on the verification Mac; the
  55.4 s one cleared a paste made at the end of a 45 s window), and requires the same receipt; the macOS smoke on 2026-09-24 had lost
  a `tell` pasted 10.3 s after startup, 0.85 s before the deferred skills reload, and reported it as delivered. A follow-up to a session
  whose deferred reload is already logged, or whose own log stamps already span the window since startup, passes after one 3.5 s quiet
  period; only a follow-up to a session that is still inside its window on both clocks waits for the window to end. On both platforms a skills reload logged within one second after a `Starting new
  conversation` line is that conversation's reload and never settles the deferred-reload condition; without this rule the reload that the
  argument-delivered macOS prompt triggers a few seconds after startup would open the gate before the deferred reload. The macOS receipt
  is the same Go-quoted `HandleUserInput` record, one line per multi-line paste, carrying the verbatim framing header instead of the
  Windows JSON envelope. The `agy_input_receipt` doctor check reports `redraw_required` and `conversation_reload_after_startup_ignored`.
- The Claude adapter removes Claude Code session markers (`CLAUDE_CODE_CHILD_SESSION`, `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_PID`,
  `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_EXECPATH`,
  `CLAUDE_EFFORT`) from the environment of the managed session and the messenger. An inherited `CLAUDE_CODE_CHILD_SESSION` made the managed
  `claude` treat itself as a nested child and skip registering its cross-session inbox, so `ListAgents` could not find it; on native Windows
  `ask claude` failed outright when invoked from inside Claude Code (issue #42). User configuration such as `ANTHROPIC_*` and `CLAUDE_CONFIG_DIR`
  is untouched. The version preflight and the `doctor --probe` queries drop the same adapter-owned list, so no `claude` the bridge starts
  inherits the caller's session identity. `doctor` reports `claude_caller_markers`.
- Lifecycle hardening (issues #5, #12, #13, #15): `closed.json` is the commit point of a close and recovery converges an interrupted close;
  the completion journal is created atomically and every discard of a journal syncs `events/` first; a mismatched event is quarantined as
  `unpublished-*` rather than published; oversized provider results (over 64 MiB) are recorded as explicit failed completions; turn-scoped
  status writers (terminal delivery failure, cross-session delivery uncertainty, initial-prompt failure) are compare-and-set on the claim
  token, and the transition table is documented; a Windows owner record without process identity is repaired only when its pid is dead, and
  dead-owner repair is exercised through `tell`, `sessions`, and the internal result wait; session creation syncs the state root and every newly
  created ancestor and keeps a `state-root.durable` receipt so ancestry durability does not depend on which creator made the directories;
  `result` and `inspect` stay read-only and `sessions` remains the repair entry point.

## Compatibility and requirements

- Provider delivery transports, completion identities, permission behavior, and explicit close semantics are unchanged for Codex, Claude, and Pi; the Agy Windows paste path and the Agy macOS follow-up paste path gain the readiness gate and receipt described above, so the first macOS `tell` to a fresh Agy session can now wait up to 60 s plus the quiet period before it pastes instead of pasting at once.
- Existing session, event, and receipt records remain readable; `context_sources`, `resumed_from`, `provider-process.json`, `reopen.marker.json`, `reopen.refusal.json`, `state-root.durable`, and `unpublished-*` files are new and optional.
- `search`, `--context-result`, and the reopen gates reuse the read-only snapshot machinery of `inspect`/`result`.
- Rust 1.97.1 or newer is required to install from source. Native Windows managed consoles require PowerShell 7. Provider CLIs must already be installed, authenticated, and initialized.
- Minimum provider versions remain Codex 0.147.0, Claude Code 2.1.234, Agy 1.1.12, and Pi 0.84.1.
- macOS iTerm2/Terminal.app and native Windows retain their existing support boundaries. Ghostty stays fail-closed. Linux visible-terminal transport is not part of this release and is planned for a later version.

## Verification boundary

- Every feature and fix in this release was implemented on its own branch, reviewed by Codex through Agent Bridge, and revised until the review found no blocking finding, before integration into the release branch; the integrated branch passed the full test suite, Clippy with warnings denied, formatting, whitespace checks, and a Linux cross-compile check of the tests on Windows.
- Native Windows authenticated checks on 2026-09-24 (Windows 11, PowerShell 7.5.4, Codex 0.156.1, Claude Code 2.1.281, Agy 1.2.10, Pi 0.84.4): the four provider live smokes passed on `windows-console`, including Codex invoked from cmd.exe and Windows PowerShell 5.1; the Claude smoke failed before the marker fix when run from inside Claude Code and passed after it; `search` ran against the real state root and its hit addresses were re-read with `result`; a Codex `ask --context-result` attached a Claude result and returned it with `context_sources` recorded; closed Claude sessions were reopened four times and recalled earlier context, a follow-up `tell` to a reopened session succeeded, and a second reopen of the same source was refused; after the Agy gate landed, every Agy launch delivered its paste and the one lost paste observed during development was reported as delivery-uncertain within 25 seconds instead of hanging until the timeout; Claude, Agy, and Codex asks and a search succeeded on the integrated build.
- macOS authenticated checks on 2026-09-24 (macOS 26.6.2, iTerm2 3.7.3, Codex 0.156.1, Claude Code 2.1.281, Agy 1.2.10, Pi 0.87.1, Rust 1.98.1), invoked from inside a Claude Code session that exported `CLAUDE_CODE_CHILD_SESSION=1`: the Claude, Codex, and Pi live smokes (ask, detached `tell`, `tell`, explicit close, repeated close) passed on `iterm2`; the managed `claude` registered under its Agent Bridge name as an independent top-level session and the messenger reached it, which is the macOS path of the marker fix; `reopen` of the closed Claude session was refused with gate `provider-unsupported` and left every byte of the source session unchanged; `search` found the smoke results and its hit addresses were re-read with `result`; `doctor` reported `claude_caller_markers_removed_at_launch`; an explicit `--terminal ghostty` failed closed before any surface existed. The Agy smoke failed before the macOS follow-up gate landed (the `tell` pasted 10.3 s after startup was cleared by the deferred reload at 11.2 s and reported as delivered); after it landed, a session whose reload arrived at 55.4 s reported the lost paste as delivery-uncertain within the receipt window, and with the 60 s window three consecutive follow-ups to one session were delivered with receipts (the first after the window, the next two in 8 s each). `native::tests::macos_terminal_applescripts_compile_without_opening_a_tab` needs Ghostty installed and was skipped on the verification Mac; CI runs it with Ghostty and iTerm2 installed.
- Codex 0.156.1 on macOS asks to trust the workspace folder on first launch in a folder that only inherits trust from a parent entry, which holds the initial prompt until the user answers; the smoke was answered once and the trust decision was saved by Codex. Workspace trust unification (issue #28) is still a proposal.
- Terminal.app was not exercised on this Mac; its adapter is unchanged in this release.
- Codex 0.156.1 on native Windows exposes daemon subcommands whose control socket connection fails; Agent Bridge treats the daemon as unavailable and keeps the console follow-up path.
- Power-loss durability is not proven by any test; the sync order is proven with a test-only sync log.

Workspace trust unification across providers (issue #28) remains a design proposal; Linux support is planned for a later version.
