# Agent Bridge 0.1.2

0.1.2 is a maintenance release. It reorganises the session and terminal code
and changes nothing that a user or a script can observe: commands, output,
the records in a session directory, provider transports, and every close and
repair decision are those of 0.1.1. There is nothing to migrate.

## Session records behind one seam (#73)

- Session records are read through `session::Reader` and changed through
  `session::Store`. Queries (`inspect`, `inspect --timeline`, `result`,
  `search`, `doctor`, the read-only `sessions` form) hold only a Reader, so
  the rule that a query observes and never repairs or writes is enforced by
  the type they are given.
- The turn lifecycle (claim, receipt, completion journal, publication,
  recovery) lives in `session::turn`; explicit close, interrupted-close
  convergence and dead-owner repair live in `session::close`. Provider and
  terminal adapters keep the names and schemas of their private records.
- The session state is a typed `SessionState`; its serialized strings are
  unchanged.
- `CONTEXT.md` defines the terms the code and its documents share.

## Surface ownership behind the terminal seam (#74)

- The owner record types, macOS process identity, the Terminal.app
  app-incarnation checks, the Warp close preparation, surface-ownership
  verification, close authority and the close execution move from the
  orchestration module into the terminal module (`terminal::ownership` and the
  adapters). Terminal adapters no longer call back into the orchestration
  module for them, and the session module reaches them only through functions
  that name no terminal kind.
- The moved functions keep their bodies, error texts, check order and
  platform gates. The orchestration module now decides from a terminal kind
  only when it parses `--terminal`, prints the iTerm2 session id, frames
  terminal input, and dispatches the Windows console control command.
- `CONTEXT.md` gains Attestation, App incarnation and Close authority.

Provider adapters are unchanged by #74. #73 changed how they report a
completed turn (through `turn::Report`) without changing what they report.

## Verification and remaining limits

- macOS tests passed: 698 tests, no failures, 6 ignored. Clippy passed for
  the host, `x86_64-unknown-linux-gnu` and `x86_64-pc-windows-msvc`;
  formatting and diff checks passed. Ignored tests are not runtime evidence.
- Linux and native Windows were not run locally. Their tests ran in CI on the
  pull requests and on `main`: for #74, Linux passed 509 tests (1 ignored) and
  native Windows 558 (5 ignored), with no failures. The Release workflow runs
  macOS and Windows again for the tagged commit.
- Authenticated macOS round trips with the 0.1.2 candidate passed through the
  public `self-test` command (ask, result, `tell`, result, owned-session
  cleanup): Codex 0.160.1 in WezTerm, Terminal.app, iTerm2 and Ghostty, and
  Claude Code 2.1.291 in WezTerm.
- A session that 0.1.1 launched was inspected, continued with `tell` and
  closed by the 0.1.2 candidate (Codex, WezTerm).
- An earlier candidate's first attempt in Terminal.app, iTerm2 and Ghostty
  timed out while the surface was being created, before any ownership code
  runs. The installed 0.1.1 timed out the same way in Terminal.app, which did
  not answer Apple Events at that moment; each terminal passed on the next
  attempt. The cause was not established.
- Not exercised: Warp, Agy, Pi, native Windows and Linux runtime behaviour, a
  close after the owner died, and the Terminal.app paths for a restarted or
  second Terminal process. Those paths are covered by unit tests only.
- The limits recorded for 0.1.1 (Codex queue timing, #57, #65) are unchanged.

Sessions, hashes and the first-attempt failures are in the
[macOS verification record](../verification/2026-10-06-macos-0.1.2.md).
