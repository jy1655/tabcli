# Agent Bridge 0.0.3

Agent Bridge 0.0.3 adds native Windows release support while preserving visible, provider-owned CLI sessions on macOS.

## Highlights

- Publishes Apple Silicon macOS and 64-bit Windows archives with `LICENSE` and a SHA-256 checksum.
- Implements the same `ask`, `tell`, `sessions`, and explicit close contract from `cmd.exe`, Windows PowerShell 5.1, and PowerShell 7. The exact MSVC candidate is live-verified for Codex; authenticated Windows runtime verification remains outstanding for Claude, Agy, and Pi.
- Preserves the exact canonical Windows workspace as Codex's inherited current directory and omits the redundant Windows `-C` override, avoiding both Codex's `os error 161` rejection of Rust-canonicalized `\\?\` paths and semantic changes from stripping the verbatim prefix.
- Uses Claude Code 2.1.234+'s official cross-session `ListAgents`/`SendMessage` transport on both macOS and native Windows; the former Windows `--print --resume` supervisor is removed.
- Correlates Codex turns with the claim marker in official notify `input-messages`, preserving exact-output response bodies. Pi's session extension verifies the current claim marker in the actual `before_agent_start` prompt and submits that correlation with the settled result, so Pi also preserves exact-output bodies; Agy retains claim-token/final-marker correlation. Delayed or unrelated results cannot satisfy a later request.
- Recovers partially committed completions through a durable journal, enforces monotonic status generations, and serializes completion, process exit, and explicit close under the turn lifecycle lock.
- Persists a Windows console's identity-bound handle before resuming its suspended process, retains a freshly verified console-owner process handle across `AttachConsole` and input or close control, atomically records dead-owner close reasons, and verifies macOS PID birth identity, TTY, foreground process group, login shell, and exact terminal surface before terminal input.
- Sends Windows console prompts as plain Unicode key events instead of exposing nested bracketed-paste delimiters, then queues Codex's provider-owned paste-confirmation and submission Returns as two separately delayed batches.
- Keeps Windows Claude initial prompts out of process arguments and sends them through Claude Code 2.1.234+'s official named-pipe cross-session transport after launch.
- Contains each Claude messenger process tree in a Unix process group or, on Windows, creates it suspended, assigns it to a kill-on-close Job Object, and only then resumes it; kills descendants on timeout and retries only output-proven pre-`SendMessage` discovery misses within a five-second window that begins at the first proven miss and remains inside the total request timeout.
- Encodes multiline Agy and Pi Windows prompts as one physical console line containing a JSON string, preserving newlines and tabs without turning them into raw console submission keys.
- Waits through Codex's cold-start MCP and extension redraw window before delivering the initial Windows prompt so its confirmation and submission Returns are not discarded while the composer initializes.
- Distinguishes a missing Windows console from an `AttachConsole` access failure so an unsuccessful cross-session close retains the live session state and identity-bound terminal handle for a valid retry.
- Fails closed before AppleScript for an explicit Ghostty selection and routes auto-detected Ghostty environments to Terminal.app: Ghostty 1.3.1 has an AppleScript terminal-surface regression and 1.3.0 lacks current positive runtime evidence. iTerm2 and Terminal.app remain the supported v0.0.3 alternatives.
- Applies `ask --timeout-secs` to terminal startup, initial-input readiness, provider delivery, and result waiting as one total budget, and propagates one absolute deadline through terminal automation, the Windows console helper, and Claude cross-session delivery instead of restarting a remaining-duration timer after state persistence, helper startup, or provider setup.
- Releases a turn claim when terminal delivery proves that no input was written, including macOS deadline, prompt-path, and AppleScript pre-spawn failures, while retaining the claim after terminal automation starts and a timeout or transport failure leaves delivery uncertain.
- Runs mutable Homebrew terminal-app installation only in a non-publishing release test job; artifact-producing jobs build and package in separate clean runners.
- Normalizes CRLF prompt files to LF while continuing to reject bare CR and terminal action controls.
- Refuses release publication unless the repository's immutable-releases setting is enabled and the `IMMUTABLE_RELEASES_READ_TOKEN` Actions secret can verify it with repository `Administration: read` permission.
- Rejects inline and file-backed prompt control characters that could create a separate terminal action.

## Requirements

- Rust 1.97.1 or newer when installing from source.
- PowerShell 7 for native Windows managed consoles, regardless of the caller shell.
- Provider CLIs installed, authenticated, and initialized before Agent Bridge launches them.

Minimum provider versions are Codex 0.147.0, Claude Code 2.1.234, Agy 1.1.12, and Pi 0.84.1.

## Verification boundary

- Ordinary CI runs format, clippy, unit/policy tests, archive construction, checksum verification, archive extraction, and packaged-binary version checks on macOS arm64 and Windows x86-64 targets.
- Authenticated visible-terminal evidence is recorded separately with the release-prep commit, provider versions, caller shells, terminal adapters, and managed session IDs. CI or an ignored-test count is not treated as a substitute for those live runs.
- Release publication requires the repository immutable-releases setting, an `IMMUTABLE_RELEASES_READ_TOKEN` fine-grained token with repository `Administration: read`, and an annotated `v0.0.3` tag whose commit is contained in `main`; the tag version, Cargo version, curated notes file, packaged binary version, archive manifest, and checksum must all agree.

## Known boundaries

- Linux visible-terminal transport is not implemented.
- Agent Bridge controls only terminal surfaces that it creates and does not attach to arbitrary existing CLI processes.
- Workspace or project trust remains provider-owned. Cross-provider trust sharing is tracked separately and does not imply `--yolo`, tool, credential, or general permission approval.
- Claude cross-session messaging still depends on Claude's backend, feature flag, and settings availability gates. Agent Bridge fails closed instead of falling back to terminal injection when those gates are unavailable.
- [Ghostty 1.3.1 cannot initialize AppleScript-created terminal surfaces](https://github.com/ghostty-org/ghostty/issues/12730), and this candidate has no current positive 1.3.0 runtime evidence. Agent Bridge v0.0.3 therefore rejects every Ghostty version; use iTerm2 or Terminal.app until a release is independently verified.
- The release archives change from the historical `agent-bridge-v0.0.2-*` prefix to `agent-bridge-0.0.3-*`; update download patterns accordingly.
