# Terminal Agent Bridge 0.4.13

0.4.13 closes the seventh architecture review (2026-10-16, eleven deepening candidates, #221 to
#231). Each candidate turned a shallow module into a deep one behind a small interface; the
commands, records and outputs are unchanged except for the three groups of observable changes
listed first below. Records written by 0.4.x are read as before unless they are malformed in
one of the ways the decoder now refuses.

## Observable changes

- Observation judgments (#221). Every session judgment (owner binding and liveness, the turn,
  Claim without Receipt, recovery, the request index, the residual surface, Hold, Cancel, the
  surface record and its presence, the unreadable parts, the next `result` address) is decided
  once in the Observation; `status`, `doctor`, `inspect` and `wait` map it to their own
  vocabulary and derive none of their own. `CONTEXT.md` names the *Judgment*. Three outputs
  change, documented in [docs/cli.md](../cli.md): `inspect` no longer attests an owner record
  that belongs to another managed session (`owner.error` is
  `owner record belongs to another session`, the owner fields are null,
  `owner_identity_verified` is false); `wait` and `result --wait` end for a gone owner only when a
  bound owner's process exited or its process id now belongs to another process, or an unbound
  legacy owner's process id is gone, while a changed TTY or process group, an attestation that
  could not decide, and another session's record keep the wait going; a bound owner whose
  attestation could not decide is `owner_unverified` in `status` and `doctor`, never
  `owner_exited`, even when its process id looked absent.
- One decoder per core Record (#223), documented in
  [docs/security-and-data.md](../security-and-data.md). `manifest.json`, `status.json`,
  `closed.json`, `turn.completion.json`, `launch.json` and the receipts are decoded by one
  decoder each in every command. The bytes are strict UTF-8: a record with invalid UTF-8 is
  unreadable rather than read with replacement characters. A `*_unix_ms` value above the JSON
  unsigned integer range, anywhere in the record, makes it unreadable. `status.json` and
  `closed.json` are read as regular files only, as the other records already were: a symbolic
  link or a non-file at either path is refused with `refusing non-regular session file`.
- Provider homes (#227). An empty `CLAUDE_CONFIG_DIR` is unset for the Claude trust store, as it
  always was for the session registry; through 0.4.12 the trust store read it as the relative
  `.claude.json`.

## Structure, no behaviour change

- Close authority is decided over one observation seam (#222): `terminal/close_authority.rs`
  with a production and an in-memory adapter and one presence-only close evidence.
- The launch protocol is two operations in `session::launch` (#224): the launcher starts a
  created session in a surface; the wrapper runs admission and provision.
- Each provider adapter produces its complete launch command and its completion watcher (#225);
  the shared layer assembles no provider flag.
- `ask`, `tell` and `reopen` run one Turn from Claim to Result (#226, `turn_run.rs`).
- Each provider adapter owns its home and answers workspace trust from it; consent snapshots
  the environment once and owns the one trust wait that the Codex and Agy gates share (#227).
- Each terminal kind is registered once in its portable `facts.rs`, and the installed macOS
  dispatch is a value built from each adapter's injectable dependency, so a shared-path test
  builds one with a recording automation or a fake runner; the AppleScript runner has no test
  branch (#228).
- Each native command parses and runs in its own module; `args.rs` holds the argument helpers;
  every module imports its names from their owners; the tests of terminal internals live beside
  the terminal modules (#229).
- Claude's cross-session messenger is its own module, built per send from a clock and a retry
  policy (#230); the four Claude delivery rules of `AGENTS.md` map to one file.
- One clock seam (`clock.rs`); Origin observation is told its process attester and its clock;
  the launch binding wait, the close scope and the Codex queue read an injected clock; the
  deterministic race hooks stay as the declared test adapter at the record seam, and an I/O
  context on `Store` and `Reader` was declined and recorded in [docs/testing.md](../testing.md)
  (#231).

## Verification

See the [macOS verification record](../verification/2026-10-17-macos-0.4.13.md). Windows-only
tests ran on the Windows CI runner of each pull request; no Windows live session was run for this
release.

Closing the reported sessions behind an explicit flag (#219), the self-test's inference of
delivery certainty from error wording (#204), Pi-owned records for the extension's claim and
cancel reads (#196), workspace consent for a reopened Claude session on native Windows (#202),
Warp (#63, #87), the Windows console large paste (#124) and notify payload limit (#127), the
Windows Terminal cold-start observation of #111, #147, #148, #149, the child-to-parent question
channel (#189) and Linux transport (#6) remain outside this release.
