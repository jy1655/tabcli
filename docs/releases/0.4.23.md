# Terminal Agent Bridge 0.4.23

0.4.23 adds `--context-mode compact`, a bounded Context attachment for `ask` and `tell`
(#273), and carries three behaviour-preserving module moves from the 2026-10-22 architecture
review: the Request observation and search out of `query.rs` (#271), the diagnostic
vocabulary out of the `doctor` command (#274), and consent split by concern with one
`DialogSurface` seam (#275).

## Changes

- Compact Context attachment (#273). `--context-result SESSION/REQUEST` attached a recorded
  Result whole, up to eight results and 256 KiB in total, failing rather than truncating.
  `--context-mode full|compact` (default `full`, output unchanged) adds a Compact attachment:
  a message of at most 5,120 Unicode scalar characters is attached whole; a longer one keeps
  its first 4,096 and last 1,024 characters around a declared elision line that names the
  omitted count and the exact `tabcli result SESSION --request REQUEST` command (`--event
  EVENT` for a legacy source). The block carries a `Compact:` line with attached, total and
  omitted counts, `State: completed`, and `Questions: N emitted` when the source request has
  retained question emissions. The whole message is still validated for control characters
  and delimiter lines, so omitted text cannot bypass those validation checks; the rendered
  excerpt counts toward the 256 KiB budget, which lets eight long results be attached.
  `--context-mode` without `--context-result`, repeated, empty or unknown values are rejected
  before any session is read; `reopen` has no such option.
- Receipt context sources record `mode`, `attached_chars` and `omitted_chars` (#273). The
  three fields are optional: receipts written before this release decode without them and
  render without the keys, and an older binary ignores them. `result --json`, `inspect
  --json` and the timeline show them wherever `context_sources` is shown. The budget
  constants are first values under observation, not options; `CONTEXT.md` defines **Context
  attachment** and **Compact attachment**.
- Request observation and search modules (#271). `query/request.rs` owns the Request
  observation and `query/search.rs` owns search with its budgets; `wait` applies its owner
  rule through `RequestObservation::with_owner` instead of writing the observation's fields.
  No output, field order, error string, budget or retry window changed.
- Diagnostic vocabulary (#274). `Check`, `Availability`, `Context`, `ResultTimeoutDiagnostic`
  and `result_timeout_detail` live in `src/native/diagnostics.rs`; provider adapters, the
  Reopen marker observation and the self-test depend on that vocabulary rather than on the
  `doctor` command. `probe` stays in `doctor`: it owns a process tree, which the generic
  bounded runner does not.
- Consent modules (#275). `consent.rs` is a module root re-exporting the same names over
  `consent/store.rs` (the trust-store reader adapters use, including the Windows owner and
  access-list check), `consent/record.rs` (Bridge's consent Record and the `consent`
  command), `consent/launch_dialog.rs` (the launch dialog, now behind one `DialogSurface`
  seam with a production adapter and a scripted test adapter) and `consent/wait.rs` (the one
  trust wait). Loop order, sleep bounds and error mapping are unchanged.

## Verification and limits

Each PR passed the serial suite (`cargo test --all-targets --all-features -- --test-threads=1`:
1,399 passed, 0 failed, 6 ignored at #273 and after), host Clippy with `-D warnings`, fmt and
diff check, and every main-push CI job including the Windows runner. Each change was reviewed
read-only before merge (Codex gpt-6-astra xhigh; #271 and #273 also by Claude xhigh), all
"mergeable as is". The compact attachment was exercised once live on macOS with the dev build:
a 16,568-character Codex Result attached in `full` (16,568 characters, answer correct) and
`compact` (5,120 attached, 11,448 omitted); the Claude child recognised the elision, followed
the smoke prompt's conditional instruction to retrieve the full Result, and gave the same
substantive answer. The installing machine's self-test is
recorded separately.

Not verified: native Windows runtime for any of these changes (the Windows CI job ran the
`cfg(windows)` tests, including the consent launch tests, but no live Windows console or
dialog was exercised); the 10-delegation comparison of full versus compact attachments, which
is collected from real delegations after this release.
