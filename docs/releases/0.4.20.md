# Terminal Agent Bridge 0.4.20

0.4.20 requires Pi-owned input receipts before native Windows delivery reports Sent and
exposes historical Codex question emissions through ordinary read-only queries.

## Changes

- Pi Windows input acknowledgement (#254, #261). Bridge makes one console attempt with the
  exact framed prompt. Sent requires a matching receipt from the installed Pi extension
  within the request's original deadline. Without that evidence, a possible write remains
  Uncertain and keeps the claim. Bridge never retries text or Return. The session must
  advertise the extension's input acknowledgement capability at startup. An older session
  without that capability refuses input before a console write and requires a fresh session.
- Codex question emissions (#189, #262). Ordinary `result` shows structured titles and options
  for the selected historical Request, `status` reports `question_emitted` for its focused
  Request, and `inspect` reports per-request presence. Evidence comes only from completed
  async question items in an accepted turn bound through injected Codex lifecycle hooks.
  Emissions remain available after completion, a follow-up, and close. They do not identify
  questions as pending, answered, or withdrawn. A later `tell` creates another Request.
  This release adds no answer endpoint or parent wake mechanism. Wait, list, timeline,
  attachments, and completion records keep their existing contracts.

The Windows Claude reopen and workspace-consent fixes from 0.4.19 remain inherited.

## Verification and limits

The [Windows feature verification record](../verification/2026-10-19-windows-0.4.20-features.md)
separates independent actual parent/head runtime from component tests and CI.
With Pi 1.3.0, the parent reported false Sent when a diagnostic hook removed Return.
The head reported Uncertain at the original deadline. Controls, immediate follow-up, large
Unicode input, close during the wait, and refusal of an older extension also passed.
The large Rust-written fingerprints were 48,400 UTF-8 bytes. All nine fixtures closed.
The controlled loss demonstrates reporting behavior, not a natural loss rate.

With Codex 0.163.0, independent verification observed actual options and free-text questions
in two public mid-turn snapshots. The provider's item-to-terminal gap was approximately
24.6 seconds. The first public snapshot followed the item timestamp by 25 ms, with limited
clock resolution. Ordinary completion, a Ready follow-up, historical retention,
and status focus also passed. Both fixtures closed. The controlled 18-second barrier establishes
mid-turn visibility, not a latency guarantee.

These are feature-head Windows runs, not verification of published 0.4.20 assets.
Local linked-record coverage used a junction after file-symlink creation failed with error
1314. Actual file-symlink coverage is not claimed. macOS and Linux CI do not establish
authenticated feature runtime. Other-provider questions, answer routing, parent wake,
whole-request Claude native completion (#249), further provider usage (#55), cold Windows
Terminal, and non-Windows consent remain outside this release's new verification.
