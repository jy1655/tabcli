# Terminal Agent Bridge 0.4.18

0.4.18 replaces the timed Windows console paste of a Codex initial prompt with an evidence-based
protocol for launches recorded as `injected` (Codex 0.163.0 or newer with lifecycle hooks on),
which closes the stranded-draft defect of #124 (#255). Launches without an injected hook record
keep the previous route unchanged, now named the legacy console route. No record schema changed:
the private payload of the console helper's dialog and send actions gained two optional fields
(`expected_claim`, `expires_unix_ms`) that only the injected route sets, and the helper's text-only
send prints one JSON line that only that route reads. Records written by 0.4.x are read as before.

## Changes

- Codex Windows initial paste for injected launches (#124, #255). Codex groups fast key events
  into a paste burst, treats Enter inside the burst as a newline and collapses a paste above 1,000
  scalars into a `[Pasted Content N chars]` placeholder, so a fixed delay before the submission
  Return could never be right. Bridge now writes the framed body text-only, waits for the console
  input buffer to drain and checks the scalar count; after a 150 ms gap it writes a line feed and
  the request's claim marker the same way; then it reads the composer until its last inline segment
  is that marker line (the final input, rendered, proves ordered processing of everything before
  it) or, when the tail merged into the placeholder, until the placeholder and inline scalars add
  up to Codex's own normalized count of the framed prompt; it rechecks the claim, the session and
  the deadline and writes exactly one Return, only if the whole screen is unchanged and only if the
  claim is still current under the lifecycle lock at the instant of the write; `Sent` means this
  claim's `UserPromptSubmit` binding was observed. Every failure after the body was written is
  delivery-uncertain with a final composer classification and a conditional recovery hint, and
  nothing is ever resent. A trust dialog or hook-review picker is recognized by its own rows: any
  prompt glyph outside the addressed draft, any pinned option label and any confirmation hint
  (fragments, chords, the Codex key labels, wrapped rows) is unresolved UI and blocks the Return.
  Accepted, documented refusals: a draft line that is itself a numbered pinned menu label, a
  hint-like line or a bare action word is refused as unresolved UI; the recognizer is pinned to
  Codex 0.163.0 at the 120-column managed surfaces, the upstream 40-column snapshot and the
  43 to 47 column sandbox wrap. Documented in [docs/providers.md](../providers.md) and
  [docs/terminals.md](../terminals.md); the boundary is in AGENTS.md.
- Console helper primitives (#124, #255). The `send` action takes an explicit submission count;
  zero writes text only, drains and reports `{"schema":1,"written_chars":N}`. The dialog action and
  the text-only send check an optional expected claim and absolute expiry under the lifecycle lock
  immediately around the write, so a claim retired or replaced after the caller's check writes
  nothing. The attached dispatch is one production function that the seam test executes with a
  lock contender. Agy, Pi, the consent dialog and the legacy Codex route pass no guard and are
  unchanged in payloads, arguments and record sequences.
- Fixtures. Six real console captures of the first live matrix (which failed on every prompt
  because the parser had guessed the footer from source), the real hook-review picker and the two
  review counterexample frames are test fixtures, protected from line-ending conversion by
  `.gitattributes`.

## Why

The 0.4.4 hotfix for #124 waited for the console input buffer and a fixed 2 s before each Return
and then looked for the empty composer. Draining the buffer only proves that Codex's reader took
the events, not that the composer processed them, and the empty row proves a transition, not that
this request was accepted. The redesign was criticized twice before implementation and reviewed
nine times during it; each review found another torn-frame shape until the owner fixed the
stopping rule: refusals in the safe direction plus a documented rendering boundary.

## Verification

See the [Windows live record](../verification/2026-10-18-windows-124-paste-evidence.md) of
2026-10-18 (codex-cli 0.163.0): the second matrix (short, framed body 999, 1000 and 1001,
a multilingual multi-line prompt, 25 KB) completed with the rollout's user text byte-identical to
the framed prompt; the console-window fallback and the settings-off legacy route completed; an
untrusted hook's picker received no input; Agy's self-test passed; prompts quoting the dialog
words and a 24-line numbered list completed on every later build. Pi's self-test failed for an
environment reason (Pi 1.3.0 on Node 22.14 raises `zlib.createZstdDecompress is not a function`
at startup, with the installed 0.4.17 as well). Each round's serial gate and the pull request's six
CI jobs passed; the one CI failure was the runner's line-ending conversion of the new fixtures,
fixed by `.gitattributes`. Not verified: a screen that changes between the accepted read and the
guarded Return, a forced torn frame, narrow or resized viewports, macOS (no console paste path).

Pi's missing per-turn acknowledgement (#254), the Claude adapter's first-Stop settlement (#249),
the reopen launcher failure (#248), Pi-owned extension records (#196), provider usage (#55), the
child-to-parent question (#189), Ghostty (#104), Warp (#63, #87), trust consolidation evidence
(#28), Linux (#6) and the reopen pre-launch window (#245) remain outside this release.
