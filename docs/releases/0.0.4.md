# Agent Bridge 0.0.4

Agent Bridge 0.0.4 adds provider-native Codex queue follow-ups while preserving the existing visible-session and provider-owned lifecycle contracts.

## Highlights

- Uses `codex queue --thread <UUID> --message <TEXT>` for Codex 0.149+ follow-ups when the managed session has an authoritative thread UUID and a compatible local app-server daemon is running.
- Keeps Codex 0.147.x and 0.148.x supported through the existing provider-owned terminal follow-up, and falls back only when native queue delivery is known not to have started or the server explicitly rejects the message before enqueue.
- Treats an accepted queue item or an uncertain post-start result as potentially delivered, retains the turn claim, and never resends the same turn through the terminal.
- Completes a queued turn only when the official Codex notify payload proves both the established thread UUID and the current claim marker; delayed, foreign-thread, duplicate, and marker-mismatched notifications cannot complete a later request.
- Runs daemon probes and queue commands inside the original workspace and total `tell` deadline, contains their descendants in a Unix process group or Windows Job Object, and caps retained stdout and stderr to one combined MiB.
- Keeps every other provider adapter unchanged: Claude continues to use official `ListAgents`/`SendMessage`, while Agy and Pi retain their provider-specific terminal follow-ups and result correlation.

## Requirements

- Rust 1.97.1 or newer when installing from source.
- PowerShell 7 for native Windows managed consoles, regardless of the caller shell.
- Provider CLIs installed, authenticated, and initialized before Agent Bridge launches them.

Minimum provider versions remain Codex 0.147.0, Claude Code 2.1.234, Agy 1.1.12, and Pi 0.84.1. Codex native queue selection additionally requires both Codex CLI and the running local app-server to be 0.149.0 or newer.

## Verification boundary

- The final release candidate passes 178 unit tests and 14 policy tests, host and Windows GNU cross-target Clippy with warnings denied, formatting, release build, and diff checks. The four ignored authenticated tests remain manual by design.
- An authenticated macOS Codex 0.153.2+iTerm2 run proved `ask -> native queue tell -> correlated notify -> ready -> explicit close`; the target queue changed from empty to one accepted item and back to empty after consumption, with exact responses on one thread and distinct provider turn IDs.
- Independent Codex Dev Blue and Claude reviews reported no remaining findings on the final implementation diff. Their verdict retained runtime boundaries rather than treating static or reviewer evidence as LIVE proof.
- Native Windows queue and Job Object runtime are `NOT-VERIFIED`; Windows GNU cross-target Clippy is static portability evidence only. Codex 0.153.2 on native Windows has no local daemon lifecycle, so that environment continues to use the Windows console follow-up.
- Release publication requires the repository immutable-releases setting, an `IMMUTABLE_RELEASES_READ_TOKEN` with repository `Administration: read`, and an annotated `v0.0.4` tag whose commit is contained in `main`. The tag, Cargo version, release notes, packaged binary version, archive manifest, and checksum must agree.

## Known boundaries

- Agent Bridge does not start, stop, update, or remotely select the Codex app-server daemon. The operator owns that lifecycle.
- A successfully accepted Codex queue item is durable upstream state. `close-session --explicit` closes the managed terminal surface but cannot cancel that item; resuming the same Codex thread later may execute it.
- Linux visible-terminal transport is not implemented.
- Agent Bridge controls only terminal surfaces that it creates and does not attach to arbitrary existing CLI processes.
- Ghostty remains fail-closed because the available 1.3.1 build cannot initialize an AppleScript-created terminal surface and 1.3.0 lacks current positive runtime evidence; use iTerm2 or Terminal.app on macOS.
