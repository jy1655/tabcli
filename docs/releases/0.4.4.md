# Terminal Agent Bridge 0.4.4

0.4.4 fixes one Windows delivery defect and moves two pieces of shared orchestration behind the
seams that own them. On native Windows a large pasted prompt no longer stays unsubmitted in the
Codex composer while Bridge believes it was sent. Delivery of a Turn is one module that every
command crosses, and the consistent read of a session's records is the Reader's own. Records written
by 0.4.x are read as before.

## Changes

- Windows console paste (#124, temporary measure): each delayed submission Return waits until the
  console input buffer has been consumed before its 2 s delay, and the Codex adapter settles a
  Windows initial paste as sent only after it has seen the empty composer row again; otherwise the
  delivery is uncertain, the claim is kept and nothing is resent. A 21,000-character prompt that
  stayed in the composer as `[Pasted Content …]` with the session `working` was the observed failure;
  a 26.8 KB prompt completes after the change. The issue stays open for a redesign.
- Delivery of a Turn has one seam. `delivery` owns readiness and the reopen gates of the initial
  turn, prompt-file framing, surface ownership and send-budget checks, `begin_delivery`, the
  transport's send and the settlement, for `ask`, `tell` and `reopen` alike. Each provider adapter
  declares its initial and follow-up Transport; the eleven transport methods of the provider
  contract, both transport enums and `CrossSessionMessageFailure` are gone. Error strings and record
  writes are unchanged; on the follow-up paste path the remaining-timeout and budget checks now run
  before `begin_delivery`, so those two refusals write no intermediate `working` status.
- The consistent read of a session (`Snapshot`) moved behind the session seam as
  `Reader::snapshot()`. Timeline, search and the active-Request rule share it; reopen keeps its own
  strict read and gates. Every JSON output is unchanged.
- Issues recorded, not fixed: the Windows console paste drops every line feed (#126), and a Codex
  `notify` payload above the Windows command-line limit never reaches Bridge (#127).
