# Terminal Agent Bridge 0.4.31

0.4.31 closes three cards of the 2026-10-29 architecture review: one reader for Pi's
startup-readiness record, one owner for the Codex framed-prompt grammar, and one
start-command shell shared by `ask`, `reopen` and `tell`. Public JSON, text output,
error messages, help text, record schemas and the installed extensions are unchanged,
except for the stricter Pi readiness checks described below and the diagnostics those
checks produce for an invalid or unreadable readiness record.

## Pi startup readiness (#319)

`pi-startup-ready.json` is now read by one adapter module with one 4 KiB bound and one
validity floor: schema 1 or 2, a valid claim-token format, and a valid Pi session id
(non-blank, at most 256 bytes, no control characters). Each question keeps its schema
set: startup resolved on schema 1 or 2, `cancel` on schema 2, Windows input
acknowledgement on schema 2 with `input_ack_schema: 1`; the carry-forward to a later
Claim rewrites only schema 2 and never upgrades a legacy extension.

Two behaviours change. A record over 4 KiB now leaves `cancel` unsupported; it was
previously read without a bound. A record whose session id fails the rule is unreadable
for every reader; three readers previously accepted any non-blank id. A legacy schema 1
record is refused before the Claim is read, as before. An invalid or unreadable record now
reports the reader's reason (for example `Pi startup receipt schema 3 is unsupported`
inside the existing refusal context) where some readers previously reported
`Pi startup receipt does not identify this initial turn` or a bare decode error; the
refusal classification is unchanged. The extension and the input receipt protocol are
unchanged, so by source inspection a Pi session opened by 0.4.30 keeps its follow-up and
`cancel` capability under this binary; a live upgrade of an open 0.4.30 session, including
`cancel`, was not exercised. See [providers](../providers.md#pi).

## Codex framed-prompt grammar (#318)

`codex/correlation.rs` now owns the marker, the frame, the one recogniser (delegation
header, directly or behind the exact IDE wrapper, plus the trailing marker) and the
Windows paste splitter. The binding hook, the transcript acceptance and the initial
paste call it instead of repeating the predicate or rebuilding the marker literal. The
frame text, the marker text and the IDE wrapper constants are byte-identical; the `#61`
title-turn and `#65` steered-input fixtures are unchanged.

## Start-command shell (#320)

`ask` and `reopen` resolve their launchable spec through one step, in the order each
command used before: the canonical workspace, launch admission, the provider executable
and version, the title and the workspace consent assessment (`ask` on the requested path,
aliases included; `reopen` on the canonical source workspace). The four option checks
live once in the argument helpers, `tell` parses through the shared option parser and
still rejects the session-shaping options as unknown, and a command's own report fields
are rendered in every error output. Output, messages and help text are byte-identical.

## Glossary

`CONTEXT.md` gains **Startup readiness** and **Framed prompt**.

## Verification and upgrade

Automated source, fixture and CI checks are distinct from authenticated provider or
terminal runtime checks. On native Windows the candidate binary ran the self-test for
Codex, Claude, Agy and Pi and a Claude close and reopen; see
[2026-10-30 Windows 0.4.31](../verification/2026-10-30-windows-0.4.31.md). macOS
runtime was not exercised for this release; its coverage is the macOS CI job.

The existing [open-session upgrade notes](0.4.25.md#upgrade-notes) still apply. Do not
downgrade binaries used by open sessions. The release includes macOS and Windows CLI
archives and the Claude, Codex, Agy and Pi integration packages, with checksums.
Integrations contain instructions and no engine binary. Publishing these files does
not install or update a local binary or host integration.
