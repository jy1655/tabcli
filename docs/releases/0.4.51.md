# TAB 0.4.51

0.4.51 changes how a session ends when TAB cannot rely on its owner. A session whose owner is
gone or cannot be verified now settles on proof that its terminal is gone, on every terminal,
and TAB never ends a running terminal of such a session; on Windows an explicit close can end
the live owner of a Herdr terminal that is gone. A session copied from another operating
system is settled, pruned and observed from its records, without judging it from this
machine's processes. TAB prepares its state root before anything is written into it and
checks the result. Claude's and Codex's trust stores supply workspace consent under narrower
rules, and the steps of a launch before a session exists obey the request deadline. Commands
and JSON output keep their form. No stored field or file is added; one stored value changes,
the `terminal` of a consumption marker written for a handle without a kind.

Each item names its pull request, whose description has the conditions and limits in full.

## What changes for a caller

### Sessions copied from another operating system (#444, #446, #447, #449)

- **What counts as a copy.** Only records that state it: a bound active handle that states a
  terminal kind this system does not run, or a Herdr handle whose host birth is another
  system's; a completed consumption marker that states such a kind; a bound owner record that
  carries another system's process identity. A handle left claimed by an interrupted close, an
  omitted kind, a record its reader refuses, and a marker with a repeated `consumed` or
  `terminal` field say nothing.
- **Close.** `close-session --explicit` settles a copy that has exited or failed from its
  records alone, without addressing a terminal or a process of this machine. A copy whose
  records leave it running keeps a refusal: the existing "not available on this system" text
  for a copy shown by its kind, and a refusal that names the other system for a copy shown by
  its Herdr birth or its owner. A close that is not an explicit one never settles a copy.
- **Prune and Repair.** `prune-sessions` removes a closed copy without observing its owner.
  Dead-owner Repair, in `sessions`, `tell`, `wait` and before a close, does not judge a copy's
  owner from this machine's processes.
- **Observing commands.** `status` reports a copy's owner as unverified, and a pending `wait`
  gives no owner verdict. `inspect` reports the owner's liveness as unknown and predicts that
  `tell` is refused at the surface. `doctor` reports the launch configuration and the consent
  records from the records, leaves out the checks that examine this machine, and leaves
  `scope.executable` null. `screen` makes no terminal call for a copy. `tell` refuses a copy
  after the hold check and the record convergence it already runs, before the ownership proof,
  the Claim and the input. A running copy used as an origin is `owner_unverified` in
  `sessions`, `status`, `inspect` and `doctor`. After a refused `reopen`, a local process id
  that is gone does not release a copy's reservation.
- **Limit.** A Herdr handle is valid on every system, so once a copy whose only evidence was
  its handle's host birth has been closed, nothing in its records distinguishes it from a
  local session.
- **Native sessions: the close holds one lock.** An explicit close now holds the lifecycle
  lock, with its original deadline, across completion recovery, launch Repair, dead-owner
  Repair and the close, and acts on the records it acquired under that lock. Five native
  behaviors change with that (#446 lists them): the lifecycle lock file exists before
  pre-close Repair runs; a handle replaced between the acquisition and the claim is not
  dispatched, the attempt ends with an error and a retry closes the replacement; launch Repair
  inside an explicit close is never skipped because the lock was busy; marker bytes that are
  neither the acquired marker nor the marker this close wrote end the attempt and are
  preserved; a handle that cannot be decoded is reported under `terminal.json` and stays
  there.
- **Marker kind.** When a close writes `terminal.closed.json` for a handle that omits its
  kind, it records `"terminal": null`; earlier releases recorded `"iterm2"`. For such a closed
  session without a launch-host record, `doctor --probe` reports
  `shell_environment_probe_context_unavailable` instead of treating the session as iTerm2.
- **Origin read allowance.** The origin verdict reads up to 768 KiB per origin, up from
  512 KiB, because it now also reads the active handle and the completed marker. The
  per-record limits and the 100 ms deadline are unchanged.

### Launch

- **The request deadline bounds the steps before a session exists (#436).** For `ask`, `tell`
  and `reopen`, preparation now reads the command deadline before the workspace consent
  record, the state root and its durability receipt, the Session directory and the reopen
  marker, and an expired request is refused at the first of these it reaches, as a timeout
  that names the step and lists what the request had already written. A write that has
  started is completed. Inside an hc terminal the automatic Herdr caller check is bounded by
  the earlier of the request deadline and its own ten seconds. A reopen's reservation waits
  for the source's lifecycle lock only until the deadline. Two steps stay unbounded: finalizing
  or releasing a reopen marker once it is written, and making the state root private.
- **A failure to open a surface settles this launch's records, and waits for the lock
  (#445).** A failure without a retained surface now waits for the lifecycle lock within the
  launch budget, with one last attempt at the deadline, where 0.4.50 made one attempt and,
  when the lock was held, told the caller that provider startup was in progress. It writes
  only when the current Claim and the receipt's Claim are the Claim this launch started with.
  When nothing can be settled and this launch's Claim is still installed, the error says that
  nothing was recorded and that the Claim is retained. A reopen's fence of a failed child
  waits only until the request deadline; publishing the refusal still waits without it.
- **The owner record belongs to the wrapper that spawns the provider (#439).** The wrapper
  registers its owner record under the lifecycle lock, and the wrapper that passes the spawn
  fence makes the record name itself in the same locked step. Once an owner is recorded, a
  wrapper that is not that owner changes neither the status nor the Claim nor the owner
  record. For the ordinary single wrapper the records are those 0.4.50 writes, with three
  differences #439 states: a definitive failure to start the watcher or to spawn is settled
  inside the fence; a wrapper refused at admission no longer appends its own
  `wrapper_exit_code=1; launch cancelled or already attempted` line; and a launch without a
  receipt is checked at registration.
- **A launch host leaves a directory it refused untouched (#453).** On Linux and Windows a
  host that refused the session directory wrote its refusal into `launch.log` of that
  directory. No host does that now, on any OS. The caller still gets the reason from the
  launcher's own check before any terminal exists.
- **Paths must be Unicode text (#455).** A workspace, a state root or a TAB executable path
  that is not Unicode text is refused on every OS and every terminal before the Session
  exists, and the refusal names the field. Nothing is written for a refused request.
  `self-test` reports the refusal with a null `state_root` when the ordinary root cannot be
  written as text. On Windows the PowerShell 7 executable path, a `.cmd` or `.bat` provider
  path and a `.ps1` script path are converted to text exactly or refused, and `doctor`'s
  `powershell` row shows the path without the `\\?\` prefix. The PowerShell wrapper and the
  Herdr attach command double each character PowerShell reads as a single quote (U+0027,
  U+2018, U+2019, U+201A, U+201B), so a path that contains one is carried exactly. `PATH`
  entries keep their handling.
- **macOS: a launch that outlived its receipt reports `binding_timeout` (#438).** On the
  shell-capture host that Herdr, iTerm2 and WezTerm use, a launch whose receipt expired, for
  example across a system sleep, was reported as `binding_mismatch`. It now reports the
  existing `binding_timeout` reason. Linux and Windows do not use this host.

### Close and Repair

- **A Herdr session with a saved teardown intent closes by the creation-record rule (#437).**
  On macOS and Linux the replay of a saved teardown intent now validates the intent's own
  fields first, and one observation of the owner record chooses the branch. A session-bound,
  platform-consistent record with an attested live incarnation selects the close with a live
  owner. Every other owner puts the close on the creation record: it settles when the terminal
  is gone, removes a finished terminal and refuses a running one, and sends no signal to a
  process group. When the bound owner of an interrupted teardown has exited, the close no
  longer waits until the saved process group is proven gone. The other terminal kinds keep
  0.4.50's replay.
- **Repair rewrites a damaged consumption marker (#435).** When dead-owner Repair closes a
  session whose handle files are gone and whose `terminal.closed.json` cannot be decoded, it
  now rewrites the marker as an explicit close of an already closed session does:
  `{"consumed": true, "terminal": null}` with the owner-exit reason. A marker that decodes
  keeps its bytes.
- **A Windows managed console's presence is judged by its recorded root (#456).** The check
  reads the recorded root through one observation of the process and compares PID, creation
  time, and image path without regard to ASCII letter case. A confirmed exit or a different
  creation time proves that the root is gone; an invalid record, an inspection error or a
  different image at the same creation time leaves presence unverified. Only a proven
  disappearance ends a pending launch as a disappeared surface.

- **A session without a verified owner settles on proof that its terminal is gone (#459).**
  TAB never ends a running terminal of a session whose owner is gone; 0.4.50 applied that to
  Herdr, and this release applies it to the other surfaces.
  - **macOS terminal applications.** An explicit close of a session whose owner record is
    unreadable, malformed, unbound, another session's, incomplete, names a reused PID or names
    a process that cannot be judged was refused before TAB looked at the terminal, also after
    the window was gone. So was a session without an owner record outside a failed or
    launching start. The close now reads the recorded surface's presence without sending a
    close or any input: a proven absence settles the session, a terminal that is still listed
    refuses with the instruction to end it and close again, and a read that fails keeps the
    handle and returns that error.
  - **Windows managed console.** Dead-owner Repair, which runs with `sessions`, `tell`, `wait`
    and at the start of every close, no longer ends a running console of a gone owner; in an
    active state it keeps the handle for an explicit close. The explicit close settles once the
    recorded root is proven gone and refuses while it is there. When this session's owner
    record names a process that is alive or cannot be judged, the root's absence grants
    nothing. `reopen` needs a closed source, so an active session whose console outlived its
    owner is closed with `close-session --explicit` after the console is gone, where Repair
    used to end the console.
  - **Unchanged.** A live, verified owner with a present terminal; tmux, which keeps ending the
    private server TAB started for the session; a failed or launching start without an owner
    record; the replay of a saved close intent.

- **Windows: an explicit close ends the live owner of a Herdr terminal that is gone (#464).**
  On macOS and Linux an explicit close of a session whose owner is alive and whose Herdr
  terminal is gone ends the owner's foreground process group and settles the session. On
  Windows that close was refused. It now ends the two processes TAB has recorded for the
  session, the provider and then the wrapper, each through one handle on which TAB has
  verified the PID, the creation time and the image path, and settles the session.
  - A provider record that is missing, unreadable, invalid, another session's or changed
    during the close, or a recorded provider that has exited, ends only the wrapper, and the
    closed record says why the provider was left out.
  - A recorded provider that cannot be inspected, or whose process has the recorded creation
    time and another image, refuses the close before either process is ended.
  - When the provider was ended and the wrapper could not be, the refusal says that the
    recorded provider was already ended, and the handle is kept for a retry.
  - Limit: Windows has no foreground process group and TAB places the interactive provider in
    no job object, so processes the provider or the wrapper started can keep running (#461).
    The managed console's rows with a live owner do not change (#460).

### Workspace consent

- **Claude's store is read before its Git scope is checked (#454).** The lookup reads Claude's
  entry for the folder first and checks the scope only for an accepted entry; a folder
  without an entry costs no Git call. Where another provider's verified consent would apply
  to a Claude target without an entry, the consent authority runs the scope check itself. A
  launch folder with its own regular `.git` file is its own top level, taken without running
  Git and without reading Git configuration, so `core.worktree` does not move it. A `.git`
  directory keeps the earlier rule. A `.git` that is a link or another special entry, and on
  Windows any reparse point, refuses the scope. Two results change for a launch folder inside
  an enclosing repository: a folder whose `.git` file Git could not resolve, and one whose
  `.git` file names a repository whose `core.worktree` makes Git report another top level,
  were refused and are now their own top level.

- **Windows: Codex's trust store is matched the way Codex matches it (#457).** A store key
  matches the judged folder when the two spellings agree apart from ASCII letter case, and
  several matching keys are refused as ambiguous. An `untrusted` match declines whatever its
  spelling; when no key matches by ASCII case, an `untrusted` key equal to the folder's key
  under Unicode lowercase still declines. A `trusted` match with the folder's exact spelling
  decides. With another spelling it counts only when every directory from the volume root down
  to the folder's parent reports case-insensitive names; under a case-sensitive directory, for
  example one created from WSL, or where that flag cannot be read, Codex's trust no longer
  supplies TAB consent and the provider's own dialog decides. The launch override folds ASCII
  case only. Recorded evidence keeps the key text 0.4.50 records; a pin whose entry no longer
  counts reports `source-reset` at the next start. macOS and Linux keep the exact string match.

### State root

- **TAB prepares its state root before anything is written into it, and checks the result
  (#458).** TAB set the root's mode to 0700, or a protected user-only DACL on Windows, and did
  not look at the result, at the owner, or at a macOS access control list. Every step that can
  create the root now opens the directory, reads the owner, the mode and the ACL or DACL from
  that handle, repairs, and reads again.
  - **Repaired.** The mode and the Windows DACL, as before. On macOS an extended ACL on the
    root is removed. On Windows a root owned by the Administrators group is given to the user
    when the user's token does not own files as that group, the case of a root an elevated run
    created. The ACL removal and the owner change apply only to a directory this call created
    or one that already holds a TAB entry (`state-root.durable`, `settings.json`,
    `workspace-consent/` or a `session-*` directory).
  - **Refused.** A root owned by another uid, also when TAB runs as uid 0, or by another
    account on Windows; an ACL or a descriptor that cannot be changed, or an ACL that cannot
    be read on a directory TAB may not repair; a mount where mode 0700 cannot be set and read
    back; and an existing directory without a TAB entry whose ACL would need removing or
    whose owner would need setting. TAB never changes a Unix owner and adjusts no token
    privilege.
  - **Which commands refuse.** `ask`, `reopen` and `self-test` refuse. The settings setters
    and `consent revoke` and `reset` refuse only the directory without a TAB entry; for every
    other failure to make an existing root private they print the reason as a warning and
    attempt their write.
  - **The text.** The refusal, the warning and `doctor` give the same text: what was
    observed, the failed operation with its error, and at most one remedy that fits the
    cause. A directory that is not known to be TAB's never gets a remedy that changes it: the
    text says to set `AGENT_BRIDGE_NATIVE_STATE_DIR` to a directory meant for TAB.
  - **`doctor`** has a new `state_root` row, in both modes: private, not private, unreadable,
    or absent, with the same detail and its one remedy, or none, as the next action. It
    reports a missing root as absent only when the nearest existing ancestor resolves to a
    directory. It repairs and changes nothing. `scripts/share_diagnostics.py` keeps 25 items
    per array instead of 24 for the added row.
  - **Limits.** The ownership and permissions of the root's ancestors are not checked.
    Making the root private is not bounded by the request deadline. A home directory on a
    network file system was not tried.

## Verification and upgrade

- Tests: on the release source the serial suite passed on Linux (Ubuntu 26.04, Rust 1.97.1;
  2,035 tests, 1 ignored), with fmt, Clippy with `-D warnings` on
  the host and for the Windows and macOS targets, and the build check for an operating system
  without a terminal transport. CI ran the suite on main before the version change
  (`b91ab21`) on macOS (2,420 tests), Linux (2,035) and Windows
  (2,065), and passed on each pull request.
- Live, with builds of the release source (record in
  [the 2026-11-28 verification](../verification/2026-11-28-0.4.51.md)):
  - Linux: Codex and Claude round trips on Herdr and on tmux; the repair of a state root's
    mode by a settings setter; the `doctor` row for an absent root, a directory that holds no
    TAB entry, a selected file, a path below a file and a dangling link; and the refusal of a
    workspace path and a state root path that are not Unicode text, with nothing written.
  - macOS: Codex and Agy round trips on Herdr; the removal of an ACL entry from a TAB root by
    a settings setter; and the refusal of a directory without a TAB entry that carries one.
- Not run live: Windows; Pi; Claude on macOS, whose login on the test host had expired, so
  that the installed 0.4.50 failed the same step; the macOS terminal applications; the close
  and Repair changes (#435, #437, #456, #459, #464); the commands for a copied session (#444,
  #446, #447, #449); the launch deadline, the owner record and the failure settlement (#436,
  #438, #439, #445, #453); the consent changes for Claude and Codex (#454, #457); and the
  state root on Windows. They are covered by tests only.
- Upgrade:
  - No stored field or file is added. One stored value changes: a consumption marker written
    for a handle that omits its kind records `"terminal": null`, where earlier releases
    recorded `"iterm2"`. 0.4.50 reads `null` there.
  - The state root is checked when this release first writes into it. A mode is repaired as
    before, an extended ACL on a macOS TAB root is removed, and on Windows a TAB root owned by
    the Administrators group can be given to the user. A root that 0.4.50 used and this
    release refuses, for example one owned by another account, needs the remedy the refusal
    names. A rollback does not undo these changes to the root.
  - On Windows, Repair no longer ends the console of an active session whose owner is gone:
    close the session with `close-session --explicit` after the console is gone, also before
    a `reopen`.
  - On Windows, Codex's trust for a folder whose stored key has another spelling counts only
    where every ancestor directory reports case-insensitive names. An existing pin whose entry
    no longer counts reports `source-reset` at the next start.
  - After a rollback to 0.4.50: it reads every record this release writes. It judges a
    session copied from another operating system by this machine's processes again, its
    Windows Repair ends a running console of a gone owner, it refuses the close of a macOS
    terminal session without a verified owner before it looks at the terminal, and it does not
    check the state root's owner or ACL. When a Codex store holds keys that differ in the
    case of a non-ASCII letter and carry different trust levels, the two versions can select
    different entries; 0.4.50 then reports `source-reset` and assesses again.
  - Continuing a running session across the upgrade, and a rollback, were not exercised
    live.
