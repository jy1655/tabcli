# TAB 0.4.51

0.4.51 changes how a session ends when TAB cannot rely on its owner. An explicit close of a
macOS terminal application session whose owner cannot be verified now settles once the
terminal is proven gone, Windows Repair leaves the console of an active session for an
explicit close, and on Windows an explicit close can end the live owner of a Herdr terminal
that is gone. A session copied from another operating system is settled, pruned and observed
from its records, not from this machine's processes. TAB prepares its state root before
anything is written into it and checks the result. Claude's Git-scope lookup changes, Codex
grants from differently spelled Windows keys face stricter checks, and the preparation of a
launch checks the request deadline before its persisted writes. Commands and JSON output keep
their form. No stored field or file is added; one stored value changes, the `terminal` of a
consumption marker written for a handle without a kind.

Each item names its pull request, whose description has the conditions and limits in full.

## What changes for a caller

### Sessions copied from another operating system (#444, #446, #447, #449)

- **What counts as a copy.** Only records that state it: a bound active handle that states a
  terminal kind this system does not run, or a Herdr handle whose host birth is another
  system's; a completed consumption marker that states such a kind; a bound owner record that
  carries another system's process identity. A handle left claimed by an interrupted close, an
  omitted kind, a record its reader refuses, and a marker with a repeated `consumed` or
  `terminal` field say nothing.
- **Close.** `close-session --explicit` settles a copy from its records alone, without
  addressing a terminal or a process of this machine, when the session has exited or failed or
  an unambiguous completed marker is present; the marker lets it finish an interrupted close
  whose status still says running. It validates both handle names before it writes anything,
  publishes the marker, commits the closed record and only then removes the handles; a failed
  marker write removes nothing, and a retry finishes what an interruption left. A copy whose
  records leave it running keeps a refusal: the existing `<terminal> is not available on <OS>;
  use <alternatives>` text for a copy shown by its kind, and a refusal that names the other
  system for a copy shown by its Herdr birth or its owner. A close that is not an explicit one
  never settles a copy.
- **Prune and Repair.** `prune-sessions` removes a closed copy without observing its owner.
  Dead-owner Repair, in `sessions`, `tell`, `wait` and before a close, does not judge a copy's
  owner from this machine's processes.
- **Observing commands.** `status` reports a copy's owner as unverified, and a pending `wait`
  gives no owner verdict. `inspect` reports the owner's liveness as unknown and predicts that
  `tell` is refused at the surface (`surface_unsupported`), after the earlier refusals for a
  closed, unreadable or unbound session. `doctor` reports the launch configuration and the
  consent records from the records, leaves out the provider installation and version, the
  adapter's diagnosis and the shell startup check, and leaves `scope.executable` null;
  `configured.provider_path` still carries the recorded path. `screen` makes no terminal call
  when its first check finds a copy, and withholds the captured text when its confirmation
  finds one. `tell` refuses a copy after the hold check and the record convergence it already
  runs, before the ownership proof, the Claim and the input. A running copy with a bound owner
  that is used as an origin is `owner_unverified` in `sessions`, `status`, `inspect` and
  `doctor`; a handle or marker that changes during the read gives `origin_busy`. After a
  refused `reopen`, proof that nothing was spawned still releases the reservation; a local
  process id that is gone does not release a copy's.
- **Limit.** A Herdr handle is valid on every system, so once a copy whose only evidence was
  its handle's host birth has been closed, nothing in its records distinguishes it from a local
  session.
- **Native sessions: the close holds one lock.** An explicit close now holds the lifecycle
  lock, with its original deadline, across completion recovery, launch Repair, dead-owner
  Repair and the close, and acts on the records it acquired under that lock. Five native
  behaviors change with that (#446 lists them): the lifecycle lock file exists before pre-close
  Repair runs; a handle replaced between the acquisition and the claim is not dispatched, the
  attempt ends with an error and a retry closes the replacement; launch Repair inside an
  explicit close is never skipped because the lock was busy; marker bytes that are neither the
  acquired marker nor the marker this close wrote end the attempt and are preserved; a handle
  that cannot be decoded is reported under `terminal.json` and stays there.
- **Marker kind.** When a close writes `terminal.closed.json` for a handle that omits its kind,
  it records `"terminal": null`; earlier releases recorded `"iterm2"`. The timeline of `inspect
  --timeline` shows that field and the self-test metadata falls back to it. For such a closed
  session without a launch-host record, `doctor --probe` reports
  `shell_environment_probe_context_unavailable` instead of treating the session as iTerm2.
- **Origin read allowance.** The origin verdict reads up to 768 KiB per origin, up from 512
  KiB, because it now also reads the active handle and the completed marker. The per-record
  limits and the 100 ms deadline are unchanged.

### Launch

- **Preparation checks the request deadline before its persisted writes (#436).** For `ask`,
  `tell` and `reopen`, preparation now reads the command deadline before the workspace consent
  record, the state root with its ancestry syncs and durability receipt, the Session directory
  and the reopen marker, and an expired request is refused at the first of these it reaches, as
  a timeout that names the step and lists what the request had already written. A write that
  has started is completed. Inside an hc terminal the automatic Herdr caller check stops
  waiting at the earlier of the request deadline and its own ten seconds; a configuration read,
  a parent lookup or a reply decode that has started can finish later. A reopen's reservation
  waits for the source's lifecycle lock only until the deadline. Two steps stay unbounded:
  finalizing or releasing a reopen marker once it is written, and making the state root
  private.
- **A failure to open a surface settles this launch's records, and waits for the lock (#445).**
  A failure without a retained surface now waits for the lifecycle lock within the launch
  budget, with one last attempt at the deadline, where 0.4.50 made one attempt and, when the
  lock was held, told the caller that provider startup was in progress. It writes only when the
  current Claim and the receipt's Claim are the Claim this launch started with, so another
  launch's records at the same path are left alone. A definitive open failure on a launching
  session records the error and releases the Claim. If the provider may already have started
  spawning, TAB retains the Claim and records the uncertainty and the instruction not to resend
  in `status.error`; the command can return the original surface-open error alone. When nothing
  can be settled and this launch's Claim is still installed, the error says that nothing was
  recorded and that the Claim is retained, and warns against resending when the launch is past
  its pending phase. A reopen's fence of a failed child waits only until the request deadline,
  and a later `reopen` of the source finishes it once the child's lock is free; publishing the
  refusal still waits without the deadline.
- **The owner record belongs to the wrapper that spawns the provider (#439).** The wrapper
  registers its owner record under the lifecycle lock. Before any spawn a later wrapper can
  still replace an earlier wrapper's registration; the wrapper that passes the spawn fence
  makes the record name itself in the same locked step. When another wrapper is the recorded
  owner, a refused wrapper settles nothing: it changes neither the status nor the Claim nor the
  owner record, adds no exit line to `launch.log`, and reports its error in its own terminal. A
  wrapper that fails before it registered still settles the launch when no owner is recorded
  and no spawn was attempted. For the ordinary single wrapper the records are those 0.4.50
  writes, with three differences #439 states: a definitive failure to start the watcher or to
  spawn is settled inside the fence; a wrapper refused at admission no longer appends its own
  `wrapper_exit_code=1; launch cancelled or already attempted` line; and a launch without a
  receipt is checked at registration.
- **A launch host leaves a directory it refused untouched (#453).** On Linux and Windows a host
  that refused the session directory wrote its refusal into `launch.log` of that directory. No
  host does that now, on any OS. The launcher's own check before any terminal exists still
  reports a violation it can establish; a refusal that only the host meets leaves the directory
  as it was.
- **Paths must be Unicode text (#455).** A workspace, a state root or a TAB executable path
  that is not Unicode text is refused on every OS and every terminal before the Session exists,
  and the refusal names the field. Nothing is written for a refused request. `self-test`
  reports the refusal with a null `state_root` when the ordinary root cannot be written as
  text. On Windows the PowerShell 7 executable path, a `.cmd` or `.bat` provider path and a
  `.ps1` script path are converted to text exactly or refused, and `doctor`'s `powershell` row
  shows the path without the `\\?\` prefix. The PowerShell wrapper and the Herdr attach command
  double each character PowerShell reads as a single quote (U+0027, U+2018, U+2019, U+201A,
  U+201B), so a path that contains one is carried exactly. `PATH` entries keep their handling.
- **macOS: a launch that outlived its receipt reports `binding_timeout` (#438).** On the
  shell-capture host that Herdr, iTerm2 and WezTerm use, a launch whose receipt expired, for
  example across a system sleep, was reported as `binding_mismatch`. It now reports the
  existing `binding_timeout` reason. Linux and Windows do not use this host.

### Close and Repair

- **A Herdr session with a saved teardown intent closes by the creation-record rule (#437).**
  On macOS and Linux the replay of a saved teardown intent now validates the intent's own
  fields first, and one observation of the owner record chooses the branch. A session-bound,
  platform-consistent record with an attested live incarnation selects the close with a live
  owner, and it must be the owner the intent names; a different attested live owner is refused.
  Every other owner puts the close on the creation record: the verified core must report the
  recorded address absent, which settles the session, or identify the exact finished terminal,
  which is removed unless it is set to keep. A running or kept terminal is refused, and no
  signal goes to a process group. When the bound owner of an interrupted teardown has exited,
  the close no longer waits until the saved process group is proven gone. The other terminal
  kinds keep 0.4.50's replay.
- **Repair rewrites a consumption marker that is not committed (#435).** When dead-owner Repair
  closes a session whose handle files are gone, it now rewrites an existing
  `terminal.closed.json` unless that marker decodes with `consumed: true`, as an explicit close
  of an already closed session does: `{"consumed": true, "terminal": null}` with the owner-exit
  reason. A committed marker keeps its bytes, and an absent marker stays absent.
- **A Windows managed console's presence is judged by its recorded root (#456).** The check
  reads the recorded root through one observation of the process and compares PID, creation
  time, and image path without regard to ASCII letter case. A confirmed exit or a different
  creation time proves that the root is gone; an invalid record, an inspection error or a
  different image at the same creation time leaves presence unverified. Only a proven
  disappearance ends a pending launch as a disappeared surface.

- **An explicit close can settle a session without a verified owner once its terminal is proven
  gone (#459).** TAB does not end a running terminal of a session whose owner is gone, with one
  documented exception, tmux. 0.4.50 applied that to Herdr; this release applies it to the
  macOS terminal applications and the Windows managed console.
  - **macOS terminal applications.** An explicit close of a session whose owner record is
    unreadable, malformed, unbound, another session's, incomplete, names a reused PID or names
    a process that cannot be judged was refused before TAB looked at the terminal, also after
    the window was gone. So was a session without an owner record outside a failed or launching
    start. The close now reads the recorded surface's presence without sending a close or any
    input: a proven absence settles the session, a terminal that is still listed refuses with
    the instruction to end it and close again, and a read that fails keeps the handle and
    returns that error.
  - **Windows managed console.** Dead-owner Repair, which runs with `sessions`, `tell`, `wait`
    and at the start of every close, no longer ends a running console of a gone owner: in an
    active state it keeps the handle for an explicit close, and it settles an exited or failed
    session from its records as before. An explicit close without a usable owner record, or
    with this session's owner observed gone, settles once the recorded root is proven gone and
    the session's own stalled tab host, when one is recorded, has been ended; it refuses while
    the root is there. The closed record keeps the stored diagnosis, or carries `native session
    process N is no longer running` for this session's owner observed gone. When this session's
    owner record names a process that is alive or cannot be judged, the root's absence grants
    nothing. Windows process checks keep an inspection error as an error, and the console entry
    points reject a recorded PID of zero. `reopen` needs a closed source, so an active session
    whose console outlived its owner is closed with `close-session --explicit` after the
    console is gone, where Repair used to end the console.
  - **Unchanged.** A live, verified owner with a present terminal; tmux, which keeps ending the
    private server TAB started for the session; a failed or launching start without an owner
    record; the replay of a saved close intent.

- **Windows: an explicit close ends the live owner of a Herdr terminal that is gone (#464).**
  On macOS and Linux an explicit close of a session whose owner is alive and whose Herdr
  terminal is gone ends the owner's foreground process group and settles the session. On
  Windows that close was refused. It now applies when the owner record is bound to the session
  and attested live and the recorded core answers `not_found` for the recorded local address:
  TAB ends the two processes it has recorded for the session, the provider and then the
  wrapper, each through one handle on which it has verified the PID, the creation time and the
  image path, and settles the session. Both are verified before either is ended, and the core's
  answer and the owner record are read again before the first stop.
  - A provider record that is missing, unreadable, invalid, another session's or changed during
    the close, and a recorded provider that has exited or whose PID now belongs to another
    process, end only the wrapper, and the closed record says why the provider was left out.
  - A recorded provider that cannot be inspected, or whose process has the recorded creation
    time and another image, refuses the close before either process is ended. So does a wrapper
    that cannot be verified, an owner record that changed, and a core that no longer answers
    `not_found`.
  - When the provider was ended and the wrapper could not be, or the deadline passes after one
    or both were ended and before the consumption marker is committed, the error names what TAB
    ended and the handle is kept for a retry. Once the marker is committed the caller can
    receive the plain timeout; the marker carries both outcomes into the retried close.
  - Limit: Windows has no foreground process group and TAB places the interactive provider in
    no job object, so processes the provider or the wrapper started can keep running (#461).
    The managed console's rows with a live owner do not change (#460).

### Workspace consent

- **Claude's store is read before its Git scope is checked (#454).** The lookup reads Claude's
  entry for the folder first and checks the scope only for an accepted entry; a folder without
  an entry costs no Git call. For such a folder, a recheck of a recorded Claude source whose
  entry is gone reports the source as reset rather than unreadable, and Claude's readiness
  timeout names its trust dialog as a possibility. Where another provider's verified consent
  would apply to a Claude target without an entry, the consent authority runs the scope check
  itself. A launch folder with its own regular `.git` file is its own top level, taken without
  running Git and without reading Git configuration, so `core.worktree` does not move it; it
  still needs an accepted entry or another provider's verified consent. A `.git` directory
  keeps the earlier rule. A `.git` that is a link or another special entry, and on Windows any
  reparse point, refuses the scope. Two results change for a launch folder inside an enclosing
  repository: a folder whose `.git` file Git could not resolve, and one whose `.git` file names
  a repository whose `core.worktree` makes Git report another top level, were refused and are
  now their own top level.

- **Windows: Codex's trust store is matched the way Codex matches it (#457).** A store key
  matches the judged folder when the two spellings agree apart from ASCII letter case, and
  several matching keys are refused as ambiguous. An `untrusted` match declines whatever its
  spelling; when no key matches by ASCII case, an `untrusted` key equal to the folder's key
  under Unicode lowercase still declines, and a `trusted` one there grants nothing. A `trusted`
  match with the folder's exact spelling decides. With a spelling that differs in ASCII case it
  counts only when every directory from the volume root down to the folder's parent reports
  case-insensitive names; under a case-sensitive directory, for example one created from WSL,
  or where that flag cannot be read, Codex's trust no longer supplies TAB consent and the
  provider's own dialog decides. The launch override folds ASCII case only. Recorded evidence
  keeps the key text 0.4.50 records; a pin whose entry no longer counts reports `source-reset`
  at the next start. macOS and Linux keep the exact string match.

### State root

- **TAB prepares its state root before anything is written into it, and checks the result
  (#458).** TAB set the root's mode to 0700, or a protected user-only DACL on Windows, and did
  not look at the result, at the owner, or at a macOS access control list. Session creation,
  the consent record and the settings setters now open the directory, read the owner, the mode
  and the ACL or DACL from that handle, repair, and read again. An isolated self-test prepares
  its own root in the same way; it makes the configured parent directory private only when it
  creates that parent, and an existing parent keeps its permissions. A final link is followed
  once, and only the directory it names is judged and changed.
  - **Repaired.** The mode and the Windows DACL, as before. On macOS an extended ACL on the
    root is removed. On Windows a root owned by the Administrators group is given to the user
    when the user's token does not own files as that group, the case of a root an elevated run
    created. The ACL removal and the owner change apply only to a directory this call created
    or one that already holds a TAB entry (`state-root.durable`, `settings.json`,
    `workspace-consent/` or a `session-*` directory). On Windows TAB attempts a needed DACL
    repair also when it refuses the owner, and a DACL repair or an owner change that succeeded
    stays when a later step fails; a retry reads the current descriptor.
  - **Refused.** A root owned by another uid, also when TAB runs as uid 0, or by another
    account on Windows; an ACL or a descriptor that cannot be changed, or an ACL that cannot be
    read on a directory TAB may not repair; a mount where mode 0700 cannot be set and read
    back; and an existing directory without a TAB entry whose ACL would need removing or whose
    owner would need setting. TAB never changes a Unix owner and adjusts no token privilege.
  - **Which commands refuse.** `ask`, `reopen` and `self-test` refuse. The settings setters and
    `consent revoke` and `reset` refuse only an existing directory without a TAB entry whose
    repair would need the ACL removal or the owner change. For every other failure to make an
    existing root private they print the reason as a warning and attempt their write. A path
    that cannot be inspected or created is an error for them, as before.
  - **The text.** The refusal, the warning and `doctor` give the same text: what was observed,
    the failed operation with its error, and at most one remedy that fits the cause. A
    directory that is not known to be TAB's never gets a remedy that changes it: the text says
    to set `AGENT_BRIDGE_NATIVE_STATE_DIR` to a directory meant for TAB. On macOS an `EPERM` on
    opening the root or reading its ACL that no immutable flag explains is reported as the
    terminal's privacy access instead. Some failures carry no remedy.
  - **`doctor`** has a new `state_root` row, in both modes: private, not private, unreadable,
    or absent, with the same detail and its one remedy, or none, as the next action. It reports
    a missing root as absent only when the nearest existing ancestor resolves to a directory,
    without testing whether the creation would succeed. It repairs and changes nothing.
    `scripts/share_diagnostics.py` keeps 25 items per array instead of 24 for the added row.
  - **Limits.** The ownership and permissions of the root's ancestors are not checked. Making
    the root private is not bounded by the request deadline. Two concurrent first runs under an
    inheritable macOS ACL can see one of them refused until a retry. A home directory on a
    network file system was not tried.

## Verification and upgrade

- Tests: on the release source the serial suite passed on Linux (Ubuntu 26.04, Rust 1.97.1;
  2,035 tests, 1 ignored), with fmt, Clippy with `-D warnings` on the host and for the Windows
  and macOS targets, and the build check for an operating system without a terminal transport.
  CI ran the suite on main before the version change (`b91ab21`) on macOS (2,420 tests), Linux
  (2,035) and Windows (2,065), and passed on each pull request.
- Live, with builds of the release source (record in [the 2026-11-28
  verification](../verification/2026-11-28-0.4.51.md)):
  - Linux: Codex and Claude round trips on Herdr and on tmux; the repair of a state root's mode
    by a settings setter; the `doctor` row for an absent root, a directory that holds no TAB
    entry, a selected file, a path below a file and a dangling link; and the refusal by `ask`
    of a workspace path and a state root path that are not Unicode text.
  - macOS: Codex and Agy round trips on Herdr; the removal of an ACL entry from a TAB root by a
    settings setter; and the refusal of a directory without a TAB entry that carries one. A
    Claude round trip failed at its initial delivery, with the candidate and with the installed
    0.4.50 alike, and a separate `claude -p` call reported an expired login; no Claude round
    trip passed on macOS.
- Not run live: Windows; Pi; Agy on Linux; the macOS terminal applications; the close and
  Repair changes (#435, #437, #456, #459, #464); the commands for a copied session and the
  native close under one lock (#444, #446, #447, #449); the launch deadline, the owner record
  and the failure settlement (#436, #438, #439, #445, #453); the consent changes for Claude and
  Codex (#454, #457); the Unicode check beyond `ask` on Linux (#455); and the state root on
  Windows. They are covered by tests only. The FreeBSD target was compile-checked with `cargo
  check`.
- Upgrade:
  - No stored field or file is added. One stored value changes: a consumption marker written
    for a handle that omits its kind records `"terminal": null`, where earlier releases
    recorded `"iterm2"`. 0.4.50 reads `null` there.
  - The state root is prepared by session creation, the consent record and the settings
    setters. A mode is repaired as before, an extended ACL on a macOS TAB root is removed, and
    on Windows a TAB root owned by the Administrators group can be given to the user. When this
    release refuses a root that 0.4.50 used, for example one owned by another account, the
    refusal names what it found and gives a remedy where one exists. A rollback does not undo a
    change this release made to the root, including a Windows DACL or owner change that
    preceded a refusal.
  - On Windows, Repair no longer ends the console of an active session whose owner is gone:
    close the session with `close-session --explicit` after the console is gone, also before a
    `reopen`.
  - On Windows, a `trusted` Codex key with another spelling than the folder's can grant only
    when it matches by ASCII case and every ancestor directory reports case-insensitive names.
    An existing pin whose entry no longer counts reports `source-reset` at the next start.
  - After a rollback to 0.4.50: it reads every record this release writes. It judges a session
    copied from another operating system by this machine's processes again. Its Windows Repair
    ends a running console of a gone owner, and it refuses the Windows close of a live owner
    whose Herdr terminal is gone. On an ordinary explicit close it again refuses before it
    looks at a macOS terminal application's surface when the owner record is malformed, or when
    it is missing outside a failed or launching start. It does not check the state root's owner
    or ACL. Its Codex lookup on Windows folds with Unicode lowercase and makes no ancestor
    check; when the entry it selects does not verify a recorded pin, it reports `source-reset`.
  - Continuing a running session across the upgrade, and a rollback, were not exercised live.
