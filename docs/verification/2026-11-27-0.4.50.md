# 0.4.50 candidate verification, 2026-11-27

Automated and live checks of the source that became 0.4.50. The live checks ran on macOS
only; Linux and Windows are covered by CI.

## Tested identity and conditions

- Source: commit `5dd84c9` on the release branch, tree
  `53ef5ae5816ae91a7f83e8cc6be4fd4fc2ac741a`. It is main at `fcfdf3a`, the state after pull
  requests #413 to #418, #420 and #432, with the version change and a wording correction in
  three documents. The release commit adds only this record and the release note to it.
- The candidate executable was built from that commit with `cargo build --release --locked`
  in a checkout without local changes. It reports `tabcli 0.4.50` and has SHA-256
  `9451a40c18d5395cd9f50e22b939db4155d20f8d9e4a14b051611f4ba6148085`. This is source-build
  evidence, not verification of a published archive.
- macOS 27.2.1, arm64, Rust 1.98.1, hc 0.1.22. Commands ran inside an hc terminal.
- Providers: Codex 0.172.0, Claude Code 2.1.332 with `--model opus`, Agy 1.5.18. No bypass
  option was used in the self-tests.
- Workspace consent: the three self-test sessions and the session of the close check each
  recorded consent as verified from the Codex trust entry for the workspace.
- One live check, the worktree consent, ran on the head of #417 with a debug build of that
  head, not with the candidate executable; its section says so.
- Every self-test used `--isolated`. The other checks below each used a separate state
  directory through `AGENT_BRIDGE_NATIVE_STATE_DIR`. No run used the ordinary state root.

## Close of a Herdr terminal whose owner is gone

The detached `ask codex` above launched `session-4TCdgG` on Herdr and the following `result`
returned `READY`. The session's owner process was then ended with SIGKILL, outside TAB. The core
reported the terminal as finished with exit code 137, and `inspect` reported the owner as
not alive with the stored state still `ready`. `tabcli close-session session-4TCdgG
--explicit` returned `closed: true`; the core no longer knew the terminal, and its terminal
list matched the list from before the launch. A second explicit close also returned
`closed: true`. `inspect` then reported the state `closed` with the error `native session
process <pid> is no longer running`, and the consumption marker held the same reason.

A running Herdr terminal without a live owner could not be produced this way: the terminal
ends with its owner. That refusal is covered by tests only.

## Worktree consent and Agy's session-only setting

Checked on the head of #417 (`05df819`) with a debug build of that head, which reported
`tabcli 0.4.49`, and Agy 1.5.18 on Herdr; the consent and Agy code is unchanged since. In a
new git worktree that no provider store lists, under a main working tree that Codex trusts,
no trust dialog appeared, the prompt and a follow-up were answered (`session-u2qT2k`),
`inspect` showed verified inherited consent with the `agy-settings-override` marker, and
Agy's trust store file was byte-identical before and after. In an empty folder without
consent the dialog appeared, and no settings file and no `--settings` were used
(`session-bPW7I0`).
