# Windows verification of the 0.4.31 release candidate

Verified on 2026-10-30 on the owner's native Windows machine with a candidate binary built
from the release branch, before the tag existed. The candidate passed initial input, exact
initial result, follow-up input, a distinct exact result and confirmed close for all four
providers, and a Claude close followed by a reopen that continued the same conversation.
This is an ordinary installed-setup smoke test of the public commands, not a claim about
every permission, interruption or terminal path. The published asset is verified separately
after publication.

## Identity and conditions

- Source: `release/0.4.31`, which is main `cc55f960978872cafeb7e0d732c371232433eb7f`
  (#318, #319, #320 merged) plus the 0.4.31 version bump and these documents.
- Candidate executable: `target/debug/tabcli.exe` of that worktree, `tabcli 0.4.31`,
  SHA-256 `011566481c6814b06b99e42fe281172c4be509906aeee40f5d779e64f2b05232`.
- Windows 11 Home, build `10.0.26200.9457`, x86-64; Windows Terminal `1.24.12741.0`.
- Caller: a Python driver started from the owner's Claude Code session, running only the
  public commands; live workspace `D:/Dev/agent-bridge` with its existing consent record.
- Ordinary state root, `windows-console`, dedicated Agent Bridge window, lifecycle hooks on.
- Explicit standing owner override `--yolo`; no model or effort override. Provider
  defaults were used; resolved model, backend and effort were not controlled.
- One trial per provider, sequentially, with no concurrent source checks. The elapsed
  observations are neither performance baselines nor model or billing time.

For each provider:

```powershell
tabcli self-test PROVIDER --workspace D:\Dev\agent-bridge --terminal windows-console --yolo --timeout-secs 120 --json
```

## Not verified

- macOS runtime: no macOS surface or provider was exercised; macOS coverage of this
  release is the macOS CI job and the cross-target Clippy run.
- Reopen was exercised for Claude only, the one provider with a verified reopen on
  native Windows. Agy and Codex follow-ups ran through self-test only.
- A Pi session opened by 0.4.30 and continued or cancelled under this binary was not
  exercised; the compatibility statement in the release notes is source-based.
- Card 10 of the 2026-10-29 architecture review (the shared procedures of the macOS
  terminal adapters) is not part of this release and had no runtime verification.
- The published release asset and its installation are verified after publication and
  recorded separately. The candidate above is the local `cargo build --locked` debug
  build with default features; the later all-features test build in the same worktree
  replaces that file, so the hash is the one recorded at run time, not the file left
  behind afterwards.
