Before supplying consent, new Agy and Claude workspaces displayed their native
trust dialogs; Bridge did not accept them. Those probe sessions were closed.

Three candidate defects were found by live checks and corrected:

- Terminal.app's `contents of <variable>` dereferenced the AppleScript tab
  reference instead of reading screen text. Selecting the exact tab property
  fixed the read; both Terminal.app provider dialogs then passed.
- Codex splits the `-c` left-hand key at every dot, without parsing quoted TOML
  keys. A quoted dotted project key therefore left the trust dialog visible.
  Supplying `projects={"<exact path>"={trust_level="trusted"}}` puts the path in
  the TOML value. The regression test and live ask/tell then passed. See the
  [0.157.1 override parser](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/config/src/overrides.rs).
- Claude approved the parent Git root while displaying an exact child path
  (`session-n719Oc`). The original test failed with `Some(DownEnter)` where no
  response was allowed. The adapter now checks the actual Git scope, including
  nested repositories, and withholds sharing when it would approve a parent.
  That regression test passes. A child consent cannot replace manual approval
  of a broader provider-owned scope.

After the fix, `session-p01hlc` kept Claude's child-path trust prompt visible with
no response and no parent or child entry added to Claude's store. Agy's comparison
session `session-It5obc` saved only the exact child entry, leaving the parent
unapproved. Both were closed. All 25 task-owned sessions, including failed
candidate and probe sessions, were audited as closed with no active claim or
terminal handle; unrelated sessions were not changed.
