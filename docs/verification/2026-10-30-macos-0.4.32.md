# macOS verification of the 0.4.32 release candidate

Verified on 2026-10-30 on the owner's Mac with a candidate binary built from the release
branch, before the tag existed. Codex and Claude passed the self-test, and a caller carrying
synthetic Codex caller markers ran `ask`, `tell` and `close-session` against both providers
with the installed 0.4.30 as the baseline. The baseline's direct follow-up child carried all
five synthetic values and the candidate's carried none. This is a smoke test of the public
commands on one machine, not a claim about every terminal, permission or interruption path.
The published asset is verified separately after publication.

## Identity and conditions

- Source: `release/0.4.32`, which is main `463f78d0a9edb71c5c131696dc9994ea91f26ac9`
  (#322 to #332 merged) plus the 0.4.32 version bump and these documents.
- Candidate executable: the debug `target/debug/tabcli` that the serial test run of that
  worktree built (the package has no Cargo features), copied before the live runs:
  `tabcli 0.4.32`, SHA-256
  `00bdc1416b088e302f3014c91fde82944755562d5fbf33f2176ee016a5579752`.
- Baseline executable: the installed published `tabcli 0.4.30`.
- macOS 26.5.2 (25F84), Apple silicon; iTerm2 3.7.6; codex-cli 0.166.0; Claude Code 2.1.314.
- Caller: a shell started from the owner's Claude Code session. Live workspace: the
  repository checkout with its existing consent. Explicit standing owner override `--yolo`;
  no model or effort override.
- Each run used its own private state root (`self-test --isolated`, or
  `AGENT_BRIDGE_NATIVE_STATE_DIR` for the direct runs); the ordinary state root was not used.
- One trial per row, sequentially. Elapsed times are Bridge observations, not model or
  billing time.

removal on its own. The next section does.

## Contaminated caller

The caller exported synthetic values for `CODEX_SESSION_ID`, `CODEX_THREAD_ID`,
`CODEX_TOOL_CALL_ID`, `CODEX_DAEMON_SHUTDOWN_FILE` and `CODEX_DAEMON_SHUTDOWN_SOCKET`, and a
synthetic `CODEX_VERSION` as a name that must be kept. It then ran
`ask PROVIDER --terminal iterm2 --yolo` ("Reply with exactly: ALPHA-332"),
`tell` ("Reply with exactly: BRAVO-332") and `close-session --explicit`. While `tell` ran, a
sampler ran `ps -Eww` over every process below the `tell` process, then slept 20 ms between
samples, and retained only synthetic sentinel matches and Codex variable names. No real
environment value was printed or kept.

On macOS the managed provider starts from the terminal's new shell, not from the caller, so
the caller's environment reaches only the processes that `tabcli` starts directly: the Codex
queue, the Claude messenger, probes and terminal automation.

| Provider | Binary | Session | Direct follow-up child | Synthetic removed values it carried | Kept sentinel | Results |
| --- | --- | --- | --- | ---: | --- | --- |
| Codex | 0.4.30 | session-a4yQME | `codex` (queue) | 5 of 5 | present | `ALPHA-332`, `BRAVO-332`, closed |
| Codex | 0.4.32 candidate | session-eT6QDv | `codex` (queue) | 0 of 5 | present | `ALPHA-332`, `BRAVO-332`, closed |
| Claude | 0.4.30 | session-sIoJbl | `claude` (messenger) | 5 of 5 | present | `ALPHA-332`, `BRAVO-332`, closed |
| Claude | 0.4.32 candidate | session-EIFNB0 | `claude` (messenger) | 0 of 5 | present | `ALPHA-332`, `BRAVO-332`, closed |

No synthetic marker or kept sentinel was visible in the `ps` samples for `osascript`, the
other direct child, in either binary; these samples do not establish marker removal in that
process. The Codex queue of both binaries also carried `CODEX_COMPANION_SESSION_ID` and `CODEX_COMPANION_TRANSCRIPT_PATH`,
which the caller's Claude Code Codex plugin had set: the Codex adapter does not select the
Claude adapter's list, and that was outside this change. All six sessions ended closed.

## Automated checks

On the release branch (Rust/Cargo 1.99.1, Python 3.13.16):

- `cargo test --all-targets --all-features -- --test-threads=1`: **1,581 passed, 0 failed,
  6 ignored**, exit 0, after touching the crate roots so the log shows `Compiling tabcli`.
- `cargo clippy --all-targets --all-features -- -D warnings` on the host and for
  `x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu`: passed (compilation evidence only
  for the two cross targets).
- `cargo fmt -- --check`, `git diff --check`, `python3 scripts/check_language.py`,
  `python3.13 scripts/integrations.py check` (0.4.32; claude, codex, agy, pi) and
  `python3.13 -m unittest discover -s scripts -p 'test_*.py'` (109 tests, 2 skipped): passed.
- PR #332 ran the repository CI (seven jobs, success), whose native Windows job ran the two
  `cfg(windows)` caller-marker tests; main push CI of `463f78d` succeeded.

## Not verified

- Native Windows runtime of this release, including a cold Windows Terminal start and a
  later user-opened tab (#111). Windows coverage is the CI job and cross-target Clippy.
- Agy and Pi were not run live; their removal lists are covered by deterministic tests.
- Live values inside Codex hooks and notify, an actual Windows shutdown request through
  either marker, and any behavioral effect of the markers on Claude, Agy or Pi.
- Ghostty, Terminal.app, WezTerm and Warp were not exercised for this candidate.
- The published release asset and its installation are verified after publication.
