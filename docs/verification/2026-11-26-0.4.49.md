## Close after the program ended outside TAB

On macOS, `ask codex` launched `session-4puSp7` on Herdr and returned its result. The
terminal's program was then ended with `hc kill`, outside TAB. The core reported the terminal
as finished, and `inspect` reported the owner process as not alive with the stored state
still `ready`. `tabcli close-session session-4puSp7 --explicit` returned `closed: true`; the
core no longer listed the terminal, and its terminal list matched the list from before the
launch. A second explicit close also returned `closed: true`, and `inspect` then reported
the state `closed` with no residual surface.

## Failed attempt: Herdr from an elevated SSH session on Windows

One Windows attempt did not pass. `self-test pi --terminal herdr`, run from an SSH session
that Windows starts elevated, timed out in its first step after 31.7 seconds with
`provider launch timed out before startup was confirmed`. Cleanup passed and no terminal
remained (`session-mDH1E8`). The launch log held the cause:

```text
herdr_host_refused: Herdr launch directory is not private to the current user: session directory owner differs from current user
```

The elevated caller created the session directory with the Administrators group as its
owner, while the core and its launch host run without elevation in the desktop session. This
is the private-directory rule in [the terminal guide](../terminals.md#herdr-core-on-native-windows).
The published 0.4.48 archive, run the same way, produced the same log line, the same timeout
and the same step outcomes (`session-ekmtWR`), so the result is not specific to this
candidate. In both builds this refusal is written to the launch log only, and the caller
waits for the launch deadline.
