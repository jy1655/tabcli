# Terminal Agent Bridge 0.2.2: macOS verification

## Scope and source

0.2.2 fixes the records and the self-test report of a Ghostty launch that fails after its tab
exists (#86), names a pending Agy tool approval when a self-test result times out (#82), and
documents the screen-lock condition for a launch (#80). This record covers what was run on
macOS for the 0.2.2 candidate. It is not evidence for native Windows or Linux runtime
behaviour.

The tested source is commit `9714a2e3c5fdec68b9f17cb93e9ae958b9f04243`, the version bump. Later
commits on the release branch add this record, the release notes and the README lines that
point to them. The release binary (`cargo build --release --locked`) reports `tabcli 0.2.2` and
has SHA-256 `8c2a847f1d2427fa55097fd183bf3a6c75092bf74795472ac2d218c4328be431`. It is a local
build with Rust 1.97.1, the version the Release workflow pins.

Environment: Apple Silicon, macOS 26.5.2 (25F84), Codex CLI 0.160.1, Claude Code 2.1.292,
Agy 1.2.16, Pi 1.0.0. The commands ran from a shell inside Ghostty, which was the application
in front; the screen was unlocked throughout (checked before and after the runs with
`ioreg -n Root -d1 | grep CGSSessionScreenIsLocked`).

## The Ghostty fix (#86)

Fake-runner tests drive the three orderings around the failed-launch handoff. In the forward
ordering (handoff, then close) the handle is written to `terminal.json`, the session is
`failed` with the surface in its error, a first close whose automation call fails keeps the
handle, and a second close closes the surface and records `closed`. In the two reverse
orderings a close that arrives while the launch record is still pending is refused with the
deadline named, and a close that lands after the deadline but before the handoff records
`closed` and the handoff then appends the surface to the error without writing a handle; two
further closes keep that error and call no adapter. Each test failed against the code before
its patch: no `terminal.json`, a close that was not refused, and an error that was `None`.
The self-test tests cover the `not_verified` cleanup reasons and the recovered close. No live
Ghostty automation timeout was produced on demand; the live rows below exercise the ordinary
Ghostty path, not the failure path.

## The Agy observation (#82)

Tests bind a `Surfacing tool confirmation` line to the pending turn through the same code that
binds an executor error, reject a line of another turn or one that precedes the turn, let a
transcript result or an executor error suppress the observation, and show that a timed-out Agy
result step of the self-test appends only the same request's observation. The fixture is a
composite of the existing real log excerpts and the one line observed with Agy 1.3.0 on
2026-10-07, and says so. A contract test checks that every provider's self-test prompt still
asks for the exact marker.

## Review

Each fix was written by one Codex session (`gpt-6-astra`) and reviewed read-only by another,
with the orchestrating Claude session checking the review's claims in the code before acting
on them. The Ghostty review found that a close before the handoff lost the handle silently,
and after that was fixed, that the self-test still passed cleanup for a closed session whose
error named a residual surface and that a handle-less close erased that warning; all three
were fixed and tested before the commit. The review also found the Warp control-binding
failure path that returns a proven tab as text, which is recorded as #87 and left unchanged.
The Agy review found nothing blocking. A review of the source is not a runtime check.

### Agy

`agy --version` printed 1.2.16 before the run. The first Agy session's log names 1.2.16 and
the two later ones name 1.3.0: Agy updated itself between the first and the second Agy launch,
which is why the default-mode row was run again with 1.3.0 after the planned rows. None of the
three Agy logs holds a `Surfacing tool confirmation` line, so the `doctor` observation of #82
was not exercised live; the self-test did not need it. The two default-mode passes are the
first recorded; they do not show that the new prompt wording is what made Agy answer without a
tool, because the 0.2.1 timeout was not reproduced on this machine first (the 0.2.1 record ran
on another machine with the old wording).

### Pi

This machine has an `openai-codex` login in Pi (`pi auth check --provider openai-codex`
reports `ready`), and the Pi round trip passed in 11 seconds with Pi 1.0.0. The refused-prompt
case of #83 (no login for the selected provider) was not reproduced here, so #83 stays open.

### Ghostty

The Ghostty row is the ordinary launch path: the tab was created, Codex answered, the follow-up
was delivered and the tab was closed. No automation timeout occurred, so the failure path of
#86 (retained handle, refused close during creation, residual-surface error) was exercised only
by the unit tests above. Ghostty was the application in front when the run started; focus went
back to it after each launch, as far as the orchestrating session could tell from the next
command running without interruption, which is not a keyboard check.
