unlocked cold-start measurement requested by [#104](https://github.com/jy1655/tabcli/issues/104)
for the currently installed Ghostty 1.4.0. It does not retroactively verify Ghostty 1.3.1.

## What changed upstream, and what remains to verify

The [Ghostty 1.4.0 release notes](https://ghostty.org/docs/install/release-notes/1-4-0) and
[upstream #13639](https://github.com/ghostty-org/ghostty/pull/13639) identify a relevant fix:
renderer initialization now tolerates display-link creation failure when no display is active.
This specifically addresses tabs created while the session is locked. The old Bridge evidence
of an unavailable surface model was collected on 1.3.1; it must not be presented as an observed
1.4.0 limitation. **Locked-screen cold/warm launches on 1.4.0 remain NOT-VERIFIED here.**
The user explicitly limited this task to the unlocked screen.

Other relevant changes include character-key scripting, foreground PID/TTY properties,
background-tab rendering and close behavior. The installed dictionary still supplies Bridge's
required creation, selection, paste and close commands. The character-key change does not
replace the special Enter operation used by Bridge. New PID/TTY properties are not addressed
input acceptance, atomic UI compare-and-send, or provider completion evidence. They therefore
do not justify removing the current ownership/readiness checks or adding a version-only gate.

The new `tty` property is a candidate for a separate PTY-binding/readiness investigation.
The frame host also transfers the session directory after binding and discards startup input;
replacing it requires preserving those roles. `GHOSTTY_SURFACE_ID` is a core integer identity,
not the AppleScript terminal UUID. No replacement is implemented or verified by this run.

This run found no regression requiring a Bridge behavior change or a Ghostty version floor.
Compatibility remains based on the installed scripting capabilities and actual surface readiness.
For follow-up validation, prioritize locked-screen cold/warm creation because of the specific
upstream fix. Fresh Automation consent, locked-screen focus, physical keyboard preservation,
macOS 27, restored user windows, failed-launch cleanup and moved terminal identities are outside
this measurement; successful ordinary close does not validate those failure paths.

## Evidence and review

Raw command JSON, launch timelines, topology/lock samples, local screenshots, release identity
comparison and the observer script are retained in the operator's local verification directory
`2026-10-28-ghostty-1.4.0-102032`. Screenshots are local-only and are not part of the repository.
All three explicit closes (warm Codex, cold Codex, multiline Agy) reported `closed: true`,
but each separate `started_from` scan exhausted its budget (2,846 / 3,126 / 3,612 registry
entries). Those scans do not establish complete descendant inventories. Cleanup claims here
cover the explicitly tracked task sessions.
The preserved `run_probe.py` is the corrected observer. The initial cold/warm metadata came
from its earlier version, without a `window_count` field; those counts were derived from the
full topology. In the first cold sample, the process query returned no process before the
subsequent topology query saw the new window, illustrating the non-atomic sampling.
The original state root retains the exact addressed request records; the separate-window root
is inside that evidence directory. The check used the installed release binary throughout;
source checks do not substitute for that runtime identity.

All seven runtime provider PIDs were absent at the final process check. That is not a measured
six-second exit bound or a test of Ghostty undo restoration.

Source checks on the release Rust source passed (the proposed Rust diff changes comments only):

- `cargo test --all-targets --all-features -- --test-threads=1`: 1,535 passed,
  0 failed, 6 ignored. This includes
  `macos_terminal_applescripts_compile_without_opening_a_tab` against installed Ghostty 1.4.0.
  Ignored tests are not runtime evidence.
- `cargo clippy --all-targets -- -D warnings` and `cargo fmt -- --check`: passed.
