# 0.4.51 candidate verification, 2026-11-28

Automated and live checks of the source that became 0.4.51. The live checks ran on Linux and
macOS; Windows is covered by CI.

## Tested identity and conditions

- Source: commit `5345fa5` on the release branch, tree
  `ba25c4af8f2de6cc9530adfd592ab578751709d1`. It is main at `b91ab21`, the state after pull
  requests #435 to #439, #444 to #447, #449, #452 to #459 and #464, with the version change.
  Later commits on the release branch change only this record, the release note and the
  release index.
- The Linux candidate executable was built from that commit with
  `cargo build --release --locked` in a checkout without local changes, on Ubuntu 26.04
  (x86_64) with Rust 1.97.1. It reports `tabcli 0.4.51` and has SHA-256
  `3bbb95e2e2c0399121ac05269b83571683277e32a94db4de73b5574504e1458a`.
- The macOS candidate executable was built from the same commit in the same way on macOS
  26.5.2 (arm64) with Rust 1.99.1. It reports `tabcli 0.4.51` and has SHA-256
  `9e03b26fad8f75a12326053cbf536acb3dcedfc4b8962434eab973011e1b77af`.
- Both are source-build evidence, not verification of a published archive.
- Linux: hc 0.1.21 and tmux 3.6; commands ran inside an hc terminal. macOS: hc 0.1.22;
  commands ran over SSH, outside an hc terminal, against the Herdr core of the logged-in
  user.
- Providers on Linux: Codex 0.172.0 and Claude Code 2.1.332 with `--model opus`. The
  self-tests there passed `--yolo` and an explicit `--terminal`. Providers on macOS: Codex
  0.172.0 and Agy 1.5.18, with an explicit `--terminal herdr` and no bypass option.
- Workspace consent on Linux: the four self-test sessions each recorded consent from the
  Codex trust entry for the workspace; the two Codex sessions recorded the
  `codex-config-override` marker. The consent records of the macOS sessions were not read.
- Every self-test used `--isolated`. The other checks each used a separate state directory
  through `AGENT_BRIDGE_NATIVE_STATE_DIR`, apart from one read-only `doctor` of the ordinary
  state root on each host.

```sh
tabcli self-test PROVIDER [--model opus] --terminal KIND [--yolo] --workspace WORKSPACE \
  --isolated --timeout-secs 240 --json

# the state root; ROOT is a directory, a file, a link or a missing path under a new directory
AGENT_BRIDGE_NATIVE_STATE_DIR=ROOT tabcli doctor --provider PROVIDER --json

  --prompt-file PROMPT --detach --json
```

## State root

Linux, each case in a new directory:

- A missing root below an existing directory: `doctor` reported `state_root_absent` with
  `TAB creates it at the first session.` and did not create it.
- An empty directory with mode 0755: `doctor` reported `state_root_not_private` with
  `mode 0755, expected 0700`, said that the directory holds no TAB entry and that
  `AGENT_BRIDGE_NATIVE_STATE_DIR` must name a directory meant for TAB, and left the mode.
- Another directory with mode 0755: a settings setter set the mode to 0700 and wrote
  `settings.json` and `state-root.durable`; `doctor` then reported `state_root_private`.
- A selected regular file: `state_root_not_private`, `expected a directory`. A path below
  that file: `state_root_unreadable`, with the same detail. The file kept its content.
- A final link to a missing target, and a missing root below that link:
  `state_root_unreadable` with the failed open and the selection remedy. A settings setter on
  the link printed the same text as a warning and then failed its write.
- The ordinary state root, inspected only: `state_root_private`.

macOS, each case in a new directory:

- A root a settings setter had created, with an added ACL entry (`everyone deny delete`):
  `doctor` reported `state_root_not_private`, named the entry and `chmod -N`. A settings
  setter on that root succeeded and the entry was gone; `doctor` reported
  `state_root_private`.
- A directory without a TAB entry that carries the same ACL entry: `doctor` named the entry,
  said that the directory holds no TAB entry and gave the selection remedy; a settings setter
  was refused with the same text, wrote nothing and left the entry.
- The ordinary state root, inspected only: `state_root_private`.

## Paths that are not Unicode text

Linux. A detached `ask codex` with a workspace path that holds a byte outside UTF-8 ended
with `workspace path is not Unicode text`, and the state directory stayed empty. The same
command with such a state root path ended with `state root path is not Unicode text`, and
the directory was not created.
