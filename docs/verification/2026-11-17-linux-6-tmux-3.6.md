# Linux tmux 3.6 verification

Live checks on M8 during the implementation of [#6](https://github.com/jy1655/tabcli/issues/6),
2026-11-17, with the authenticated provider CLIs installed there.

## Tested identity and conditions

- Ubuntu 26.04, Linux 7.0, x86_64, bash 5.3, tmux 3.6.
- SSH session, no GUI.
- Branch `feat/6-linux-tmux-transport`, debug build of the working tree that was committed as
  `3b43f23`, run with a separate state directory under the user's home. This is branch-build
  evidence, not verification of a published archive.
- Codex 0.169.0, Claude Code 2.1.326 (`--model opus`), Pi 1.5.2, Agy 1.5.9.
- Claude and Agy were checked in both untrusted and trusted workspaces. The successful
  Agy round trip used `--model gemini-3.8-flash-medium` after the default model hit quota.
  Codex, Pi and Agy otherwise ran with their configured defaults; no bypass option was used.

| Provider | Initial request | Follow-up | Observation and close |

| Codex 0.169.0 | `ask` returned `pong`, about 6.7 s | `tell` through `codex queue` returned `ping` | `screen`; `inspect` reported `owner_identity_verified: true` and `attach_command`; explicit close removed server, pane processes, and socket; repeated close succeeded |

Codex and Claude use their provider-owned follow-up paths. Pi and Agy exercise the tmux
pane-paste fallback; these are distinct delivery paths.

## Expected trust refusals and quota limit

Claude in a workspace it had not trusted, and Agy in an untrusted workspace, stopped launch
with the intended refusal:

```text
the workspace trust dialog cannot be answered with a guarded key in tmux; no key was sent; use the provider's own workspace trust prompt, then launch again
```

This is the intended tmux boundary: screen comparison and key transmission cannot be one
operation, so Bridge does not answer the dialog. The pane remains available for the user to
attach and answer, and the stopped session needs explicit close. These refused launches are
not successful round trips.

Agy's default Gemini 4 Argon model returned account quota exhaustion (429). Its prompt and a
follow-up still reached the pane; that establishes delivery in this attempt, not a successful
model result. The explicit `gemini-3.8-flash-medium` run in the table completed both requests.

## Defect found and corrected during the checks

Naming the tmux session after the Bridge session id caused Claude's agent listing to show the
recipient twice (`tmux session-…:@0.%0`), so initial delivery could not be confirmed. The tmux
session is now named `agent-bridge`; the trusted-workspace Claude round trip above used that
correction.

## Not verified

- Linux processes in WSL.
- GUI attachment from a desktop session.
- Other Linux distributions or tmux versions other than 3.6.
- Linux aarch64.

This record supplies four-provider runtime evidence for the stated SSH setup. It does not
establish a complete matrix of tmux versions, distributions, permission settings, payload
sizes, copy-mode behavior, or lifecycle races. Automated surface tests are described in
[testing](../testing.md); the surface contract is in [terminals](../terminals.md#linux--tmux).
