# Terminal Agent Bridge 0.2.0: macOS verification

## Scope and source

0.2.0 renames the command and package to `tabcli` and adds documentation, third-party notices
and packaging changes. This record covers what was run on macOS for the 0.2.0 candidate. It is
not evidence for native Windows or Linux runtime behaviour.

The tested source is commit `a467d5feda01bd132247821a12e43a52c2d9b983`. Later commits on the
release branch add this record and the release notes only. The release binary
(`cargo build --release --locked`) reports `tabcli 0.2.0` and has SHA-256
`fefc121b2db3bbeccdbb79dc4bf009fc59e28c5c14229ca97eab9f11f97031af`. It is a local build with
Rust 1.98.1; the published archives are built by the Release workflow with the pinned Rust 1.97.1.

Environment: Apple Silicon, macOS 26.6.2 (25G83), Codex CLI 0.160.1, Claude Code 2.1.291. The
commands ran from a shell inside WezTerm.

## Automated checks

- `cargo test --all-targets --all-features -- --test-threads=1`: 713 passed, 0 failed,
  6 ignored: five live tests and one subprocess fixture that another test starts. Ignored tests
  are not runtime passes.

  `--all-features --target <triple>` for `x86_64-unknown-linux-gnu` and
  `x86_64-pc-windows-msvc`: passed. The two cross targets were checked, not run.
- `cargo fmt -- --check` and `git diff --check`: passed.

## Review

The rename, the packaging change, the third-party notices and each document were written in one
session and reviewed against the code by a separate one; the findings were fixed before each
commit. A review of the source is not a runtime check.

first exact marker result, `tell`, a separate follow-up result and owned-session cleanup. All
test sessions ended in `closed`. Every row passed on its first attempt.

## A session of agent-bridge 0.1.2 continued by tabcli 0.2.0

The installed `agent-bridge` 0.1.2 launched `session-GSF6kV` (Codex, WezTerm, provider defaults)
in the ordinary state root and completed its first request. The `tabcli` candidate then ran
`inspect` (owner alive, identity verified, one event), `tell` (completed with the expected
answer, two events) and `close-session --explicit` (closed). The wrapper process and the
completion hook of that session were the 0.1.2 executable throughout, at its installed path.

## Not exercised

- Native Windows and Linux at runtime. The Windows packaging steps of the workflows have not run
  on GitHub at the time of this record.
- Warp, Agy and Pi.
- A session launched by `tabcli` and then handled by an older `agent-bridge`.
- A close after the owner died, an interrupted close, and the Terminal.app paths for a restarted
  or second Terminal process. Unit tests cover them; no live run did.
- Provider approval prompts: the `self-test` prompts ask for a marker and need no tool.
