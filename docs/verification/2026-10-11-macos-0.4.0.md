## Cancel on a Pi session

Two runs with the PR2 candidate's release build against Pi 1.0.4, in WezTerm with the screen
locked. The prompt asked Pi to run `sleep 150` with its shell tool and reply `SLEEP-DONE`; 20 s
after `ask`, `tabcli cancel SESSION --json` was run, then `result --wait`, `inspect`, `status`,
a follow-up `tell`, `inspect --timeline` and `close-session --explicit`. No keystroke was sent
into the session, so the keyboard-interrupt case was exercised only by the Node harness.

| Run | Time (KST) | cancel | Pi's end of turn | Bridge record | Follow-up |
| --- | --- | --- | --- | --- | --- |
| 1, before the fix | 04:07 | `requested`; the extension called `abort` and wrote the accepted record | `stopReason: "error"`, `errorMessage: "This operation was aborted"` after an errored tool result | plain failure, `request_state: failed`, cancel `not_applied` | completed (`AFTER-CANCEL-OK`) |
| 2, after the fix | 04:22 | `requested` at 04:22:19.082 | same shape | `cancelled: true` event at 04:22:19.164 (82 ms after the request), `request_state: cancelled`, error `cancelled: Pi turn ended with error: This operation was aborted`, inspect `applied`, session `ready` | completed (`AFTER-CANCEL-OK`, 2.6 s); `inspect --timeline` has the `cancel_request` entry; close confirmed |

Run 3, on the release candidate itself (`tabcli 0.4.0`, 04:37:23 KST): the same sequence ended `cancelled` with `inspect` showing `applied`, the session `ready`, and the follow-up completed at 04:37:27.

Run 1 is the reason the extension accepts Pi's tool-call abort shape as well as `stopReason:
"aborted"`; the fix was re-reviewed before merging. `result --wait` and `wait` exit non-zero on
a cancelled request, as documented.

With iTerm2 quit, `ask codex --terminal iterm2` created the session and completed its turn
(ask at 04:36:41 KST, result at 04:36:47); `close-session --explicit` confirmed the close. Before #100 the same launch failed
in 0.3 s with an AppleScript syntax error (#99).

## Hold, wait, status, doctor

A Codex session completed its first turn; `hold` made the next `tell` refuse with `session … is
held; release the hold before sending a follow-up`; after `hold --release` a second `tell` was
delivered; `wait` on both requests returned the completed first one and listed the second as
remaining; the second completed; `doctor --probe` reported `session_state`, `cancel`
(`cancel_absent`), `hold` (`not_held`) and `provider_version` (`version_supported`); the explicit
close confirmed. (04:36:48 to 04:37:02 KST.)

## Not verified in this release

Native Windows and Linux runtimes; Warp (its Control endpoint is empty on this machine, #63);
Ghostty with the screen unlocked (#104) and any launch that needs the screen unlocked; cancel on
Codex, Claude and Agy (refused by design in this release); a direct Esc on a Pi turn during a
Bridge request (no keystrokes were sent into the owner's terminals); the live consent matrix of
#28; closing a session whose surface vanished while its provider process lives (#101).
