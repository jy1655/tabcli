# Terminal Agent Bridge 0.2.1: macOS verification

## Scope and source

0.2.1 fixes a race in closing a Warp session (#85) and changes documentation, the "Self-test"
paragraph of the help text and the names of two CI checks. This record covers what was run on
macOS for the 0.2.1 candidate. It is not evidence for native Windows or Linux runtime behaviour.

The tested source is commit `3a27ce0712483147c8afb60a0b1da4762b9c5778`. Later commits on the
release branch add this record, the release notes and the README lines that point to them. The
release binary (`cargo build --release --locked`) reports `tabcli 0.2.1` and has SHA-256
`d8b32b1a8ba5922f6103beaae74e1540fde6869448416884e966a290f56f5e68`. It is a local build with
Rust 1.98.1; the published archives are built by the Release workflow with the pinned Rust 1.97.1.

An earlier build of the same branch, made before the Warp fix was written, was tested the same
way an hour before. It differs from the tested source only in `src/native/terminal/macos/warp.rs`
(the fix and its tests); its binary had SHA-256
`f9d4bda936b1d23c45a89b5f5befb4078e89f76ead1d3164b777ee650d1210ba`. Its results are given
separately below, because the screen was unlocked for that run and locked for the later one.

Environment: Apple Silicon, macOS 26.6.2 (25G83), Codex CLI 0.160.1, Claude Code 2.1.291,
Agy 1.3.0, Pi 1.0.4. The commands ran from a shell inside WezTerm.

## The Warp fix (#85)

`kill(-pgid, 0)` was measured on this machine: a process group whose only member is an unreaped
zombie gives `EPERM`, and `ESRCH` once the zombie is reaped. Two new tests hold a real process
group in that state. Against the old observing loop both failed with "could not observe the
stopped Warp foreground group: Operation not permitted (os error 1)"; with the fix one waits for
the reaping after two `EPERM` probes and the other fails at the deadline, as it must. No live
Warp session was run: Warp has no verified round trip on this machine (#63).

## Review

The two translated pages were compared with their Korean originals mechanically (code blocks,
inline code, links and structure) and then reviewed sentence by sentence by a session that had
not written them. The same session checked the new self-test wording against the consent code
and the CI job name against the workflows. The Warp fix was written by one session and reviewed
by another, which found the change fail-closed and asked for tests that depend on what the
function observed instead of on sleeps. All findings were fixed before the commits. A review of
the source is not a runtime check.

### Agy in its default permission mode

`ask` passed and Agy received the prompt (`Forwarding user message` in its log). Eight seconds
later the log has `Surfacing tool confirmation: "RunCommand" at step 2`, and nothing more until
the session was closed: Agy was waiting for the user to approve a command. The self-test prompt
asks for a marker and needs no tool. The report gave `initial_result` as timed out, `tell` and
`follow_up_result` as not verified, and `cleanup` as passed. This is recorded as #82. The rows
with `--yolo` show that the Agy path works, including the follow-up paste and its receipt; they
are not a check of the default permission mode.

### Pi

`ask` passed, and the session directory holds Pi's startup record and the pending turn. No
result arrived within the 120-second budget, and cleanup passed. Run directly afterwards,
`pi -p` with the same model exits with `No API key found for openai-codex.`: Pi has no login
for that provider on this machine. The Pi round trip is therefore not verified. That the
request stayed pending until the timeout instead of failing with the provider's reason is
recorded as #83. What the Pi screen showed in the managed session was not read before the
session was closed.

In the isolated state root, the Pi session's consent record was `verified` with Codex's trust
store as its source and `pi-approve-once` applied: `--isolated` keeps Bridge's records apart
and still reads the providers' own trust stores. This is the behaviour that #79 describes.

## Not exercised

- Terminal.app and Ghostty with the tested source and the screen unlocked. The earlier build
  passed there; the tested source differs from it only in the Warp close path.
- Native Windows and Linux at runtime.
- Warp, including the fixed close path in a live session.
- A Pi round trip, and Agy in its default permission mode beyond the timeout above.
- A session launched by an older version and continued by this one. 0.2.1 changes no record and
  no transport; the 0.2.0 record covers `agent-bridge` 0.1.2 to `tabcli`.
- A close after the owner died, an interrupted close, and the Terminal.app paths for a restarted
  or second Terminal process. Unit tests cover them; no live run did.
- Provider approval prompts other than the Agy confirmation above, which was left unanswered.
